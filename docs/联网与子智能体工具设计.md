# 联网与子智能体工具设计文档

> 版本：v0.1（2026-10-23，待用户拍板）
> 触发：用户要求为本智能体设计联网功能 tool 与开子智能体的 tool，以实现更强的效果。
> 前置事实：DSH 已升级至 0.2.1-rc.2（见 `docs/DSH与新模型优化评估.md`）；
> 官方 Search/Fetch API 与 V4.1-Flash-1017 的 Harness 专项优化均已就绪。

## 1. 背景与目标

### 1.1 一个先行的事实纠正

测绘结论：**执行工作台层，两个 tool 都已经是 DSH 原生现货**——

- `web_search` / `web_fetch` 由上游 `@deepseek-ai/dsh-tool-web` 注册，
  搜索走本仓自研的 `chengxin-execution-search` provider（官方
  `web_search_20250305` 服务端工具，按会话归因、请求落事件、maxUses 3）；
- 子智能体由 `tool-subagent`（spawn）与 `tool-subagent-fork`（fork）提供，
  已在 `execution.patch.yml` 启用（maxDepth 2），且根与后代共享同一网关
  预算（每回合 24 次调用 / 180 秒，进程终身 200 次）。

因此本设计真正要解决的不是「从零造 tool」，而是三件事：

1. **工作台层**：把已启用的原生联网/派生能力纳入本仓的治理口径
   （归因、预算、审计、评测），从「上游默认开着」变为「我们设计过」。
2. **医疗路径周边**：在不触碰问诊内核的前提下，新增两个受控能力——
   结论后的联网教育层、Python 层的受控子智能体协调器。
3. **医疗决策路径本身**：明确**不做**——见 §2 的结构性决策。

### 1.2 目标

- 患者在结论单之后能获得带权威出处的延伸阅读（教育价值），且联网内容
  在结构上不可能改变任何一次分诊与处置。
- 自适应引擎在证据稀薄、需要二意见或长病例压缩时，能派生受控子任务
  并行处理，产出经确定性校验后才可被主流程消费。
- 全部联网与派生动作可审计、可计量、可熔断、可一键关闭（env 开关）。

### 1.3 非目标

- 不给问诊决策循环加任何外部工具（见 §2）。
- 不做患者主动发起的「问问网络」入口（v1；理由见 §4.6 决策点 D5）。
- 子智能体不做自由任务，只做封闭枚举的任务类型（§5.2）。

## 2. 总体架构决策：三层落点

| 层 | 联网 | 子智能体 | 理由 |
|---|---|---|---|
| 执行工作台（DSH 原生） | 已有，纳入治理（§3） | 已有，纳入治理（§3） | 研发场景，信任边界与医疗路径不同 |
| 医疗 advisory 层（新增） | 结论后教育区 + 后台复核（§4） | Python 协调器，仅自适应引擎（§5） | 与患者回路隔离、可 shadow、可评测 |
| 医疗决策路径（内核） | **永不** | **永不** | K1–K8 契约与「模型只提案、确定性代码掌权」是系统根基 |

核心结构性原则（红队评审的第一红线，设计层落实）：

- 检索与子智能体的产出只能进入**带来源标记的不可信数据槽**，
  永不成为病例事实（事实的 evidence 必须逐字出自患者转录——现有证据
  契约在校验层扩展断言：tool_result 与子产出不可被引为 evidence）。
- 红旗扫描、急症路由、必问题目、处置等级的决定权不因新 tool 发生
  任何迁移；联网/派生失败时系统按现状完整工作（fail-open 向主流程）。

## 3. 工作台层治理（Phase A，存量纳入设计）

对象：`integrations/dsh/execution-search.mjs`、`execution.patch.yml`
的 subagent 配置段、execution-worker 网关。

1. **归因补全**：`chengxin-execution-search` 已按会话归因并把内层请求
   落事件；补 `web.fetch` 的同级归因（当前 fetch 走上游 provider，
   归因弱于 search），事件字段对齐 §7 的命名。
2. **预算口径成文**：在 `execution_limits.py` 注释与 README 中明确
   「联网与派生共享回合预算」的既有事实（search maxUses 3、subagent
   maxDepth 2、根与后代共享 max_calls/时限），并给工作台补一个
   每会话联网次数上限（建议 30，与 web 设计草案一致）。
3. **子智能体纪律复核**：patch 的 system-prompt 已有委派纪律
   （有界自含任务、依赖时同步等待）；按 §5 的词汇统一事件命名
   （`subagent.started/finished` 已存在于 worker 通知中，仅对齐）。
4. **check 断言**：`integrations/dsh/check.mjs` 增加对 search/fetch/
   subagent 三个面的存在性与关键配置断言（maxUses、maxDepth），
   防上游升级再次悄悄改变能力面（0.2.1 文件系统面事件的教训）。

## 4. 联网 tool（医疗 advisory 层）

### 4.1 供应商决策

- 搜索：**DeepSeek 官方 Search**（与工作台同一 provider、同一密钥与
  计费账户；2026-11-01 起 $0.75/1000 次）。
- 抓取：**自研 Python fetcher**，不用官方 Fetch——重定向复检、SSRF
  防护、出站闸门、来源分级与注入扫描都必须在本地完成，服务端 Fetch
  不暴露这些控制点。（工作台层维持上游 fetch 不变，信任边界不同。）

### 4.2 工具契约

`web_search`（仅供结论后教育合成器与后台复核器调用，不注册进问诊
决策引擎的工具目录）：

| 字段 | 约束 |
|---|---|
| `query` | ≤120 字符；患者路径**只能由代码按 §4.4 模板构造**，调用方不得自由填写 |
| `purpose` | `patient_education` / `guideline_check` / `drug_info` / `service_info` |
| `max_results` | 1–8，默认 5 |
| `min_tier` | 按 purpose 推导：教育 T3、指南 T1、药品 T1；低于此级只计数不返正文 |
| `recency` | `drug_info` 强制 `year`，其余默认 `any` |

输出含 `search_id`、`query_as_sent`（脱敏后实际发送形态，与审计事件
一致）、结果数组（title/url/domain/snippet ≤300 字/published_at/
fetched_at/tier/source_id）、`filtered_below_tier`、`status`。

`web_fetch`：URL **只能**是本会话 search 返回过的 URL 或来源注册表
中的策展 URL（禁止任意 URL）；输出清洗后纯文本（默认 8000 字、
硬顶 20000）、`content_sha256`、`final_url`、`tier`、
`injection_suspect` 标记。

引用结构 Citation（结论单统一格式）：`{citation_id, title, url,
publisher, published_at|null, fetched_at, tier, quote ≤120 字}`。
规则：**URL 只能来自供应商响应，模型永不生成 URL**；published_at
为 null 时患者端显示「发布日期未标注」并降权。

### 4.3 来源分级注册表

新内容文件 `content/web_sources.json`（域名 → 分级，随待临床评审清单
一并签核）：

- **T1 指南与官方**：WHO、国家卫健委/中国 CDC、NICE、国家药监局与
  药品说明书库、专科协会指南。
- **T2 同行评议**：PubMed 收录期刊、中华医学会系列杂志、Cochrane。
- **T3 机构与专业平台**：三甲医院官网、默沙东诊疗手册等。
- **T4 一般网页**：未注册域名一律 T4。

患者可见引用仅限 T1–T3（v1 建议只 T1/T2，见决策点 D3）；T4 只计数
不显示不摘录。排序「分级优先、其后时效」；指南内容超 5 年标注
「可能已有更新版本」；药品信息无说明书版本日期不展示；**禁止从网页
摘录给药剂量/疗程数字进入患者文本**（与结论单禁用词同构的
剂量模式 lint 拦截）。

### 4.4 隐私：查询构造与出站闸门（硬规则）

- 患者路径的查询只能由代码从受控词表拼装：方向 `patient_label`、
  症状类目词（问题库词表）、药品通用名（内容表）+ 固定后缀
  （「诊疗指南」「患者教育」）。模型与患者原文都不参与查询文本。
- 复核等自由查询路径必须过同一脱敏管线：删姓名；精确年龄→年龄段；
  删绝对日期；地点降至省级以下删除；正则清身份证/手机号模式；
  脱敏后仍含疑似标识 → **整条拒绝**并落 `web.blocked` 事件
  （隐私 fail-closed，与其他层的 fail-open 相反）。
- 禁止外发字段：姓名、精确年龄、主诉原文、任何 fact 的 evidence
  原文、transcript、结论单全文、交接摘要、图片及元数据、经纬度、
  session_id、内部 hypothesis id、密钥与请求头。
- 红队补充闸门（采纳）：query 与病例全文做子串检查（患者原文连续
  ≥8 字片段出现即拒）；fetch 侧执行 SSRF 校验（仅 https 公网、
  解析后 IP 落私网/回环/链路本地即拒、每跳重定向复检、禁 URL
  credentials、≤256KB、仅 html/text）。

### 4.5 触发、预算与降级

| 场景 | 触发 | 上限 | 说明 |
|---|---|---|---|
| 结论后教育区 | composer 按方向 id/自护主题**确定性查表触发** | 每例 ≤3 search + ≤2 fetch，总 25s，**异步追加**（结论单先渲染） | 超时整区省略 |
| 后台复核 | 复核器查指南时效/本地内容一致性 | 每例 ≤5 search + ≤3 fetch | shadow 先行 |
| 问诊进行中 | — | 0 | v1 不开放 |

- 全局开关 `MEDAGENT_WEB_TOOLS=off|education|review|all`，默认 off。
- **日付费熔断**：默认 500 次/日（search+fetch 合计），超限自动降
  off 并落事件——2026-11-01 起按次计费，必须有账本上限。
- 失败语义：无网/超时/供应商错误 → 教育区整段静默省略（与结论合成
  同一 fail-open 纪律）；只有低质结果 → 返回
  `insufficient_authoritative_results`，患者端不展示。
- 冲突规则（单向）：本地红旗/自护/鉴别内容**永远优先**；抓取内容与
  本地安全网矛盾时患者端只呈现本地文本，矛盾记
  `web.conflict_detected` 进入临床评审队列（联网层对内容库的反向
  价值：发现过时线索，但修改必须走临床签核，永不自动生效）。

### 4.6 决策点 D5：问诊中患者主动搜索入口

推荐 **v1 不做**：问诊中的信息需求由本地内容承接；该场景患者文本
进查询的隐私风险最高，且会打破内核的确定性问答节奏。教育区评测
达标后再议。

## 5. 子智能体 tool（Python 协调器）

### 5.1 落点决策

**问诊路径的子智能体实现在 Python 层**，新增
`src/medagent/subagents.py` 的 `SubagentCoordinator`（与
`BackgroundReviewCoordinator` 并列）：

- 医疗 DSH 桥是零工具面契约，在那里开 subagent 等于在最严边界凿洞；
- 子运行经现有 `decide()/decide_cancellable()` 后端抽象发起，
  compatible/dsh 两种部署行为一致、可互换评测；
- 校验器（证据池、内容文件、fetch 全文）都在 Python 侧，审计链完整。

DSH 执行工作台继续用其原生 subagent（§3），两条路径只共享预算词汇
与事件命名，不共享运行时。

### 5.2 工具契约：spawn_subagent（封闭任务枚举）

注册进自适应引擎 `TOOL_DEFINITIONS`（同一单 JSON 信封与
`validate_command` 校验）；确定性引擎与分诊路径永不调用。

输入（模型提案，Python 钳制后生效）：

| 字段 | 规则 |
|---|---|
| `task_kind` | **封闭枚举**：`evidence_lookup` / `second_opinion` / `case_digest` / `followup_batch`。每 kind 绑定固定提示词模板、输出 schema、工具上限、预算档；模型不能自创类型 |
| `objective` | ≤200 字，进审计事件 |
| `branches` | 1–4 个并行分支 `{branch_id, objective, scope}` |
| `scope.fact_keys` | 与 kind 允许键集合、病例现有事实双重求交，超出剔除并记 `scope_clamped` |
| `scope.hypotheses` | 同上钳制 |
| `scope.transcript` | `none`（默认）/ `evidence_only`（只给事实 evidence 原话，推荐档）/ `recent_window`（最近 16 轮，仅 case_digest 且需部署开关）；完整 transcript 永不透传 |
| `scope.prior_case` | 默认 false |
| `tools` | 只能收窄 kind 上限，不能扩权；超限剔除并记录 |
| `budget` | 只能调低，Python 钳制到 kind 上限 |

输出 `SubagentResult`（每 branch 一份，聚合后作为单个 tool_result）：
`{subagent_id, branch_id, task_kind, status, conclusion ≤1000 字,
findings[{claim ≤300, evidence[{source_type: case|knowledge|web,
quote, ref}], confidence}], sources[], uncertainty{level, reasons},
usage{model_calls, input/output/cache tokens, duration_ms},
validation{schema_ok, quotes_total, quotes_verified, dropped_claims,
scope_clamped}}`。status 枚举：`completed / partial / failed /
timeout / budget_exhausted / cancelled / stale /
rejected_by_validation`。

### 5.3 隔离：ScopedCaseView（投影，不是 CaseState）

- 给：scope 内事实（key/value/assertion/evidence）、scope 内假设的
  differentials 条目、任务相关的内容摘录、（开启时）prior_case 摘要。
- 不给：session_id（替换为一次性 case_ref 哈希）、完整 transcript
  （默认）、scope 外事实、其他患者的任何数据（followup_batch 也
  **一例一个 child**）、系统提示词与工具目录、密钥与部署配置。
- 子智能体工具全集（只读）：`case_view`、`knowledge_search` 全 kind
  可用；`web_search/web_fetch` 仅 evidence_lookup 且受
  `MEDAGENT_SUBAGENT_WEB`（默认 off）与 §4.4 出站闸门双重约束；
  **任何写工具与 spawn 本身永不在子工具面**（深度 1 靠工具缺席
  结构性保证，不只靠计数器）。

### 5.4 回传校验流水线（确定性代码，按序）

1. 信封校验（严格 JSON、键集合恰合、长度上限，复用 parse_decision 风格）；
2. 按 kind 的 schema 校验；
3. **证据逐字核对**：case 类 quote 必须命中 ScopedCaseView 证据池；
   knowledge 类必须命中所引 content 条目原文；web 类必须命中
   fetch_id 对应的宿主抓取全文。不命中的 claim **直接丢弃并计数**，
   不做修复性改写；
4. 安全 lint：conclusion/findings 过结论单 `BANNED_PHRASES`；
   面向患者的处置指令口吻 → claim 丢弃；
5. 不确定度地板：有 claim 被丢弃 → uncertainty ≥ medium；
   evidence_lookup 无任何已验证来源 → 整份 rejected；
6. 丢弃率熔断：dropped/total > 50% → 整份
   `rejected_by_validation`，主模型只收到状态与计数；
7. 时效水位印校验（§5.6）。

幸存 findings 进入主上下文时统一标注 `provenance: "subagent"`；
主模型若要将其落为事实，仍须走 record_facts 并再次逐字校验——
**子产出永不直接生成事实**。

### 5.5 预算与生命周期

| 维度 | 上限 |
|---|---|
| 深度 | 1（结构性） |
| 分支/次 | ≤4 |
| spawn/患者轮 | ≤1（主循环 6 步内只许 1 步用于 spawn） |
| 全局并发 | 8（进程级信号量） |
| 单轮子总信封 | ≤48k tokens、墙钟 ≤45s |

分 kind 预算（max_calls / max_tokens / deadline）：evidence_lookup
6/branch、24k/branch、45s；second_opinion 3、16k、40s；
case_digest 2、12k、30s；followup_batch 4/例、16k/例、异步批 600s
（不占问诊轮预算）。分支间共享信封先到先得；部署级
`MEDAGENT_SUBAGENT_MODE=off|shadow|advisory`（默认 off）+ 日累计
token 熔断（默认 2M/日/进程，超限自动降 shadow 并告警）。

生命周期：`proposed → clamped → running → validating → settled`，
每次迁移落事件。超时分支单独结算、主轮不等（partial 返回）；
父轮取消广播 cancel（2s 优雅期后弃置）；仅传输错误与已知空 content
可重试（每分支 ≤1 次，复用有界重试）；schema 失败给 1 次带错误说明
的修复重问；timeout/budget 不重试；`spawn_id + branch_id` 为结算键
保证幂等。

### 5.6 时效水位印

spawn 时记录 `{phase, updated_at, fact_ids 哈希, conclusion_revision}`；
交付时重算比对，期间病例有新事实/更正 → 结果 `stale` 丢弃。
仅 case_digest 可由协调器以新水位自动重发一次；含临床判断的 kind
不自动重发，由主模型按新状态决定。

### 5.7 四个 kind 的用例与消费方式

1. **evidence_lookup**：≥2 个 active 假设且证据稀薄时，每方向一
   branch，产出「还缺什么证据/支持与反对点/红旗注意」（全带逐字
   证据）；主模型据此选下一个问题或在 review 时参考。安全网文案
   永不取自子产出。
2. **second_opinion**：**盲化**——子智能体看不到主模型的结论与处置，
   独立给处置倾向。shadow 期只记一致率；advisory 期与主处置分级
   不一致时以 `second_opinion_disagreement` 标记进入主模型下一步
   上下文；永不以「另一位 AI 有不同意见」的形式直接示人；emergency
   路径不等待二意见（先行路由、后台补核）。
3. **case_digest**：transcript 超窗或复诊引用 prior_case 时由控制器
   **确定性触发**（不依赖模型提案）；产出带逐字 quote 的结构化摘要
   `{timeline, confirmed_facts, contradictions, prior_outcomes}`，
   校验后替换窗口外原文。因 quote 可验，是敢先上 advisory 的 kind。
4. **followup_batch**：到期 ≥3 例时离线批量，一例一 child，产出
   `{priority, reason, draft_message}`；草稿进待随访区，**必须由
   用户确认/编辑后才发送**，无自动发送。

与 background_review 的关系：二意见本质是同步版后台复核。v1 不动
现有协调器（其 shadow 数据在积累）；待 spawn 稳定后，再评估把后台
复核注册为 coordinator 的一个 kind。

## 6. 安全红线（上线门槛，任一不满足则两个 tool 都不得上线）

采纳红队评审的七条红线，作为验收标准而非建议：

1. **权限隔离由代码校验层强制**：检索/子结果只进带来源标记的不可信
   数据槽；不得改变红旗/风险/必问题安全路径；不得作为事实 evidence
   被引用。
2. **出站闸门上线**：query 与 fetch URL 发出前都过确定性 PII/病例
   原文拦截与 SSRF 校验，红队用例集拦截率 100%；联网默认关闭、
   设置页显式开启并有「去标识化检索词会发送给第三方」的知情文案。
3. **不覆盖评审内容**：本地评审内容对联网结果有代码级优先权；
   检索内容不进结论单结构化字段；白名单外来源不得被摘录进患者
   可见文本。
4. **派生最小授权**：派生必须显式声明 context 投影与工具清单；
   子智能体无写权、无再派生、结果不升格信任；越权用例 100% 拒绝。
5. **预算硬顶与降级路径**：深度、单轮/单会话次数与 token/时长硬顶
   由代码强制；超限能以无联网/无派生路径正常收口；放大攻击用例
   验证通过。
6. **审计链完整**：§7 事件逐项落地，复合场景测试通过；子任务调用
   链可按 task_id 完整重组。
7. **红队语料进发布门**：注入、投毒（与本地内容冲突的检索结果）、
   外发、SSRF、放大五套语料进入与现有 release gate 同级的阻断式
   评测，且在**自适应引擎**上跑通（只有它会真正调用这两个 tool）。

## 7. 审计事件（沿用 EventStore，命名对齐既有风格）

- 联网：`web.search_requested {search_id, query_as_sent, purpose,
  caller, min_tier}`、`web.search_completed {result_count, tier 分布,
  duration_ms, status}`、`web.fetch_completed {domain,
  content_sha256, tier, injection_suspect}`、`web.blocked {reason
  类别}`、`web.citation_attached {citation_id, sheet_revision}`、

## 8. 评测方案与上线节奏

### 8.1 联网层

- 检索相关性：冻结评测集 ~120 查询（8 路径 + 药品 + 教育主题），
  双人标注 top-8 相关性、临床抽核；门槛 nDCG@5 ≥ 0.7、top-3 权威
  命中率（≥1 条 T1/T2）≥ 90%。
- 引用真实性：shadow 期每条「摘要+引用」做蕴含校验（人审 + LLM
  法官双轨），蕴含率 ≥ 98%；假 URL 率必须为 0（结构性保证，评测
  只作回归确认）。
- 隐私对抗集：200 例植入标识的合成病例跑全管线，断言
  `query_as_sent` 标识出现次数 = 0。
- 安全不回归：108 例结论语料在联网开启下重跑，处置一致率 1.000、
  harmful 0；冲突套件（检索内容唱反调）断言处置零变化且冲突事件
  必落；注入套件 ≥20 页，断言行为零变化、检出率 ≥ 95%。

### 8.2 子智能体层（发布门新增 subagent gate 节）

语料：second_opinion 复用 108 例结论语料构造 scoped view；
evidence_lookup 40 例（8 路径证据稀薄病例）；case_digest 20 例
合成长病例（埋矛盾与已知事实集）；followup_batch 20 例。

| 指标 | 门槛 |
|---|---|
| schema 一次通过率 | ≥90%（含 1 次修复后 ≥99%） |
| 证据丢弃率 | ≤10%；**未验证 quote 漏过校验 = 0（硬红线）** |
| 二意见一致率 | ≥0.95；金标准 urgent/emergency 而子意见 self_care 的危险低估 = 0 |
| digest 保真 | 事实 quote 召回 ≥95%，臆造 = 0 |
| lookup 黄金特征命中 | ≥85% |
| 预算健康 | budget_exhausted ≤5%，p95 墙钟 ≤ deadline 的 80% |
| advisory 模拟有害影响率（A/B 回放） | **0** |

非确定性口径：每轮跑 3 次，≥2 次全过且任一次不得出现红线失败
（吸取 A/B 评测两臂同源的教训，脚本自检模式确实不同源）。

### 8.3 上线节奏（分 kind/分层独立晋级）

1. Phase A（工作台治理，§3）：无患者面风险，先行。
2. Phase B（联网）：`review` shadow（仅 telemetry）≥2 周且 §8.1
   全过 → `education` 开放 T1/T2 引用展示。
3. Phase C（子智能体）：离线门全过 → shadow ≥2 周或 ≥500 次 spawn
   （结果只落事件、不进主上下文）→ advisory 按 kind 晋级，顺序
   case_digest → evidence_lookup → followup_batch → second_opinion。
4. 任一红线事件（未验证证据漏过、子产出被追溯为患者可见有害内容
   之源、日成本超信封 2 倍）→ 对应 kind/层自动降回 shadow 并告警，
   恢复需人工改 env。
