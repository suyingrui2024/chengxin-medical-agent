# 阶段 4 实施报告（2026-10-22）

对应设计文档第 6 节（纵向闭环与数据飞轮）与第 7 节阶段 4。

## 已完成

- **随访计划**（`src/medagent/followups.py` + 引擎接线）：问诊关闭时按
  最终风险派生计划并写入 `CaseState.follow_up`、回复体
  （`reply.follow_up`）与事件 `followup.scheduled`：
  - 急症路由：不排随访（患者已被导向立即就医）；
  - 风险升级关闭（urgent_route）：24 小时 urgent_checkin；
  - 摘要确认关闭：例行回访 72 小时；若病例中存在"未知"断言则提前到
    48 小时（未知不是阴性，值得更早确认）。
  计划派生是纯函数（`build_follow_up_plan`），调度点只有两处：
  `_finish` 的 urgent 关闭与摘要确认处理器。
- **结局记录与再分诊**：引擎新增公开方法
  `record_follow_up_outcome(session_id, outcome, note)`，结局词表为
  recovered / improving / unchanged / worsened / sought_care /
  hospitalized；非法结局、重复记录、无计划记录均显式报错。
  worsened / hospitalized 触发再分诊：创建新会话并以
  `runtime_snapshot["follow_up_of"]` 回链原会话，事件
  `followup.outcome_recorded` / `followup.retriage_session_created`
  全程留痕——纵向链路由事件与状态双通道可查。
- **复核飞轮**（`src/medagent/flywheel.py`）：临床复核结果 → 语料候选
  的纯数据管线。候选必须注明复核人、阳性样本必须标注红旗 id；
  合并时拒绝未审候选、按规范化文本与 id 双重去重、且不修改输入
  语料。候选进入语料后自动被发布门与语料门测试消费，形成
  "复核修正 → 标注样本 → 门禁变严"的闭环。
- **发布门脚本**（`scripts/evaluate_release_gate.py`）：把设计 5.1 的
  红旗指标做成可执行门禁（每集总体召回 ≥0.99、单旗召回 ≥0.95、
  误报率 ≤0.05），当前两集全项 PASS（详见脚本输出存档）。

## 验收

- 行为基线 **334 passed, 2 skipped**（+9 随访/飞轮用例），零回归。
- 随访全链路有用例固定：确认关闭排计划（48h，未知断言存在时）、
  加重轨迹在答题回合即以 urgent 关闭并排 24h 计划、急症关闭无计划、
  结局记录/重复记录/非法结局、加重结局生成回链新会话。

## 边界

- 随访的**触达通道**（推送/短信/调度器）不在本仓库范围：本阶段交付
  计划、词表、回链与事件，触达由部署侧按 due_at 消费
  `followup.scheduled` 事件实现。
- 纵向视图（patient_longitudinal_summaries）为既有只读扩展，本阶段
  未改其实现；随访计划与结局已进入事件流，其后续纳入纵向摘要是
  纯展示层工作。
- 飞轮只提供管线与完整性约束；真实临床复核数据的产生依赖临床
  所有者（设计文档待决问题 1），管线本身不产生临床结论。
