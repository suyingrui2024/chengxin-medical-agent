# 阶段 3 实施报告（2026-10-22）

对应设计文档第 7 节阶段 3（鉴别诊断推理核与分诊推理复核层）。

## 已完成

- **鉴别诊断工作区**（`src/medagent/reasoning.py`）：类型化的
  `Hypothesis` / `EvidenceRef` / `ReasoningWorkspace`，序列化存入
  `CaseState.reasoning`（domain 新增字段，尾部默认值，不影响既有构造
  与摘要结构）。假设状态机：active / supported / refuted / unlikely。
- **更新协议"提议 → 确定性校验 → 写入"**：
  - 提议器 v1 为规则映射（`content/differentials.json`，覆盖现有产品
    范围内的呼吸道与胸痛两条路径，条件 DSL 支持 contains/assertion/
    equals/gte/lte）；红旗假设凭主诉即可进入工作区等待排除。
  - 校验器逐条核验证据：fact 必须存在且 fact_id 未被更正覆盖、
    quote 必须是该 fact 证据/取值或用户原话的逐字子串；任一证据不实
    则整条假设拒绝并写 `reasoning.proposal_rejected` 事件。
  - 全部鉴别问题已问完且毫无支持证据的"主诉入场"假设自动降级为
    unlikely，避免弃答规则误触发。
- **DifferentialPlanner**（实现阶段 2 的 Planner 协议）：按设计 4.5 的
  权重打分选问（红旗覆盖 3.0——经 `red_flag_questions` 精确到直接探查
  红旗域的问题；区分度 2.0；必需性 1.0；新鲜度 0.5），同阶段内选题、
  背景阶段仍先提供自查任务，与 RulePlanner 的结构性行为对齐；
  提问理由写入既有 developer_trace 通道（如"为排除红旗相关假设
  （下呼吸道感染/肺炎可能）提问 resp_breathing"）。
  工作区变更写 `reasoning.workspace_updated` 事件，全程可审计。
- **弃答规则（v1 映射）**：红旗假设停留在 active、无区分问题可问且
  连续 3 个规划回合工作区无进展 → 返回既有 urgent 优先求助回复，
  不以良性摘要收尾；supported 的假设正常完成并进入摘要。
- **分诊推理复核层**（`src/medagent/triage_review.py`）：实现阶段 1
  预留的 SemanticProvider 协议，适配任意结构化决策回调；扫描器侧
  强制校验 flag 合法性与证据逐字性，复核器异常时静默回落到确定性层。
  默认不启用（确定性引擎不注入 provider），与设计"影子→灰度"一致。
- **双引擎安全差分测试**（`tests/test_dual_engine_safety.py`）：语料
  全部 69 条样本以首条消息分别提交两条引擎——急症文本在两条路径上
  都必须直达 emergency（且自适应引擎零模型调用），否定对照在两条
  路径上都不得误报。阶段 1 的分层分诊红利由此被证明覆盖双引擎。

## 验收

- 行为基线 **325 passed, 2 skipped**（+8 推理用例 +2 双引擎差分）。
- 可观测的行为差异（有测试固定）：呼吸道路径下 DifferentialPlanner
  首个病史问题选 resp_breathing（红旗覆盖+区分度最高），RulePlanner
  按题库顺序选 onset；默认仍为 RulePlanner，切换遵循设计的灰度门。

## 暂缓与边界

- **默认规划器未切换**：按设计 5.4，需 OSCE 式病例集评测后灰度切换；
  该评测集依赖临床病例来源（设计文档待决问题 4），不在本轮工程内。
- **自适应引擎 `_submit` 未合并**：其与确定性管线的前置校验存在已知
  行为分歧（过期动作的事件与文案），且与模型决策循环深度耦合；
  本轮以双引擎安全差分先行锁定 K1 不变量，合并留待模型网关统一时
  处理（届时一并决定文案口径）。CaseState 遗留字典字段
  （calculation_feedback 等）同理未动；新增状态一律类型化。
- differentials.json 为工程 v1 内容，未经临床审校，文件内已注明；
  其临床所有权为设计文档待决问题 1。
