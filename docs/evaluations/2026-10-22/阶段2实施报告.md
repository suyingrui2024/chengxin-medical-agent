# 阶段 2 实施报告（2026-10-22）

对应设计文档第 7 节阶段 2（管线统一与状态收敛）。

## 已完成

- **TurnContext 落地**（`src/medagent/turn_context.py`）：回合级上下文
  （turn_id、工作文本、结构化定位答案、回复理由、管线轨迹）。
- **`_submit` 拆为显式管线**：编排顺序为——急症求助短路 → 过期动作守卫
  `_guard_stale_action` → 回合建立 `_begin_turn` → 直达急症门
  `_direct_emergency` → 有序处理器注册表（`_turn_pipeline`）：

  | 管线处理器 | 对应设计条目 |
  |---|---|
  | location_revision | H4 定位修改 |
  | closed_session | H5 会话关闭 |
  | subject_control | H6 就诊对象（K7） |
  | prepared_location | 结构化定位答案核对 |
  | observation_action | H8 重复观察 |
  | summary_review | H9 摘要核对 |
  | intake | H10+H11 图示任务/答题摄入/自由输入 |
  | risk_escalation | H12 分诊复评与升级 |
  | planning | H13 规划（经 Planner 策略） |

  每个处理器返回回复即短路（理由经 `ctx.reply_reason` 统一记录），
  返回 None 则继续；分支顺序与拆分前逐条一致。
- **Planner 策略缝**（`src/medagent/planner.py`）：`Planner` 协议 +
  `RulePlanner`（封装原 `_plan_next`），引擎以 `self.planner` 持有，
  可在构造后替换；替换测试证明规划策略已与管线解耦——这是阶段 3
  接入 DifferentialPlanner 的接口。
- **阶段图数据化**（`src/medagent/phase_graph.py`）：主链 + 安全回边
  （任意阶段可回 emergency_screen 复筛、可关闭）+ 更正双向边；
  `_phase_rank` 改为委托 `planning_rank`，取值与历史完全一致
  （observation/summary 仍为 9），仅描述、不强制，不改变既有行为。
- 新增 `tests/test_turn_pipeline.py`（7 个用例）：注册表顺序、正常回合
  全轨迹、急症直达绕过管线、规划器可替换、过期守卫仍记录
  `turn.rejected`、阶段图与 rank 兼容性。

## 验收

- 行为基线 **315 passed, 2 skipped**（295 原基线 + 13 分诊 + 7 管线），
  零回归。管线拆分在首次运行即全绿，说明提取是行为等价的。

## 暂缓项（附理由，转入阶段 3 范围）

1. **自适应引擎 `_submit` 合并**：核查发现两条路径存在真实行为分歧——
   自适应路径的过期动作校验不写 `turn.rejected` 事件且报错文案不同
   （"回答对应的页面已更新，请刷新当前问题" vs 确定性路径
   "页面上的问题已经变化，请按当前问题重新回答"）。这说明设计文档预警的
   "双实现漂移"已经发生。合并涉及行为取舍（哪套文案/事件为准），
   且自适应路径与模型决策循环、抢占语义深度耦合，放在阶段 3 与
   DifferentialPlanner 接入一并处理，避免在纯结构阶段混入行为变更。
   本阶段两条路径共享的安全层（分诊单次计算、发布门、事实写入）已统一。
2. **CaseState v2 类型化子状态**：`calculation_feedback` 等字典字段被
   约 30 处代码以字典方式读写，整体迁移风险与本阶段的结构目标不匹配；
   随阶段 3 假设工作区引入时一并收敛（工作区本身按类型化设计新增，
   不再新增字典型状态）。
