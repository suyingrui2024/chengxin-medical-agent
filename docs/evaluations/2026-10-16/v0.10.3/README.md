# v0.10.3 模型等待、优先求助与长任务

Linux x64 桌面程序：`dist/desktop/Chengxin-0.10.3-linux-x64/Chengxin`。桌面启动脚本已指向此版本，0.10.2 的程序与归档保留。

患者等待模型时仍可主动优先求助；已有规则识别的紧急描述也可中断旧等待。HTTP 快照保持一致；迟到的模型提议、失败、页面响应与清理不会覆盖新状态。主动求助不构成临床症状证据，已经合法提交的事实保留。求助卡片完整显示控制器原有说明，使用固定图标和可展开原因，不重新生成医疗动作。

`decision_wait.py` 用公开 Condition 释放并恢复递归会谈锁。每个引擎最多 8 个未结束决策工作线程；直接模型 HTTP 可能继续至原 45 秒超时。DSH 每 0.2 秒检查逻辑取消，终止并回收自己的进程组；Python 父进程拥有临时根，即使 Node 被强制终止也能清理临时会话资料。这里不声称撤销已计费的上游请求。

执行底座的显式 `job_output` 等待上限从 30 秒改为 600 秒；默认后台等待 10 秒、前台默认 10 秒与上限 30 秒保留。本轮截止时间、共享预算和停止通道继续生效。实际 185 秒命令已通过，三次确定模型请求完成启动、一次显式等待和收尾；它不是宽泛真实模型效率提升的证据。

源码与打包版各 13 组原生检查、24 组界面和直接运行的 11 项 Node 检查通过。完整后端较早 196 项全部通过，包含真实 185 秒任务；随后新增两项用例的常规回归执行 198 项，197 通过、1 项长时检查跳过；最后的结构化投影与临时目录回收另有 21 项定向检查通过。包审计逐字核对 91 个项目文件，核对 544 个 Linux x64 适用生产依赖版本。源码通过与打包通过分别记录，不能以一个代替另一个。

真实 DeepSeek 使用三个合成工程场景，共 4 次请求、全部 HTTP 200，执行源码冻结一致。正常信息提取实际记录四项已提供事实并继续提问；两个优先场景先取得并缓冲真实提供商成功响应，再触发优先路径。本机引擎优先处理各约 1 毫秒；原等待在释放缓冲前返回，释放后状态不变、DSH 桥接回收并记录旧决策失效。这不是患者端到端延迟或急症识别性能测量，也未新增临床规则。详见 `real-provider/round1.json` 和各场景请求账本。

`replay.py` 使用归档源码零网络重放普通场景的两条真实提议，核对事实内容、来源、质量、证据和下一问题；另用同一普通场景的提议制造两种受控迟到竞态。两个优先场景取消时的实际提供商正文没有归档，不能将该受控重放称作其正文精确重现。故意把年龄提议改为 77 的负对照被拒绝。重放均未请求模型。

早期失败完整保留：新等待测试曾误读历史命令，并错误要求超时为 failed；原测试指出契约应为 cancelled 加 time_budget_exhausted，改动已撤销。本轮完整运行只改旧长任务测试的预期请求数 8→3，与显式长等待行为一致。移动端底部求助按钮最初挤出计算卡，改到会谈标题栏；新界面测试最初错误期待聚焦模式的忙碌提示可见；原生测试未等待服务就绪导致 fetch 失败，关闭启动窗又暴露退出时阻塞错误对话框，均保留首次日志及后续复验。最终 DSH 配置展开在受限进程沙箱内未产生输出，使用正常运行权限复验通过；不将环境失败删除或算作能力提升。早期完整检查在最终卡片视觉改动之前，后续界面、原生及投影定向检查覆盖该变更。

最终截图已人工查看桌面和 390×844 手机尺寸。紧急消息取消入场动画；卡片保留完整控制器说明，折叠原因，并在手机视口中显示完整操作。图示和急症规则仍待临床审核与患者理解验证；整体达到 DSH/Codex 仍未证明，本轮没有重新评分此前六个公开 TEST 任务。
