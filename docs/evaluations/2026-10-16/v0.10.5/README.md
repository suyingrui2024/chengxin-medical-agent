# v0.10.5 文件版本与交付检查

检查结束时由宿主只读辅助进程计算文件摘要，交付前重新观察。相关文件变化时显示“需复验”，不沿用旧退出0；同命令、至少原范围的实际复验通过后解除。缺失或不完整摘要仍未核对。参考检查不触发自动修改；主、子任务仍使用原预算和时限。桌面恢复历史时明确显示历史退出状态，不自动核对当前文件。

默认观察工作区文件，排除常见缓存和依赖目录；可用 `watch` 显式指定代码、测试、配置或依赖文件。范围只能扩展。摘要不包含源码文本；单次扫描默认20,000文件、256MB总内容、32MB单文件、5秒辅助进程限制，另有深度和元数据边界。目录fd及文件身份核对沿用既有实现。显式链接输入保持未知；普通目录中的链接只记录链接本身，不跟随读取目标。详见 `design/通用执行底座与能力评测设计.md`。

这些是检查结束和交付前的有界文件观察，不是原子快照，不证明执行期间没有并发写入、测试数量、断言正确、范围充分或临床有效性。外部环境与默认忽略内容不自动获得文件证明；未来后台任务也不由当前根回复背书。

## 真实模型与反例

两轮各最多12次请求，实际各8次、合计16次，全部HTTP200，运行源码在各自调用期间冻结一致。均为非医疗合成加法模块，要求保护测试文件，只允许修正实现，使用真实检查和独立产物验收。

首轮在成功检查后、下一模型请求转发前注入错误。DeepSeek通过文件变更工具主动发现错误，修复并复验；任务、保护文件及独立验收通过，但没有触发“过期检查阻止提前收尾”和自动纠错。因此首轮原始严格场景评分为false，保留在 `real-provider/round1.json`，不能称模型没有修复或强行算预期分支通过。

第二轮改变故障时点：等待提供商真实最终回复到达，在原响应转交运行时前改坏合成文件，随后原样转交响应。没有伪造模型回复或检查结果。运行时检测旧检查过期，在原预算中接续一次纠错；DeepSeek修复实现、用原命令复验，独立算术、文件保护与冷恢复检查通过。第二轮全部符合性检查为true，见 `real-provider/round2.json`。这是有意构造的分支验收，不是未见任务或整体DSH能力比较。

本地正、负夹具先验证评测器。负对照保留错误、不执行必要修复，被运行时完成门与独立产物检查同时拒绝。第二轮保存的助手文本和有序工具调用另从独立临时目录恢复源码重放：125个运行文件核对，8次本地模型夹具请求，零外部模型请求；退出状态、过期／当前状态和一次纠错一致。不包含推理重放，也不声称提供商传输帧逐字一致。

## 失败与复现

`v0105-stale-check-baseline.log` 保存修改后仍被误判完成的原始失败。新辅助进程最初传递列表身份而扫描器要求元组，有效检查因此没有摘要；修正后旧14项交付检查通过，再增加范围与复验用例，31项定向通过。格式化多进程池在受限进程环境停滞，确认并停止确切自有进程后在正常环境完成。新原生测试最初把“本轮已完成”写成“本轮完成”；随后冷恢复检查暴露“历史退出0”被显示成“版本未核对”的含义歧义，修正显示并新增断言，失败trace均保留。这些不算模型失败或付费能力改善证据。

`snapshot-final` 保存最终源码、测试、评测器和锁文件；`real-provider` 保留每轮报告、请求账本、调用时源码和候选。`verification.json` 列出验证阶段和哈希；`credential-scan.json` 与 `archive-manifest.json` 记录扫描和文件校验。源码快照不含真实配置或依赖，重放复用既有锁定Node依赖，不下载包。
