八次计划已全部结束，共 160 次真实模型请求，全部 HTTP 200，执行源码与评测器冻结核对通过。本轮没有证明长等待提升真实模型效率，未发布新的产品版本。

已知开发任务为 SymPy 21627、Sphinx 8627，每题两次重复、两条路径共八次。它们因旧失败而被选中，不是新独立保留集，也没有本轮官方 SDK 臂。每次同一模型、同一用户任务与文件契约、同一准备源码、20 次请求和 600 秒；总上限 160 次。顺序种子 2026101603 决定首组次序，随后按题目和重复平衡先后。原文、完整条件及冻结摘要在首次调用前写入 `round1.json`。

两条路径都使用 0.10.3 控制器和官方 DSH SDK；控制组仅把显式 job_output 最大等待从 600 秒改回 30 秒，并同步一处系统说明，其余集成文件逐字相同，依赖共享同一锁定安装。控制组不能称作整个 0.10.2 产品。源码及原始评分器在运行中没有改变。

实现判定恢复原测试、配置和依赖后应用候选修改：SymPy 每次 27 节点、Sphinx 每次 19 节点，八次共 184 个重复执行的节点全部通过。文件约束与根任务完成分开记录；模型耗尽额度不能冒称完成。600 秒组虽少了三次后台读取，但总请求数相同，且多种工具路径与测试范围发生变化，不能把全部运行时差归因于等待机制。

分析器对“明确长等待”的描述计数使用大于 31,000 毫秒的工具墙钟时长，为旧 30 秒上限留 1 秒调度余量；两组均没有这样的调用。每次原始请求值、实测时长与 SDK 结构化返回另行保留，不能由这个保守计数证明较短调用未受策略影响。小样本、公开历史数据、可能的训练污染及模型生成波动，不支持因果退步、统计优势或整体达到 DSH/Codex 的结论。此前跨 30/185 秒的确定模型机械检查仍成立。

第六次完成后审阅到一份错误新增测试，另冻结 `audit_added_tests.py` 对全部八份候选追加相同检查。此门明确标为 post-hoc，原模型报告、原验收和所有候选保持不变。两次失败均属于 600 秒组的第二次重复：SymPy 测试错误要求 cosh(0).is_zero 为 True；Sphinx 新测试调用当前版本不支持的 signature(..., typehints=True)。原独立节点通过不能替代这些交付文件的检查。补充门没有改变本轮联合完成数量，因为这两次根任务本来就未完成。没有新增测试会标 not_applicable，不能冒称执行过新增测试。

`analyze.py` 保留实现、文件、正常收尾、请求、耗时及等待指标，不从终端打印推断退出码。第一检查点后的变动只增加 31 秒阈值元数据，公式未改变；旧分析器恢复为 `analysis-first-checkpoint.py`，其哈希与原检查点一致。`sdk-budget-context-proof.json` 和八份压缩 SDK 会话记录预算 20 递减至 0/1 的上下文；它证明提示进入持久会话，不证明模型遵守，也不是提供商请求体捕获。

候选仅按 no-follow 规则读取：保存所有修改字节、删除项与链接原文，运行时关闭后才清理本次工作副本。八份归档候选已全部离线重放，pytest 退出和逐节点结果一致；恢复原始缺陷的负对照确实重现缺陷并被拒绝。另在全新临时项目中从 0.10.2 归档的源码、wheel、历史解释器输入重建两个环境，128 个冻结文件保持一致，并成功重放一份候选。复用已安装的锁定 Node 依赖，没有新增模型请求或包下载。首次四批旧预检副本报告已与原归档逐字核对、确认没有本账户进程打开后清理，约释放 5.5 GB；最新预检、准备源码和所有原报告保留。

后续改进应优先让新增测试在预算早期获得实际执行与纠错机会，并提供清楚、如实的未完成反馈。需要把新增交付测试检查纳入正式验收，继续区分代码实现、测试本身、检查覆盖和模型正常收尾。已知任务可作开发回归；推广效果需再冻结新任务，不把本组结果当保留集成绩。医疗有效性仍需独立临床与目标用户验证。
