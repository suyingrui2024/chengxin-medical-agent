# 本地项目目录与原位执行

实现版本：0.10.0。通用执行工作台可以绑定用户通过原生选择器明确选择的已有项目，使用官方 DSH 文件、Bash、联网及子任务工具在原目录执行；患者问诊中的事实更新仍走原医疗控制器。

## 使用

在独立桌面切换“研发视图 → 执行工作台 → 打开本地项目”。系统选择器的“使用此项目”绑定实际目录，界面显示原路径及直接保存说明。选择、取消、查看文件和历史不调用模型；提交任务才开始实际执行。所选项目中的内容可被模型读取，生成、编辑和删除会直接影响原文件，包含用户自行放在其中的配置；这不是项目副本或自动回滚功能。

相同规范路径重新选择会复用可读的已有记录和会话，不重复创建另一个上下文。无模型配置时仍能打开已有记录、读取文件和本轮差异；继续执行须匹配原服务并提供当前凭据。首次绑定新项目需要模型配置，但不会立即调用。普通浏览器预览没有原生目录入口。

## 路径与生命周期

原生主进程取得路径，通过父进程专有 stdin 控制通道交给后端；渲染器只获得“打开选择器”的无参数方法，不获得任意 IPC、shell 或路径授权接口。主进程核对当前窗口、主 frame 和私有服务 origin。HTTP API 不接受目录字段，不能绕过选择器提供任意主机路径。取消和错误保留当前选择。

目录规范化后按原设备／inode 绑定。系统目录、整个账户根目录、应用与其受信依赖、应用执行资料以及已列出的账户配置／凭据目录均拒绝；包含这些保护目录的父目录也拒绝。别名先解析再判断，不能用链接绕过保护检查。任意项目内的秘密文件并不因此自动脱敏，选择时应理解整个项目的读写范围。

项目根目录持有文件锁，同一目录 inode 不能同时由本工具的另一执行工作区占用，即使使用另一个索引目录或路径别名。文件锁不约束编辑器和不参与锁协议的其他程序，也不保证不同父子目录绑定之间的互斥。目录被移走、丢失或同名替换后不能接管替代目录；恢复原路径与原 inode 才可继续原记录。没有自动重新定位或迁移。

| 位置 | 保存内容 |
| --- | --- |
| 用户选择的原目录 | 已有文件、实际代码修改及产物 |
| 执行根目录 `.state/<ID>/` | 官方 DSH 持久会话及运行资料 |
| 执行根目录 `.index/<ID>.json` | 路由摘要、目录身份、原项目路径及近期任务 |
| 执行根目录 `.index/changes/<ID>/<回合ID>.json` | 不挂载给模型的逐轮基线与有限差异文本 |

恢复索引增加可选 `project_path`，老记录没有此字段时继续使用原管理目录，无须迁移。变更工具和界面仍使用统一协议，主／子任务观察同一个项目与当前回合，基线的存储根始终是应用执行资料目录，不取项目父目录。关闭或保存失败不会删除项目文件。

模型运行时仍将当前目录映射到 `/workspace`，只挂载所选项目和对应运行资料；应用自己的 `.env`、其它未挂载文件夹不暴露。目录内指向外部的普通链接目标不会因此自动挂载，依赖绝对主机路径或项目外部文件的程序可能需要调整。这是当前 Linux x64 上的文件系统隔离和研究工具，不是同一操作系统账户下恶意程序的完整防护。

## 验证范围

本轮完整回归为 **174 项后端、21 组浏览器、源码与打包版各 10 组原生检查、7 项桥接断言**，格式检查通过；85 个包内源码及随附文件与工作区一致，544 个适用生产依赖版本匹配。另以独立 Python 进程和不同索引验证占用拒绝、释放后接管与原文件保护。

单元检查覆盖原位绑定、零模型打开、私有基线位置、同 inode 占用、别名复用、冷恢复、路径保护、替换目录拒绝，以及保存失败后释放占用且保留原文件。原生检查运行真实 Electron、父进程控制通道、完整 DSH 和本机确定模型；仅模拟系统选择器返回的临时测试目录，生产代码不含测试路径开关。

原生流程实际执行加法代码修复、子智能体查看原差异并独立运行、原文件保护、离线恢复和重复选择复用；同时检查取消、保护目录、HTTP 目录注入拒绝及 900 像素窗口布局。对隔离目录外的合成文件和本应用 `.env` 只检查不可见性，不读取密钥内容。该工程验证不构成整体 DSH 能力对照或临床评价，本轮不新增付费提供商请求。
