# v0.9.9 执行工具定向验收

本轮增加逐轮文件基线、主／子 `workspace_changes`、差异审阅窗口和显式长任务时限。合成工程验收，不是广泛编码对照或临床验证。

- 后端 168 项通过，含真实 185 秒命令跨越旧时限、前后台到期与接续。
- 浏览器 21 组、源码和打包原生桌面各 9 组、桥接 7 项通过；格式检查通过。
- 包内 80 个运行文件及 3 个随附文件匹配，544 个当前平台生产依赖版本一致。
- 真实 DeepSeek 13 次请求，全部 HTTP 200；主／子查变更、原测试执行与保护、临时文件清理、离线差异恢复通过。
- 首轮真实报告 `passed=false`：独立验收器复用 unittest 加载器，第二个测试目录无法导入。原始结果保留；仅修正验收器，对同一候选零模型请求验证通过。原测试和 5 项新回归、独立整数检查通过，恢复原缺陷的负对照失败符合预期。

`online-snapshot/` 是付费调用前冻结版本，包含当时有缺陷的验收脚本；`snapshot-final/` 保存已修正验收器和最终运行代码。运行部分在在线与离线修正间没有变化。`live-first-report.json`、`live-requests.json`、`corrected-verification.json`、`negative-control.json` 与日志分开保留。最初长时测试 fixture 失败和包校验范围错误也保留：前者误把命令字符串当完成输出，墙钟断言拒绝；后者误要求打包器保留开发元数据、并检查异平台可选依赖，随后按生产元数据转换与平台条件重新核对。

`candidate/` 只含本次合成项目的 5 个源文件／复核文件，不含模型状态或真实密钥。`verification.json` 为核对摘要，`archive-manifest.json` 记录所有其他归档文件的 SHA-256。旧 v0.9.8 公开任务和分数保持历史归属，本轮没有重新测量整体 DSH 能力。

在相同 Linux x64、锁定依赖与 v0.9.9 运行源码下，从项目根目录零模型请求重放：

```bash
PYTHONPATH=src python3 docs/evaluations/2026-10-16/v0.9.9/replay-change-checks.py
```

脚本校验运行源码和候选哈希，将候选复制到临时目录，并在相同 bwrap 文件系统策略下独立执行验收。源码已经更新时，请先将 `snapshot-final/` 恢复到另一个目录、使用锁文件准备依赖，并通过 `--project-root` 指定；不要覆盖正在使用的工作区。
