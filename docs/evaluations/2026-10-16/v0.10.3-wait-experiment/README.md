# 显式后台等待独立实验（未发布）

候选目录为 `.runtime/v0103-wait-experiment`，基于冻结的 0.10.2 源码，仅调整执行配置、相应提示和配置检查；增加一份可移植的运行回归用例。正式 0.10.2 与 24 次真实模型对照未使用这些改动。

前台默认 10 秒、上限 30 秒和后台默认 10 秒等待保持原策略。调用者显式要求更长 `job_output(wait=true, timeout_ms=...)` 时，上限设为固定官方 SDK 支持的 600 秒。共享任务截止与停止通道继续生效。所有原有测试文件与执行 worker 均与基础版本逐字一致。

已有 12 项运行检查及新增 3 项等待检查共同通过，耗时 121.178 秒；另独立重验了可移植控制组。最后的控制组只复制同版本代码并将显式等待上限改回 30 秒，不依赖历史安装目录。相同三次本机确定模型请求、同一 34 秒后台任务：控制组 30.06 秒返回仍在运行，候选 34.04 秒返回实际结束输出和文件。旧策略可再等待，因此这里不宣称完整任务总调用数已经降低。

等待中的用户取消约 0.05 秒后返回，并可在原 SDK 进程继续下一轮；4 秒总时限中断等待，保留原 `cancelled + time_budget_exhausted` 契约。这里只报告本机确定模型与真实 SDK 的机械检查，不是新真实模型效果、完整产品回归或正式发行。

早期失败保留：最初新用例误读了包含历史命令的整段请求，现仅检查工具返回；它还错误要求超时为 failed，候选一度据此改变状态，随后被原有测试拒绝。该状态改动已撤销，新用例已按既有契约修正，所有旧测试未更改。`verification.json` 记录实际差异和未完成验收。

正式合入前仍需基于最终归档完成完整后端、界面、原生桌面与打包检查，以及同约束的真实模型检查。不能将 0.10.2 的公开任务结果归因于这个候选。
