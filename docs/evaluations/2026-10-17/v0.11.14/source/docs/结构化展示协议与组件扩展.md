# 结构化展示协议与组件扩展

版本：medical-agent 0.11.6。更新日期：2026 年 10 月 17 日。

## v0.11.6 同轮补充回执

observation_series可选supplement包含text和pending／forwarded／unprocessed状态。分别显示待重试、已带入本轮问诊、尚未结构化，不把forwarded说成所有事实已验证。紧凑卡将补充放入已有记录折叠，接口错误阶段不突出旧摘要。格式异常独立回退，原话始终为惰性文本；字段缺省的旧回执仍读取。见[完整反馈](测量反馈与同轮补充.md)。

## v0.11.5 重复观察记录

新增受控组件`observation_series`，目前只接受已实现的腋温任务、摄氏单位、类型正确的有限记录、唯一当前值及覆盖数量；已知值、跳过、未知、取消分别呈现，原话为惰性文本。摘要引用同一组件，不再重复体温数值行；接续当前问题时使用紧凑记录条，历史和来源按需展开。新字段均为可选，旧事件继续读取。任务`repeat`元数据可携带上次记录和待核对候选；确认动作绑定当前action_id与尝试ID，不能从展示数据执行任意代码。协议细节与验证见[重复测量与问诊接续](重复测量与问诊接续.md)。

## v0.11.1 目录浏览与覆盖范围

工作区文件改为按实际目录逐层读取，使用`execution-directory/v1`，默认每页100项；支持上／下页、目录路径导航、隐藏与缓存切换，以及按文件相对路径直接预览。数量仅描述当前目录与当前筛选，包含文件、子目录和链接，不表示整个项目总文件数。链接可见但不跟随。

`GET /api/execution/{id}/directory?path=outputs&limit=100&hidden=0`返回条目、`next_cursor`、`scan_complete`、`total_entries`与原因。只读取一层，保留根目录身份与逐级fd、不跟随链接的约束；查询不调用模型。目录导航最多64层、路径最多4096字符。单次最多观察10,000项及约1秒的循环预算，慢文件系统的底层系统调用不保证可被这一计时中断。达到边界、条目不可读取或名称不是有效UTF-8时标为不完整，总数为`null`。单条文件预览另受既有大小／格式限制，不依赖目录是否完整或文件是否出现在当前页。

分页标记关联目录设备／inode、路径、筛选条件与已观察条目名称／类型摘要。内容改写不强迫翻页重置，条目集合或类型变化时旧标记返回409 `directory_changed`，界面从第一页重新读取。标记不是授权令牌或全文件系统原子快照；部分扫描不能证明未观察区域稳定。扫描期间并发变更可能产生一次混合观察，后续页面会再次读取和核对，不能声称跨页获得了事务快照。

普通界面轮询请求`include_artifacts=0`，只核对根目录仍可用并读取任务状态，不再每次递归扫描。原有`artifacts`默认概览为兼容接口保留，最多200个普通文件、1000个遍历条目和8层深度，新增`artifact_scan`明确报告是否扫描及范围不完整原因。其空列表或未扫描不能用于证明文件不存在。已选预览也不根据当前目录列表缺席推断删除，而是继续核对实际文件摘要。目录读取失败时清除旧条目、总数显示未知，恢复后重新读取；不将过期列表作为当前结果。

目录请求关联工作区和请求代次，旧工作区的迟到目录内容不能覆盖新工作区；文件变动刷新保留同路径焦点。后台读取不禁用路径输入和隐藏项切换，用户操作可使旧读取失效；延迟目录响应期间仍可继续输入并主动翻页。隐藏／缓存默认过滤，显式输入该目录路径仍可访问目录内可见文件。查看、翻页与无凭据恢复不增加模型请求。真实原生窗口与验证见[0.11.1验收](evaluations/2026-10-17/v0.11.1/README.md)。

## v0.11.0 执行产物的图像与表格

执行工作台使用独立的`execution-artifact/v1`投影，将实际工作区文件显示为图片、表格或文本。该协议不属于患者的`medical-ui/v1`，不会将模型生成的文件提升为注册计算回执或病例事实。界面显示文件类型、尺寸／行列、大小和“读取快照”，可放大查看，表格可切换原文。

宿主通过逐级目录fd、不跟随链接的有界读取获得字节，核对读取前后元数据，再计算SHA256。图片先返回类型、尺寸和摘要，真实图片请求再次读取并要求相同摘要；变化则拒绝返回。文件预览及原位项目使用相同目录身份约束、桌面鉴权和Origin规则。图片只由同源HTTP响应提供，保留`nosniff`及`no-store`，未放宽页面CSP去执行文件HTML或SVG。

```json
{"schema_version":"execution-artifact/v1","kind":"image","path":"产物/趋势.png","size":22732,"sha256":"实际字节的64位十六进制摘要","revision":"元数据提示","mime":"image/png","width":960,"height":576}
```

示例中的摘要是说明占位符，实际渲染器只接受64位十六进制。结构由`execution_artifacts.py`根据真实字节生成，前端不解析模型文本来构造图像地址。PNG要求正确区块边界、CRC、静态内容和结束标记；常用JPEG核对结构和尺寸。每图最多4MiB、单边8192、总16,777,216像素；像素解码仍交给浏览器，失败显示可重读反馈，这不是完整图像真实性或医学内容验证。

CSV／TSV仅解析UTF-8文本，最多128,000字节。表格保留引号、单元格换行、原文和公式字符串；显示前100条非空记录与24列，首条记录作为表头的格式约定直接标明，原文随时可查。截断及不等长行直接提示，格式不完整时退回原文。不会执行单元格公式，也不推断单位、趋势或临床含义。HTML、SVG和其它可读代码通过`textContent`显示。

文件列表元数据只作提示，不能由时间戳或大小相同证明内容相同。工作台可见且已选中文件时，借现有轮询约每两秒额外有界读取该文件并核对内容摘要；变化或无法核对时保留快照并提示重新读取。核对不是连续监控、原子快照或交付检查，不能证明两次观察之间未发生变化。只核对所选文件，不扫描全部产物或发送模型请求。选择另一文件、切换工作区或目录不可用会使旧请求失效并关闭放大层。

源码及打包版的实际窗口和最终结果见[0.11.0验收](evaluations/2026-10-17/v0.11.0/README.md)。下图由真实DSH工具执行Matplotlib和CSV写入后生成，使用合成换算数据；不是临床测量。

## 数据和组件

回复和能力执行结果新增可选 `presentation`，保留原有字段：

```json
{
  "schema_version": "medical-ui/v1",
  "blocks": [
    {
      "id": "message:current-action",
      "type": "message",
      "data": { "text": "请描述当前最困扰的问题。", "kind": "question" }
    }
  ]
}
```

`schema_version` 由宿主固定；`id` 用于识别展示块，`type` 对应本地注册组件。`data` 不能携带可执行处理器。患者操作由已打包代码绑定，继续调用现有受控 API。

| 类型 | 来源 | 已实现的展示 |
| --- | --- | --- |
| `message` | 控制器的患者可见回复 | 文本气泡；危险提示保留原有突出样式 |
| `question` | 已登记问题和本轮实际问句、选项 | 当前问题图卡、趋势、程度刻度和结构提示；临时追问保留实际原文 |
| `self_check` | 已注册、已打包任务 | 当前步骤放大图、步骤说明、导航、停止条件与反馈入口 |
| `calculation` | 输入输出校验后的能力结果 | 实际数值、输入项、单位、公式、确认状态、质量与执行依据 |
| `observation_series` | 控制器生成的当前观察及尝试记录 | 当前数值、未完成标记、折叠历史及重复入口 |
| `summary` | 控制器生成的病例摘要 | 已知记录、未知项、来源、可更正项与后续提示 |
| `notice` | 现有急症规则或用户主动求助后的路由结果 | 完整操作说明、固定图标与可展开原因；不要求普通摘要字段齐全 |

投影函数在 `src/medagent/presentation.py`。患者展示投影不包含 `developer_trace`；原有研发事件和 API 字段仍保留，因此展示投影不构成访问权限隔离。

0.10.3 的 `notice.data` 保留 `title/items`，增加可选 `message`，完整复制控制器的患者操作说明；不按标点切分或从模型输出提炼新的医疗行动。新卡片以高对比正文展示，触发原因收在原生 details 中；重复消息气泡隐藏但事件原文保留。没有 `message` 的历史投影继续显示原有原因，旧回复适配器也补入原文。紧急消息取消入场动画，截图检查另禁用动画避免抓到中间态。

前端 `structured-ui.js` 提供 `createRenderer`、`register`、`render` 和 `renderEnvelope`，同时提供旧回复与能力结果的有限兼容转换。组件自行检查必要字段和类型，这不是通用 JSON Schema 实现。未知协议、未知类型或组件异常显示独立回退卡片，其他组件继续显示。

`question.data` 包含 `question_id`、`prompt`、`canonical`、`input_kind`、`choices`。服务端仅当本轮问句与登记原文完全相同时置 `canonical=true`；前端 `visual-question.js` 使用受信视觉词汇补充固定问题。临时追问的 `canonical=false`，不会被固定模板改变含义。所有选项均来自实际回复，交互继续传递原 `choice_value` 与行动版本，渲染器不产生医学事实。

图标及人体轮廓是仓库内固定 SVG 路径；仅这些常量被解析成 SVG，患者或模型文本始终经 `textContent` 写入。部位图只绑定已注册部位，先选择再确认。v0.11.10起，不适刻度使用独立的组件草稿，不修改文字输入；明确确认后才向既有问诊接口提交分数，不会因选中直接写入事实。测量失败由 `AgentReply.input_error` 投影为任务的 `feedback`，在聚焦图示内直接显示；不改变任务状态或观察解释。

## 自查进度

体温内容包升级为 0.2.0，新增可选 `step_assets`，与 `steps` 一一对应。当前通过已打包 SVG 的三个 `<view>` 片段呈现单步骤，不生成新的医学动作：

```json
{
  "asset": "/temperature.svg",
  "step_assets": [
    "/temperature.svg#step-1",
    "/temperature.svg#step-2",
    "/temperature.svg#step-3"
  ]
}
```

注册表拒绝外部 URL、非 SVG 地址、缺失资源和步骤数量不匹配。客户端只接受同样受限的本地 SVG 路径。没有 `step_assets` 的旧任务继续显示整体示意图。

进度在当前界面进程的 Map 中按会话、任务及内容包版本保存。展开历史、切换视图和重新打开同一任务时复用当前步骤；任务完成后清除对应进度。页面刷新或应用重启不恢复步骤，本版未增加持久化。

最后一步的“填写结果”只聚焦输入框，不宣称动作完成、读数已采集或已经过视觉验证。预览没有该提交行为，患者仍可自由跳过任务。

## 计算展示

结果数值和公式来自能力执行，不从模型自然语言中提取。投影保留输入、能力版本、组合摘要、输入来源、待确认状态和质量。会谈中的展示 ID 关联 `execution_id`；相同执行重复加载不新增卡片，数据变化时替换对应卡片。

v0.9.5已加入患者可编辑输入卡、明确核对及固定换算后的原问诊接续，详见[患者计算输入与问诊衔接](患者计算输入与问诊衔接.md)。核对输入仍不证明测量质量或公式医学适用性，结果不自动写成临床事实。

## 摘要与更正

演示模式的普通摘要现在停留在 `summary` 阶段，保留输入与更正入口；只有点击“摘要准确”才进入 `closed`。更正会调用既有事实更正 API，保留历史，再生成新的摘要和确认动作。旧摘要确认动作被拒绝。需要优先求助的路径仍保持原有关闭行为。

当前摘要提供核心可编辑记录的更正按钮；未知项仍可从病例侧栏更正。历史摘要的旧更正按钮禁用，回看当前待确认会谈会重新启用最新摘要。当前事实更正使用`expected_fact_id`核对版本；旧版本请求返回409并保留草稿，具体范围见[病例与更正设计](首版产品与技术设计.md#5-病例证据与更正)。这不是生产多用户身份及权限体系。

## 新组件和插件

复用已有展示类型的受信插件可以直接使用注册组件。增加新展示类型时，需要在宿主代码中提供验证函数和渲染函数并重新打包；仅修改清单不会自动加载前端代码。注册表拒绝重复组件名称，防止静默替换已有组件。

下一步可以将此投影适配为 A2UI，继续使用医疗控制器持有的事实和工具结果。已有独立 A2UI 实验仍可运行；本版没有接入官方 Lit 渲染器、AG-UI 网络协议、MCP Apps iframe 宿主或第三方安装机制。

## 验证和边界

历史v0.4通过 64 项 Python 测试（含真实 DSH 进程和本机确定响应链路）、11 组浏览器测试，以及源码版和打包版各一次 Electron 检查。已核对打包程序中的 36 个源码和资源文件与当前实现一致。独立 A2UI v0.9.1 契约实验也已重新通过。

Python 验证投影不混入调试内容、计算来源与质量保留、投影副本不修改原输入、紧急路由投影，以及非法图示资源拒绝。问诊测试覆盖摘要更正、过期确认拒绝和最终确认。

浏览器验证完整问诊、自查图示切换、展开历史保留步骤、摘要更正与确认、未知组件回退、单组件异常隔离、患者文字不执行、求助提示及窄屏布局。Electron 测试验证组件在独立窗口中运行、实际计算、分步图示以及服务隔离和退出回收。

图示和规则仍待临床审核；本轮使用合成病例、离线演示和确定响应的 DSH 进程链路，不代表真实模型临床质量或患者理解能力已得到验证。未增加运行取消、跨进程恢复或新的临床公式。


## v0.11.2 未确认原话

`summary` 可选增加 `unknown_details`，原 `unknown` 标签数组继续用于旧事件兼容。明细为当前事实的 `key`、`label`、`evidence`、`source`、`quality`，以及可选 `context`（`scope=source_turn`、`turn_id`、完整原话 `text`）。上下文来自宿主事件，必须包含当前引文；仅显示同轮原话，不声称整体属于该字段。渲染器校验契约，文本保持惰性；短引文直接显示，超过160字符折叠，原话与来源可核对。详见[完整契约与验证边界](待确认病史的原话与摘要.md)。


## v0.11.4 已记录项目的原话

summary.known项目可选增加evidence及context（scope=source_turn、turn_id、text），与未知明细使用相同受控校验。原话与来源默认折叠，展开占满内容栏，唯一字面引文高亮并定位；同一引文出现多次时不猜测是哪一处。原轮可能含其他已更正内容，须以当前事实为准。展开仅操作本地DOM，不调用模型或更新事实。兼容旧known数组；安全、来源与长问诊只读输入目录见[设计](长问诊的信息保留与原话核对.md)。


## v0.11.10：组件草稿与显式提交

`question`的数据协议保持不变。程度组件另使用宿主注入的本地交互上下文：`questionDraft.degree`仅接受0至10的整数；`onQuestionDraft({degree})`保留选择；`onConfirmAnswer("5分")`在患者明确确认后提交。回调由已打包代码提供，模型不能下发处理器或指定可执行代码。未提供提交回调、只读或忙碌时，卡片不接受选中／提交。

页面用会谈和动作身份绑定组件草稿，切换会谈后可恢复同一动作的选择。不同动作不复用旧选择；普通文字草稿使用独立会谈键。问题与图示任务的`isBusy/onChoose/onConfirmAnswer`同时检查原会谈及动作，旧控件即使被程序重新启用也不能提交到新问题。真正处理仍由服务端事实、原话证据和动作校验负责，界面确认不证明临床有效。

选择不发送病例请求，不改变事件或事实；确认仍经过既有`messages`接口，只发送所选分数。若输入框有另写的文字，确认分数后仍保留，不能暗中拼接成患者一次发言。两种草稿都只保存在当前页面内存，不写localStorage、不自动上传、不保证刷新／关闭后恢复。图形化设计及截图见[界面检查](图形界面设计与检查.md#v01110图形答案与文字补充)。


## v0.11.11：图示任务的交互身份与草稿

`self_check.data.interaction_id`是新增的可选展示字段。宿主在记录回复前复制任务数据，首次提供绑定本会谈`self_check.offered`事件；重复测量使用已登记的尝试ID。反馈沿用当前可见任务的身份；显式接续可恢复较早提供的任务，之后的录入错误仍跟随该任务，而非盲目选择最新的offered事件。新发起同名任务得到不同身份，未找到可信来源的旧任务退回当前动作身份。

该字段不是测量结果、真实身份核验或授权凭证，也不修改内容目录、当前事实和适用性。步骤按会谈、任务、内容版本和交互身份保存；部位草稿使用同一交互身份，与文字补充分开。切换会谈、展开对话再返回，以及同一次任务的新错误回复可恢复操作状态；新一次任务从头开始。确认前不提交事实，确认只提交登记的部位，文字仍待发送。页面内存生命周期与前版一致。

客户端保留步骤／选择，但不沿用旧回调。确认和步骤按钮仍校验原会谈及动作；只读或忙碌不接受交互。任务新回复先重置旧滚动位置，错误提示在快捷选项等布局完成后进入可见区域并获得焦点；不把DOM存在当作患者已经看见。较大的图示仍采用任务区域滚动，本轮不声称全部图示、说明与操作在每种窗口同时可见，也未开展患者理解研究。[验证与原始失败](evaluations/2026-10-17/v0.11.11/README.md)。


## v0.11.12：部位图的图示与控制分离

`self_check`数据、登记的部位值、确认接口和任务身份不变。人体轮廓沿用仓库常量，布局改为示意加独立选项；展示标记由固定选项映射，不接受模型指定SVG或坐标。仅显示当前方向的人体，四肢以分组示意表达，不将标记数量转成症状数，也不推断左右、精确部位或疾病。

分步原文与进度保留在可展开说明中。选择仍只更新当前任务草稿；确认只提交现有选项值，文字继续独立。小窗口使用受控的紧凑布局，移除重复输入提示、减少外围留白，但不删除记录查看、其他部位、跳过、求助和研究说明。渲染器属于应用版本，评审应同时绑定应用源码及内容包版本，不能只凭内容包版本推断患者看到的图示。图库仍是已登记素材的预览，不等同于实际问诊交互。[验证](evaluations/2026-10-17/v0.11.12/README.md)。
