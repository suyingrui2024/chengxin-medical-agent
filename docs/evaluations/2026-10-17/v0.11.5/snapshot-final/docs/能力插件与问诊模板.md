# 能力插件与问诊模板 v0.7

更新日期：2026 年 10 月 15 日。本文对应已实现的受信能力组合器，接口为 `medical-capability/v1`。

v0.7 已通过 103 项 Python 测试（含真实 DSH 进程链路和失败轨迹重放）、13 组浏览器交互测试。独立桌面另有真实接口全流程与故障重试验收。工程测试使用合成输入；真实 API 结果另见 [评测报告](缓存优化与真实模型评测.md)。

## 使用与评审

应用默认进入患者视图，只显示问诊与会谈记录。左侧“界面模式”切到研发视图后，可以打开“能力与模板”、图示库、运行检查及模型配置。视图切换保留当前会谈，只是展示偏好，不构成身份认证。

![能力与模板管理](assets/ui/08-capabilities.png)

建议检查：

1. 开始一个离线会谈，再打开研发视图的“能力与模板”。
2. 执行默认示例 `1.25 kg → g`，核对 `1250 g`、公式、输入和版本。
3. 将目标改为 `mL`，确认拒绝跨量纲换算，并清除上次的成功结果。
4. 停用体温内容包，核对当前会谈的配置摘要保持原值。
5. 新建会谈，在运行检查的 `session.created` 中展开 `runtime_snapshot`，核对新的启用状态。
6. 应用“病史整理研究模板”，确认新配置没有图示和计算；再切回“通用问诊研究模板”。

独立验证不创建会谈，也不读取或写入病例。其事件记录在独立的 `capability-preview` 身份下；当前界面只显示本次验证结果。真实问诊的能力调用进入该会谈的事件轨迹，可以按“能力执行”筛选。

## 三种组成

| 组成 | 当前实现 | 职责 |
| --- | --- | --- |
| 问诊模板 | `general`、`history` | 组合可用能力；两者复用通用问诊问题与控制器 |
| 图示内容包 | `observe.temperature`、`observe.location` | 目的、设备、步骤、图示、反馈、结果字段、适用条件与解释器绑定 |
| 执行插件 | `calculate.units` | 接收契约限定的输入，返回可校验、可重算的结果 |

当前模板只提供能力组合差异，尚不支持自定义整套问题、风险策略或结束条件。模型根据回答选择下一步，医疗控制器负责病例写入、风险优先级、适用性和终止。

```text
src/medagent/extensions/
  contracts.py       有界 JSON 契约校验
  registry.py        能力注册、组合快照和执行检查
  builtin.py         受信实现映射、换算与观察解释器
  packs/             三个能力清单
  templates/         两个问诊组合模板
```

DSH 保持官方 SDK/CLI 接入。本协议属于项目的医疗能力层，不是 DSH 原生包格式。上游源码和已固定发行版均未变更。

## 清单与执行契约

清单包含 `id/version/api_version/name/description/kind/permissions/ui/review_status/validation`。审核状态和验证范围是登记信息，不是自动获得的认证。

计算能力另有输入输出契约与示例；图示包包含完整 `task`。契约支持对象、数组、字符串、布尔、有限数值，以及必填、额外字段拒绝、枚举、长度和范围等规则。不支持的关键字在加载时拒绝，不能宣称实现完整 JSON Schema。

模型通过统一工具执行：

```json
{
  "tool": "run_capability",
  "arguments": {
    "id": "calculate.units",
    "input": {"value": "1.25", "from_unit": "kg", "to_unit": "g"}
  }
}
```

执行前校验输入，执行后校验输出。实现只收到输入副本，框架不传入病例对象。未启用、未注册的能力拒绝执行；失败返回工具错误供协调器调整。急症、升级或已关闭会谈不继续计算。

结果保留能力版本、组合摘要、输入、公式、结果、限制和来源。问诊中的结果保存为 `calculations` 草稿及事件，**不写入临床事实**。模型输入标为 `model_proposal`，独立验证标为 `developer_preview`；均保留 `unconfirmed/not_assessed`。

当前换算采用 Decimal，支持 `kg/g/mg` 或 `L/mL` 同量纲转换，拒绝缺少密度的质量/体积转换、负数、非有限值、指数表示和超长输入。它不推导药物剂量或医疗建议。

图示反馈保留患者报告来源，由控制器处理照护者归属；不能升级为设备直连、质量已验证或阴性体征。解释器失败时保留任务；跳过由通用层处理，即使解释器出错也能记录为未知且未执行。

v0.6 的任务清单新增可选 `invalidate_on`：只接受去重的 `chief_complaint`、`age_years` 列表；未声明时沿用主诉变更失效。`observe.location` 0.2.0 声明 `["chief_complaint"]`；`observe.temperature` 0.3.0 声明 `[]`，同一患者的读数不会因更正年龄或主诉文字被删除。受影响结果从当前事实中移除、保留历史和失效事件。更换已确认咨询对象需要另建会谈。

患者明确请求的任务可经 `request_self_check` 登记到会谈待办，仍需通过适用性和急症筛查门才能展示。登记保存原文证据，不调用插件解释器、不写观察结果；未知筛查保持等待。待办按任务去重，主诉更正时取消。

v0.7 提供可选 `request_phrases/cancel_phrases`：每项最多 16 条，每条 2–40 字，拒绝重复和非法类型。`observe.temperature` 0.4.0 与 `observe.location` 0.3.0 声明了有限的明确短语。事实写入后控制器补充匹配的待办，模型可继续通过登记工具处理其他表达；这些规则不代替通用语义判断。取消保存为未知且未执行，不删除已有读数；明确重开只撤回未执行的当前标记，保留历史。

温度录入解析完整数值，保留 `38.25` 的精度，拒绝 `380`、负值、华氏或多个数值；不从错误输入中截取温度。当前单框仅支持一个数值，带数值时间戳的文本需分开填写，范围检查沿用原型的 34 至小于 44 摄氏度，不能把范围外输入解释为正常。

## 配置与会谈隔离

启停能力或应用模板会创建新的注册表及运行实例。每个会谈保留应用版本、模板、完整能力清单与启用状态、SHA-256、问题版本与摘要，以及模型适配器和配置模型 ID。模型提示摘要另保存在 `agent.started`。

旧会谈继续路由到原实例，仍可完成原任务，历史结果不随停用删除。快照追溯工程配置，不冻结外部模型权重，也不提供跨进程恢复。

配置请求携带 `expected_revision`；发生并发变更时返回 409。病例、启停状态和模板选择均只在进程内保存，关闭后恢复默认配置。

| API | 行为 |
| --- | --- |
| `GET /api/capabilities` | 当前组合、清单、模板和 revision |
| `POST /api/capabilities/configure` | `id/enabled/expected_revision` 或 `template_id/expected_revision` |
| `POST /api/capabilities/preview` | `id/input/expected_revision`；独立验证 |
| `GET /api/tasks` | 新会谈配置启用的图示 |
| `GET /api/sessions/{id}` | 该会谈自己的快照、事实和计算草稿 |

桌面服务继续要求实例凭证。研发视图没有独立管理员权限，浏览器开发服务也没有用户隔离。

## 扩展与边界

新增图示包：增加清单和本地 SVG，在 `builtin.py` 的白名单绑定解释器，加入模板。可以声明 `result_label` 作为新观察字段的中文名称，不能覆盖核心问诊字段。

新增计算插件：提供清单、输入输出契约及受信执行函数，再加入实现映射与模板。复用 `calculation` 卡片时，结果遵循 `value/unit/formula/method/limitations` 结构。复用现有组件时，无需修改会谈控制器或前端主体；修改实现后需重启源码应用或重新打包桌面版。

当前只接受 `permissions: []`。没有第三方安装、依赖解算、任意代码热加载、网络授权或后端代码沙箱。Python 进程内受信代码仍拥有进程权限；权限声明与 Electron 页面沙箱不能隔离它。设备、网络、视觉插件需要另外实现宿主权限、数据流和隔离策略。

## 验证

`tests/test_capabilities.py` 验证换算精度、量纲和格式拒绝、接口契约、畸形输出、来源质量、失败后跳过、配置并发及会谈版本固定。测试另外注册新计算能力与新观察包，复用现有控制器、摘要和依赖失效流程。

`tests/ui/capabilities.spec.mjs` 验证视图切换、独立计算、错误结果清除、启停和模板切换。桌面测试也执行实际换算；DSH 集成测试通过官方运行时完成多事实写入、单位换算、观察计算结果和选择下一问，随后验证急症输入不再请求模型。

这些检查不证明真实模型能选对能力、理解数值或提供临床有效建议。图示与风险规则尚未临床审核，本版用于合成病例和内部评审。

## v0.11.5 重复观察声明

内容包可选`repeatable`必须为布尔值；当前只有已实现的temperature输入可启用，不能据此开放任意自查。`repeat_phrases`沿用每项最多16条、每条2–40字和去重校验。首版observe.temperature为0.6.0，显式允许已有有效值后的重复测量；`repeat_self_check`须通过适用性、急症筛查和本轮明确请求引文校验。用户按钮另须匹配当前动作版本。新成功值通过supersedes关联旧值；未知／跳过独立保存尝试，不删除已有有效值。详见[生命周期和展示](重复测量与问诊接续.md)。
