# 重复测量与问诊接续 · v0.11.5

已有读数不能阻止患者再次测量，也不能在本次未完成时被冒充为新读数。本版把重复测量作为一次可中断、可接续的图示任务，目前只支持已注册的腋温任务，不扩展自查动作或临床阈值。

## 交互

摘要的腋温卡突出当前保留的数值、来源和质量；旧读数及原话默认折叠。点击“再测一次”回到图示第一步，卡片提示旧值将保留。失败可重新填写或跳过，完成后恢复原来的问题、澄清、摘要或换算卡。直接给出“刚刚又测了一次腋温40.1℃”等明确叙述时，展示患者原文解析出的候选值；点击核对才写入，也可重新填写或跳过。

| 本次反馈 | 当前结构化事实 | 尝试记录 |
| --- | --- | --- |
| 有效读数 | 写入新Fact，supersedes指向旧Fact | recorded，关联新Fact |
| 无效／冲突数值 | 原值保留，停留当前任务 | 保留待处理尝试及失败事件 |
| 不确定读数 | 已有有效值保留 | unconfirmed、inadequate |
| 跳过／做不到 | 已有有效值保留 | skipped、not_done |
| 求助或事实更正 | 不从旧卡补写读数 | cancelled，旧候选失效 |

没有既有有效值时，未知仍按原有协议记录为未知；旧的“未执行后重新请求”流程继续保留。所有手工读数保持患者／照护者来源，质量未评价；程序解析通过不升级为设备来源或临床测量验证。

## 生命周期与原话

`repeat_self_check` 只对内容包声明repeatable、主诉适用、已有记录且急症筛查明确阴性的任务开放。按钮须匹配当前action_id，工具提议须引用本轮明确重复请求；否定、假设和提问不会自动触发文字快捷路径。首版快捷匹配是有限短语集，不是通用自然语言理解。

控制器保存原问题及其实际措辞、澄清标记、阶段、换算提议及执行标识。测量完成后恢复相同交互；摘要从最新事实重建，不复用包含旧读数的摘要。确认候选写入原报告轮次和全文，确认动作另记事件。跳过不会覆盖旧值；尝试状态独立保存在observation_attempts中。

有效读数再次经过现有风险规则；若需要升级则结束普通问诊，丢弃挂起的计算卡，不恢复原问题。求助文本仍优先于旧动作版本校验。候选核对前不写入结构化事实，这条路径尚未经过临床验证，不证明所有风险描述都能被识别。

## 视觉协议

`observation_series` 为受控组件，包含任务、单位、当前记录、有限历史和覆盖数量。摘要嵌入同样的组件，不重复展示另一张体温数值卡。记录链沿当前Fact的supersedes回溯，不把已撤回的孤立历史事实重新变成当前值。最多展示8条，若跳过次数过多仍保留当前采用值，明确注明展示条数；完整记录保留在状态／事件中。

时间统一标为**系统记录时间**，不推断真实测量时间；不绘制连续趋势线、正常范围或臆造的测量质量。失败、跳过和取消用文字状态区分，不用绿色数值假装测量完成。原话作为惰性文本，异常契约回退；旧事件没有新字段时仍可回看。

## 验证与限制

后端测试使用实际控制器和注册任务，覆盖正常替代、来源、原话、失败／跳过、未知、版本冲突、假设、紧急优先、更正、问题／计算恢复和长记录覆盖。界面测试用本机确定模型响应，经过实际HTTP服务、真实渲染器及独立桌面；不以预填DOM代替问诊流程。

```bash
PYTHONPATH=src python3 -B -m unittest tests.test_repeated_observations -v
npm run test:ui -- --grep 'repeated temperatures|observation rendering'
DISPLAY=:1 XAUTHORITY=/run/user/1000/gdm/Xauthority npm run test:desktop -- --grep 'native repeat observations'
```

`scripts/evaluate_repeated_observations.py` 需要显式提供新报告路径和事前冻结的源码摘要，最多12次真实提供商请求；通过父进程网关使用本地密钥，事件和报告剔除密钥及网关凭证。它检验真实DSH开场和后续零模型重复测量，不评估模型选择repeat_self_check工具的覆盖率。工程和合成结果均不能证明临床有效性或目标患者的图示理解能力。
