# 有来源的计算插件与血糖单位换算

实现版本：0.11.7。新增 `calculate.glucose` 0.1.0，用第二个计算实例验证同一插件链路：模型提议 → 引文与适用项目校验 → 患者修改、核对 → 宿主计算 → 结构化结果 → 接续原问诊。研发工作台的主、子智能体可通过 `medical_capabilities/medical_calculate` 使用同一实现。

## 来源选择与运算规则

采用 ADA Common Terms 中两个单位词条的文字规则：血糖从 mmol/L 转为 mg/dL 乘18，反向除18。系数18是常用近似约定，因此跨单位结果和公式显示 `≈`，不把十进制程序运算等同于测量精度。[ADA 原始资料](https://diabetes.org/about-diabetes/common-terms)（核对日期：2026-10-17）。

核对时发现，ADA 反向文字说明写“除18”，紧随的示例却印成乘号。实现采用文字规则，以正反向算例和逆运算检验方向，没有照搬该示例中的符号。这说明来源权威仍需交叉检查与数值验证。

NIDDK《Diabetes in America》第三版附录的葡萄糖页另列 `mg/dL × 0.0555`。本版不混用这两个经过取近似的系数，也不以该表逐项显示值要求本实现完全一致。例如本实现 `97 ÷ 18` 显示 `5.3889`；这是所声明的18系数策略，而非额外测量精度。[NIDDK 换算附录，第2页](https://www.niddk.nih.gov/-/media/Files/Strategic-Plans/Diabetes-in-America-3rd-Edition/DIA_Conversions.pdf)。

使用 Decimal（48位上下文）；跨单位四舍五入至最多4位小数。非零极小值若将显示成零，改保留4位有效数字；相同单位保留输入值。允许非负十进制，整数及小数各最多12位；0只是工程输入域的一部分，不被解释为正常临床读数。

## 插件契约

- 清单声明输入输出契约、版本、来源、患者组件及出处策略。来源由受信清单提供，模型不能替换为任意网页。
- `unit_conversion/v1` 保留原质量／体积组件；`unit_conversion/v2` 从受信策略提供单位、项目名称、范围和错误反馈。当前只有 `mass_or_volume`、`blood_glucose` 两种策略；未知策略拒绝加载。
- 此次复用的是“三字段换算”组件，不宣称已经实现任意医疗公式表单。未来增加多变量公式，需要增加并验证相应输入组件、适用条件和出处策略。
- 血糖预填必须有连续原话明确对应项目、数值与原单位。其他检验、HbA1c/eAG、负号、指数、区间、不等式、否定以及多读数歧义不会被截成一个确定读数。语言规则有覆盖边界，失败可澄清或让用户自行填写，不能宣称完整语义识别。
- 通用模板更新为0.2.0，新增启用血糖换算；病史整理模板仍不启用计算。既有绑定不被静默升级，旧执行回执仍可离线阅读。
- 结果保留原始请求、最初提议、最终参数、公式、近似与显示规则、来源、能力版本。研究执行回执额外关联真实用户轮次、工作区与实现摘要；主、子任务共用原预算。

这仍是项目内受信实现注册，不是第三方任意代码安装或完整插件市场。来源格式校验、类型检查和可重算不等于临床审核。

## 患者呈现与接续

输入卡明确标注“血糖（葡萄糖）单位换算”，仅提供两个合法单位；缺失值留空，允许编辑。核对后突出结果、单位、近似符号、三个输入和一行公式；来源、范围与舍入说明折叠。未知组件、缺少必要依据或非HTTPS来源有可见回退；标题按文本渲染。

核对、纠错和“继续问诊”由宿主处理，不增加模型请求。计算保留为草稿，不自动写入病例事实；参数已核对不升级测量质量。失去响应后的重复提交仍受动作版本保护，不能重复计算。

只完成血糖读数的单位换算，不评价血糖高低、不判断采样条件、不推算诊断、饮食摄入或用药。患者可能对结果提出进一步问题；当前不应据此声称已经支持糖尿病管理流程。
