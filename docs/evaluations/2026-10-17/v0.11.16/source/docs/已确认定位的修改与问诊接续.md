# 已确认定位的修改与问诊接续

目标版本：0.11.16。沿用`location-answer/v1`与已注册定位内容，不新增诊断或医学查体动作。

## 为什么需要这一步

0.11.15允许修改待核对草稿，但已经确认的定位不属于普通病史编辑字段。患者随后发现左右选反时，既不能用普通文字直接覆盖观察，也不能通过不可重复的旧图示重开。本版提供受事实版本约束的修改入口。

问诊记录、当前摘要的定位项目可以选择“修改定位”。修改卡显示原记录来源和可编辑选项。确认前原事实保持有效，取消后回到原问题；确认后新事实通过`supersedes`和`structured_input.revision_of`关联旧事实。确认轮次与规范化选项是新记录来源，旧引文不能冒充修改后的证据。质量仍为`not_assessed`。

## 模型与宿主

患者自然语言明确更正位置时，模型先调用`revise_self_check`引用原话，宿主建立版本绑定的修改卡并返回观察；模型随后可用`propose_self_check_result`提议本轮明确修改。原记录的其他维度由宿主保留，标注为`baseline`，不伪装为本轮新引文。患者最终核对后才写入；`record_facts`仍没有观察字段写权限。

假设例子、拒绝修改或只更正药名不建立定位修改。这里使用有界的请求词校验，不声称完整理解所有自然语言。不确定的左右不能被确定化；需要澄清时相关维度留空，原记录仍可展开查看。

## 接续与中断

- 打开、取消和纯定位确认由宿主执行，不额外调用模型；原问题的文字和未发送草稿保留，旧按钮不能提交到新步骤。
- 修改期间补充新病史，继续处理新信息；返回修改后不恢复已经回答过的旧问题，接续较新的有效问题。
- 原备注保留且不重复处理；本次新增备注另行交给模型，失败可重试，已确认事实不重复写入。
- 从摘要修改后重建当前摘要；已由用户确认关闭的记录可显式重开修改，取消仍返回已关闭状态，确认修改后需要重新核对摘要。
- 事实版本、动作版本或表单标识不匹配，在记录答案前拒绝。其他字段更正、换人边界和求助沿用现有失效规则，不回滚新的病例事实。
- 同时只处理一张输入卡；计算、其他图示或待重试补充未结束时不再开启定位修改。用户可完成或跳过当前卡后再修改。

更改大部位会清空依赖于原部位的区域、左右和范围选择，避免把旧部位细节带到另一个部位。手机端打开修改时关闭记录面板，聚焦当前核对卡。历史摘要保持只读。

## 证据范围

0.11.15的全新原生呼吸道问诊、急症门和服务恢复已用21次真实请求验证，见[独立归档](evaluations/2026-10-17/v0.11.15-full-flow/README.md)。它没有经历细化定位表单，不能冒充本版定位修改的全流程证据。

本版另以两类脚本准备的定位记录进行实际DSH决策评估：明确改为左侧、不确定哪一侧。合计4次真实请求，均建立可核对修改，无需额外模型调用即可确认或取消并返回原问题。该定向评估不等于从零开始的完整定位问诊，也不等于临床验证。具体源码、日志和最终界面检查范围随本版验收记录保存。

随后在实际0.11.16程序中新建头痛问诊，完成首次细化定位、自然语言修改、患者确认与最终摘要核对；患者视图的独立补验使用15次请求且未重试。四类完整病例在多轮中取得通过证据，首次整轮存在网络失败并保留原报告；本版完整流程共72次请求尝试，另有上述4次定向请求。见[本版软件与真实模型验收](evaluations/2026-10-17/v0.11.16/README.md)。这些是合成工程病例，临床审核和目标用户研究仍未完成。
