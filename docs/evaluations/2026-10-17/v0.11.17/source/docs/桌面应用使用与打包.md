## 1. 直接打开

当前电脑桌面已有 **“澄心问诊”** 启动图标，双击即可打开独立应用窗口。若 GNOME 首次提示启动权限，右键选择“允许启动”。不需要打开浏览器、填写网址或手动启动 Python 服务。

桌面启动器位于 `/home/suyingrui/Desktop/澄心问诊.desktop`，指向项目中的 `scripts/start-desktop.sh`。启动器优先使用已打包程序；不存在时使用已安装的开发版 Electron。

也可以直接运行：

```bash
./scripts/start-desktop.sh
```

打包后的程序在：

```text
dist/desktop/Chengxin-0.11.17-linux-x64/Chengxin
```

请保留 `Chengxin-0.11.17-linux-x64` 整个目录，不能只复制其中一个可执行文件。

不同版本使用独立目录和运行资料目录，旧版进程不会被强制关闭。桌面启动器优先打开新版。患者会谈仍只在各自进程内保存；0.9.3 起的执行工作区另有持久恢复索引。

## 2. 桌面体验

0.11.1 支持目录导航、每页100项、隐藏与缓存切换，以及按相对路径打开文件。计数指本目录当前筛选下的条目，包含子目录和链接；链接只显示、不跟随。扫描不完整时总数显示未知，目录条目变化后从第一页重新读取。图表和表格预览可直接访问深层文件，工作区切换会丢弃旧目录请求。[验收与范围](evaluations/2026-10-17/v0.11.1/README.md)。

0.11.0 在文件列表区分图像、表格与文本；点击实际文件直接预览，可放大查看，表格可切换原文。每次读取均标注快照；后台仅核对当前选中文件的有界内容摘要，变化后由用户重新读取。仅支持静态PNG／常用JPEG与UTF-8表格，图像最多4MiB和16,777,216像素，表格最多128,000字节、前100行和24列，截断直接标明。研究产物不会被当作已核验医疗结论。[截图与协议](结构化展示协议与组件扩展.md#v0110-执行产物的图像与表格)。

0.10.6 将未接受的参数提议与实际检查分开处理：参数错误保留详情，改正后的实际检查可正常完成。长检查支持本轮原时限内的持续等待，默认60秒、参数上限30分钟；每次作业等待最多600秒后继续读取同一作业。停止入口与原任务截止时间继续生效。明确监控的依赖或缓存文件会在扩大范围后保留。

0.10.5 将检查与文件版本关联：受检文件变化显示“需复验”，摘要不可用显示“版本未核对”；原命令同范围复验后解除。工具可显式指定代码、测试和配置范围，范围外的报告不会使其失效。离线恢复显示“历史 · 退出状态”，不自动证明当前文件已验证。

0.10.4 执行工作台增加检查记录：点击短标记可定位实际命令和输出；同一命令复验后显示最近状态，先前失败仍可回看。失败的必需检查会阻止本轮完成；预算与时间允许时最多自动纠错一次。只检查并报告的参考检查不会触发修改。开始请求即更新已用调用额度，包含等待响应的请求。

0.10.3 在普通模型等待期间保留“紧急求助”入口，可用独立弹窗提交选填描述；成功后立即显示原有求助说明，停止普通问诊。失败保留草稿；旧请求的迟到回复不能覆盖新状态。求助卡片突出操作说明，原因可展开；本功能不会替患者自动拨号。

使用 Electron 的独立系统窗口，带应用图标、原生窗口控制和中文应用菜单。界面继续由 HTML/CSS 渲染；这次完成的是独立桌面应用封装，没有重写为 Qt 原生控件。

默认患者视图提供问诊和记录；左侧切到研发视图后，可以打开图示库、运行检查、能力与模板和模型配置。自查任务集中展示，支持回看对话后返回原步骤。见 [能力插件与模板说明](能力插件与问诊模板.md)。应用只允许运行一个实例，重复启动会聚焦现有窗口。

## 3. 启动和关闭

桌面主进程自动启动 Python 服务，使用随机回环端口，避免与开发预览端口冲突；就绪后自动进入工作台。两者之间使用一次性访问凭证，凭证通过标准输入传入 Python，由桌面网络层附加到请求，不写入 URL、启动参数或患者页面。

无有效凭证的请求，包括主页、健康检查和病例 API，均返回 401。普通浏览器不能直接访问该桌面实例。这个机制用于实例隔离，不构成生产身份认证，也不能阻止具有同一用户权限的恶意进程。

关闭最后一个窗口会退出应用并关闭其 Python 服务；父进程异常退出时，Python 检测标准输入关闭并退出。工作台关闭时会中止正在执行的 DSH 调用，清理其独立进程组，也覆盖配置连接测试中的临时 DSH 实例。

桌面渲染进程启用 sandbox 和 contextIsolation，关闭 Node integration，禁止页面开新窗口、跳向外部页面及申请设备权限。设置依据：[Electron 安全文档](https://www.electronjs.org/docs/latest/tutorial/security/)、[进程沙箱说明](https://www.electronjs.org/docs/latest/tutorial/sandbox)。当前没有摄像头功能；未来接入时需另行设计任务授权。

## 4. 依赖与数据

当前桌面包包含 Electron、页面、Python 项目代码与 DSH 生产依赖，**尚未捆绑 Python 解释器**。离线演示和直接模型模式需要系统 Python 3.10+；DSH 另需系统 Node 22.19+。可设置 `MEDAGENT_PYTHON` 为 Python 可执行文件的绝对路径。

当前电脑已具备这些运行条件。桌面启动脚本会将已有 Volta 目录加入 PATH，便于图形桌面找到 Node。其他平台尚未制作或验证安装包，当前交付为 Linux x64 应用目录和本机启动图标。

应用默认离线演示，可在“模型与运行配置”中设置服务。病例和密钥保存在服务进程内，关闭后丢失。配置外部模型后，会谈信息会发送到所选服务。桌面应用不自动加载 `.env` 或保存密钥到文件。

Electron 的普通运行资料位于系统应用配置目录下的 `chengxin-medagent-0.11.17`，也可由启动环境指定独立资料目录。问诊窗口使用非持久化 session；该目录不是病例数据库。主动导出记录会生成含健康信息的文件。问诊后端的 DSH 决策临时目录正常调用后回收；执行工作台的独立文件、任务记录与运行资料则保留在桌面“澄心工作区”，配置密钥不写入索引。当前应使用合成病例。

当前仍是研究原型，图示、风险规则和模型问诊质量尚未完成临床验证。

## 5. 从源码复现

```bash
npm ci --ignore-scripts
npm run desktop:setup
npm start
```

`desktop:setup` 单独下载固定版本 Electron 二进制。保持 `--ignore-scripts`，不依赖安装时隐式执行所有依赖脚本。

生成 Linux x64 应用目录及当前工作区桌面图标：

```bash
npm run desktop:build
npm run desktop:shortcut
```

打包仅复制运行所需内容，排除 `.env`、开发会话、源码检查用 vendor、截图、测试及开发依赖。不修改上游 DSH 源码。修改业务代码后，需要重新打包才能让桌面启动器使用新代码；也可以用 `npm start` 检查未打包代码。

## 6. 验证

在有图形会话的终端运行：

```bash
npm run test:desktop

# 验证实际打包产物
MEDAGENT_DESKTOP_BINARY="$PWD/dist/desktop/Chengxin-0.11.17-linux-x64/Chengxin" npm run test:desktop

# 既有界面与后端回归
npm run test:ui
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

`tests/desktop/app.spec.mjs` 真实启动 Electron，检查窗口与隔离设置、无凭证访问拒绝、问诊写入、配置测试、图示预览和关闭后的端口回收。它不依赖已运行的网页预览服务，也不调用外部模型。

`tests/test_desktop_lifecycle.py` 另外启动真实的阻塞模型进程及其子进程，检查工作台使用的后端关闭方法能中断调用并结束整个进程组。

当前环境的图形会话为 `DISPLAY=:1`、`XAUTHORITY=/run/user/1000/gdm/Xauthority`，自动化验证时显式传入。正常从桌面图标启动会继承系统会话，无需用户填写这两项。

## 7. v0.9 执行工作台与生产依赖

研发视图新增“执行工作台”。提交任务才调用真实模型；可以直接观察工具、子智能体和实际文件，选择文件查看文本代码。停止按钮同时覆盖前台命令与仍在运行的后台工作；正常取消保留同一会话。每轮调用预算由主任务与子任务共享，具体边界见 [执行底座设计](通用执行底座与能力评测设计.md)。

构建在临时目录执行锁定的 `npm ci --omit=dev --ignore-scripts`，然后不再让打包器裁剪依赖。实际测试发现其自动裁剪会漏掉官方 DSH 的传递 peer 依赖，造成源码可运行而打包版无法启动。当前打包检查必须真正启动完整 DSH、创建文件、运行子智能体和取消接续，不能仅检查离线窗口。

0.9.2 的工作目录被移走或替换时会显示“工作目录不可用”，禁用新执行，文件数量显示未知；恢复原目录后可继续操作。目录身份校验不会自动接受替换后的同名文件夹。已有运行仍可停止。切换新工作区时清空旧预览，并忽略旧请求的延迟错误。这里的“恢复原目录”是当前进程内文件位置恢复，不等于已经支持跨应用重启恢复会话。

0.9.3 新建的执行工作区可以跨应用重启恢复。在选择器中打开已保存工作区，无密钥时查看任务和文件；匹配原服务并填写当前密钥后继续原 DSH 会话。“×”关闭并释放占用但保留资料，另一个窗口不能同时接管。旧版本无宿主索引的目录不会自动迁移。详见 [恢复范围与存储](执行工作区恢复与存储.md)。

## 8. 文件变更审阅

完成一轮执行后，点击文件栏上方“查看本轮变更”。左侧选择新增、修改或删除文件，右侧查看原始内容与当前内容的差异；哈希与权限信息按需展开。查看和刷新不请求模型，无凭据打开历史也可审阅。执行中刷新是当前观察，并非任务结束的原子快照。旧任务没有基线时明确提示不可用。

输入框旁可选择 3、10 或 30 分钟，仅影响下一轮。命令单次前台等待仍最多 30 秒，之后读取原后台任务；每轮时限包含子任务，主回复结束后后台仍在运行也继续计时。文件扫描、恢复边界与验收见 [执行底座设计](通用执行底座与能力评测设计.md#12-v099-文件变更与长任务预算)。

## 9. 打开已有项目

“研发视图 → 执行工作台 → 打开本地项目”使用系统文件夹选择器。选择后显示实际路径及“文件直接保存到原目录”。提交任务才会调用模型和执行工具；取消选择不改变当前工作区。相同路径重新选择会复用可读的已保存会话，关闭工作区保留项目文件。

执行资料仍位于桌面“澄心工作区”的 `.state` 与 `.index`，不会在所选项目中添加这两个目录。保护路径、跨重启恢复、外部链接和直接编辑范围见 [本地项目目录与原位执行](本地项目目录与原位执行.md)。

## 10. 执行中的问题卡

需要必要输入或遇到需求冲突时，主任务／子任务可调用澄清工具。卡片直接显示问题、可点击选项及自由输入；原因和历史回答按需展开。回答后继续原任务，等待期间仍消耗原执行时限。停止或到期后旧卡不能再提交；应用重启只展示历史，不自动续挂旧请求。回答内容不写入患者问诊。详见 [澄清设计与验收](执行澄清与用户回答.md)。
