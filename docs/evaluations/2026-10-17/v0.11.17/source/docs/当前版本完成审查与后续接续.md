## 通用执行与医疗问诊如何接续

当前两条路径各自可运行：患者问诊调用已注册医疗能力；研发执行工作台操作文件、代码、公开网页和子任务。问诊不会自动把患者信息发送给通用执行工作区，也不会自动导入其文件结果。用户已明确当前可以暂不整合，本轮保留这一阶段安排。

未来接通时，沿用既有注册能力及执行回执协议，先实现一个完整案例，再扩展能力数量：

1. 问诊协调器生成明确任务，固定病例事实版本、需要的输入、允许的数据范围、能力版本、额度及原问题的接续位置。
2. 执行器返回结构化成功、缺参、失败或取消状态；结果附来源、单位、实现版本及真实执行标识。缺参回到患者补问，失败观察错误后在同一额度内修正。
3. 协调器检查病例是否已更正或换人、任务是否过期；旧结果只能作为历史，不能覆盖新状态。任意脚本产物保持研究属性，不能冒充注册计算回执。
4. 渲染器展示必要结果、可展开依据及患者核对动作，随后恢复原问诊。临床解释和行动条件单独验证。

这四步是后续接入验收条件，尚未实现自动跨路径调用。子智能体用于独立的检索、图像处理或计算复核，简单补问继续由主流程处理。具体底座与现有边界见[通用执行设计](通用执行底座与能力评测设计.md)、[注册计算回执](注册计算工具与执行回执.md)。

## 同机隔离环境的交付补验

新增可重复运行的`verify_clean_desktop.py`与`clean-desktop-probe.mjs`。它们不读取`.env`，不改交付包、不新增真实API请求；输出目录必须全新，以保留失败和历史。探针通过原生Electron实际界面完成演示问诊、测温图示、无效读数拒绝与摘要确认，同时检查患者来源、未知状态和服务关闭。

```bash
DISPLAY=:1 XAUTHORITY=/run/user/1000/gdm/Xauthority \
  python3 -B scripts/verify_clean_desktop.py \
  --package dist/desktop/Chengxin-0.11.16-linux-x64 \
  --output-directory .runtime/clean-desktop-fresh
```

显示和授权文件位置须符合实际图形会话。工具需要Linux bubblewrap与已安装的Playwright依赖；缺少条件时明确失败，不退回读取开发目录。隔离环境仅挂载只读交付包、系统库、Node与三个自动化依赖，以及临时输出和图形显示通道。空用户目录在退出时销毁；外网关闭，仅有loopback接口。最终14项断言通过，原始结果和适用边界见[交付补验](evaluations/2026-10-17/v0.11.16-clean-environment/README.md)。

Playwright启动参数包含自动化用的`--no-sandbox`；页面的sandbox／contextIsolation配置已核对，但这次运行不构成Chromium进程沙箱有效性验证。该补验也没有覆盖另一台机器、其他系统库、缺少系统Python／Node、DSH联网或临床效果。

## 0.11.17 字体与图示交付

独立Debian系统文件环境发现了页面中文缺字，以及页面字体恢复后SVG图内仍缺字的实际问题；随后补齐了公式和原始记录的等宽字体回退。0.11.17随包提供正文、标题及代码文本的中文字体，并将图示标签生成矢量轮廓，保留原文字、可编辑源图及无障碍说明。该补验继续使用同一宿主内核和X11服务，未验证另一台物理机器。来源、许可证、生成与逐项验收见[本地字体与跨系统验证](本地字体与跨系统界面验证.md)。原0.11.16流程和同机用户环境归档保持原样。
