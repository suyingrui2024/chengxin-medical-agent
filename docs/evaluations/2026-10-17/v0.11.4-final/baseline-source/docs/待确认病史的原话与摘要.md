# 待确认病史的原话与摘要

0.11.2 解决问诊摘要遗漏患者已提供内容的问题。合成输入“昨晚用过药物甲，用量不清楚”在演示解析器中被记录为 `unknown/null`；原话原本仍在事实证据与对话中，但摘要仅显示“用药未知”。真实模型另会只引用“是否药物过敏不确定”，省略同轮中的“以前有过皮疹”。

## 展示与交互

摘要的“仍待确认”区域展示当前事实的实际引文、来源与未确认状态，提供“补充／更正”。编辑器带入当前引文；保存后显示新记录，旧事实仍在历史中。测量跳过仍显示“未执行／已跳过”，不变成正常结果。结束会谈或回看旧摘要时不提供可执行的补充入口。

超过160字符的引文折叠，可展开完整内容；短引文直接展示。新增补充按钮高度至少44像素，窄窗口逐项排列，原话通过文本节点渲染。

如果模型引文只覆盖原话的一部分，另提供“查看同轮原话”。这段上下文来自宿主事件中的实际患者输入，并注明“包含本轮其他信息，尚未全部归入此字段”。它不是模型补写的字段值，也不表示整段内容都属于此字段。

## 数据协议

`medical-ui/v1` 的摘要增加可选 `unknown_details`，原有 `unknown` 标签数组继续保留。旧事件没有新增字段时仍能显示。

```json
{
  "unknown": ["过敏信息"],
  "unknown_details": [{
    "key": "allergies",
    "label": "过敏信息",
    "evidence": "是否药物过敏不确定",
    "source": "patient",
    "quality": "not_assessed",
    "context": {
      "scope": "source_turn",
      "turn_id": "实际原话所属回合的ID",
      "text": "以前有过皮疹，是否药物过敏不确定"
    }
  }]
}
```

宿主仅从本会谈、当前事实 `turn_id` 对应的用户输入或更正事件查找上下文。引文必须实际包含在该原话中；相同内容不重复附加上下文。来源仅允许患者／照护者，不从其他会谈、旧事实、模型输出、程序产物或缺失的回合推造。找不到对应输入时只显示已有证据。渲染器核对引文、上下文范围、来源与质量类型，异常块回退为受控提示。

原有 `Fact.value`、`assertion`、计算输入、风险判断及模型工具提议协议不因展示而改变。未知字段仍不能作为已知计算参数。此版没有把自然语言拆成已验证的药名、剂量、时间和过敏类型；演示解析与模型规范化仍可能采用不同的字段级断言，不能据此推断细项已经确认。

## 验证与边界

完整演示问诊验证原话进入摘要、照护者来源、跳过质量、连续更正、历史关联及缺失原回合时不使用其他会谈。浏览器验证实际交互、390像素窄窗口、原话带入编辑、结束后只读、长引文展开、旧协议兼容和HTML保持文本。原生桌面使用同一真实服务流程。

两轮真实DSH医疗决策共13次DeepSeek请求。首轮6次中，家属场景实际到达摘要，但过敏短引文遗漏皮疹上下文；本人场景停在急症筛查问题。第二轮允许回答实际提出的筛查问题，7次请求中两场景均实际到达摘要，相关原话可见或可展开。评分接纳明确标注的同轮上下文，因此两轮结果不构成模型准确率提升对照。

首轮家属场景的3个原始决策在最终控制器中离线重放：引文仍是“是否药物过敏不确定”，`unknown/null`保持，宿主同轮原话能找回“皮疹”。这证明了程序的上下文保留行为，不计作新增真实模型成功。

首轮保留运行源码哈希与完整合成事件；第二轮另保存逐文件匹配的源码字节快照。后续界面检查不增加模型调用。完整日志、截图、最终桌面包核对与验证范围见[0.11.2归档](evaluations/2026-10-17/v0.11.2/README.md)。本版没有新增临床公式、诊断或治疗能力，也没有证明目标用户的理解效果和临床有效性。
