# 就诊对象与会谈草稿隔离

实现版本：0.11.9。修复两个独立问题：父亲和母亲都属于`other_adult`，旧版可能在同一病例中替换年龄和主诉；输入框中的未发送文字也可能在切换会谈后沿用，造成误发。

## 对象边界

保留`consult_for`原有枚举，另从实际报告称谓投影`consultation_subject`。它保存当前会谈的称谓、相应引文及来源轮次，范围明确为`reported_relationship_only`。不采集真实姓名、不核验身份，也不从儿子／女儿等称谓推断年龄、成年与否或检验性别。

父亲／爸爸等已登记别名可归为同一称谓；兼容的补充保留较具体约束，笼统的“其他家人”不会擦掉已有“父亲”。明显不兼容的称谓不能因共享同一枚举而合并。大宝和二宝等已支持表达亦区分；称谓不是全局唯一的人物ID，同称谓的不同人仍需要用户明确新开问诊。

明确换人或单一称谓与当前对象冲突时，先显示对象卡，不调用模型、不写新人的事实。否定、假设、相关背景问题和明确家族史按有限规则处理；不宣称完整自然语言意图识别。模型另可通过`change_subject`引用本轮对象原话提出同一入口。角色事实提议仍在整批写入前验证，即使使用相同枚举也不能把母亲信息覆盖进父亲病例。

“她本人／母亲本人”等有限第三人称反身表达不会另认成报告者本人；“母亲和本人”仍作为多人处理。普通亲属背景可以继续在原问诊中描述；称谓相对报告者，不能自动把报告者母亲等同于当前患者的母亲或把别人的疾病当作患者本人疾病。多人、否定范围、复杂亲属链及未标注的人物仍需模型澄清与患者核对。这些语义边界需要进一步临床与目标用户评审。

## 两个图形化选择

对象卡用现有本地图标显示“本次：父亲 → 另一位：母亲”，提供“为母亲新建问诊”和“继续父亲问诊”。后者不调用模型：没有新增事实、测量或计算结果时，恢复原问题、图示、摘要或待核对计算；若显示对象卡前已接收有效的新结果，则从最新状态规划，不回滚事实、不复活已失效任务。失败补充的原话和重试状态也保留，不会因显示对象卡被误标成已处理。反复提出不同对象时仍保留最初可恢复动作。

新建使用独立会谈ID，旧事实不复制。界面显示“核对母亲的原话”，把刚才描述放入输入框，允许修改后发送；创建与预填本身不调用模型、不写临床事实。草稿视图不会再次显示开场的对象选项，避免覆盖已带入的原话。明确求助仍优先于对象选择，不等待模型确认。

对象称谓显示在问诊标题区、当前记录、摘要与会谈列表；标题同时保留本会谈创建时绑定的实际模型模式，后续修改全局设置不改变旧会谈标签；原始`consult_for`枚举不变。列表按会谈ID选择，不用相同症状标题区分病例。操作绑定会谈与动作版本，旧入口拒绝执行。

## 页面草稿

未发送文字按会谈ID分别存放在当前页面的内存Map中。新会谈不沿用旧输入，返回旧会谈可恢复各自草稿。选择固定答案时，只提交该答案；另写在输入框的文字既不自动发送，也不被成功响应清掉。

待发送对象说明和草稿只在当前页面内存中，不写localStorage、不自动上传、不保证刷新页面、关闭窗口或服务重启后恢复。已提交的患者会谈仍采用原有服务进程内存生命周期；本轮没有新增持久病例数据库。未发送的换人原话也保留在原会谈的对象卡事件中，直到服务关闭，但不会冒充新会谈已提交的病史。
