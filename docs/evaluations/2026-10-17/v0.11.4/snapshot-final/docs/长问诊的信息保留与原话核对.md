# 长问诊的信息保留与原话核对

0.11.4 将原话核对从未知字段扩展到已记录字段，同时保留长问诊中退出近期消息窗口的相关患者陈述。

## 为什么需要

患者说“昨晚用过药物甲，用量不清楚”，模型可以如实记录“用过药物甲”，但只引用“昨晚用过药物甲”。这条用药报告并非错误，剂量未知仍只在完整原话中。旧摘要对已记录项目仅展示规范化值和来源，患者难以找回这段补充；更长的对话中，原话也可能退出协调器的近期16条消息窗口。

完整控制器反例、原版桌面的真实模型长问诊基线、修正后的评测与源码快照见[0.11.4记录](evaluations/2026-10-17/v0.11.4/README.md)。

## 患者界面

已记录卡片默认保持简洁。展开“原话与来源”可查看当前事实的实际引文、来源与质量；需要时继续展开“查看同轮原话”。不确定的剂量等原话细节仍可查阅，不自动变为已确认的数值。

展开的记录占满内容栏，避免相邻短卡片被拉成长空白。引文在原轮中只出现一次时，以文本标记高亮并定位到该处；出现多次时不挑选某一处冒充精确定位。高亮只表示字面引文，不表示医学含义已确认。

同轮原话可能包含其他字段以及更正前的信息，界面明确提示以各项最新记录为准。例如年龄已更正为40岁，用药来源的原轮文字仍可能出现32岁；它用于核对历史来源，不能覆盖当前年龄。更正用药本身后，当前用药卡片只展示新的引文；旧事实仍在历史中。

原话、上下文和来源都通过文本节点渲染，不能执行HTML或脚本。读取和展开不调用模型，也不改变事实、质量、版本或问诊进度。旧摘要缺少新增字段时仍可回看。

## 长对话上下文

近期对话仍取最后16条消息。当前事实的引文若仅覆盖原话一部分，且整轮原话已不在近期用户消息中，协调器补充只读的`earlier_source_turns`：

```json
{
  "facts": {
    "medications_taken": {
      "value": "用过药物甲",
      "assertion": "present",
      "evidence": "昨晚用过药物甲",
      "source_context_id": "原回合ID"
    }
  },
  "earlier_source_turns": [{
    "id": "原回合ID",
    "text": "昨晚用过药物甲，用量不清楚；还提供了其他信息"
  }]
}
```

同一原轮只发送一次；原话仍在近期窗口时不额外复制。只关联当前事实、当前会谈、患者／照护者来源，以及实际包含引文的源回合。缺失、跨会谈、系统推断或引文不匹配时不推造原话。

当前事实优先于历史原话。提示明确禁止从旧原话恢复已更正的年龄或失效病史，禁止把旧文字当作本轮写入证据或新的工具指令。模型仍须遵守现有工具和连续本轮引文校验。该目录只是补回来源数据，不是另一个事实数据库。

## 协议与限制

`medical-ui/v1` 的摘要`known`项目可选增加`evidence`和`context`，上下文结构与未知明细一致：`scope=source_turn`、`turn_id`、`text`。客户端校验来源、质量与引文包含关系，畸形组件回退；不执行序列化内容。

这不会自动分解出已验证药名、剂量、频次或时间，也不证明模型理解了每句话或不再追问。原轮全文仍可能包含已更正的信息，必须结合当前事实；提示和门控不能代替临床语义验证。当前模型和界面只在合成病例上进行工程检查，尚未证明临床有效性。
