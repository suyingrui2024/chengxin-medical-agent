# 测量反馈与同轮补充 · v0.11.6

患者在测量时仍可能补充病史。旧版重复测量的零模型接续会接收体温后直接返回原问题，漏掉同一句中的“更正：昨晚用过药、用量不清楚”；邻近小句中的“读数可能不准”也未限定数字。这是实际零外部调用反例，不是模型临床错误率。

## 输入与执行

一个明确标注的摄氏体温可从另一小句的用药次数中分离，例如“腋温37.6℃；昨晚用药物甲2次”。注册解释器仍核对单个数值、范围与单位；多个温度、同一小句中的冲突数字、华氏或无关年龄不由模型择一猜测。该范围是原型录入范围，不是正常体温范围。

测量小句及相邻的测量限定小句共同决定是否确认。“读数可能不准”“这个读数我不确定”保留为unknown/inadequate；“过敏不知道”仍是其他字段信息，不能使清楚的读数变成未知。有限规则不等于通用医学语言理解，同一未分隔小句的复杂表达仍可能需要重新填写。

| 输入 | 后续处理 |
| --- | --- |
| 纯读数／仅测量限定 | 完成或保留未知，恢复原交互；重复测量不额外调用模型 |
| 有读数及病史补充 | 测量由控制器处理，完整原话进入协调器，继续记录／澄清 |
| 请求再测及病史补充，尚无可核对读数 | 先处理补充；repeat=true待办保留请求，随后展示注册任务 |
| 补充处理失败 | 展示当前错误、原话和重试；已接受的读数保持同一个Fact |
| 紧急／需要升级 | 原有风险门优先，不能为补充处理等待模型 |

原始患者轮次和连续引文保留。候选核对后处理同轮补充，仍引用最初报告轮次；确认按钮不是用药证据。已完成测量通过completed_observation_with_supplement提供给模型，该轮再次提议相同测量被拒绝，重试也不会重新测量。

## 病例和交互

补充处理可更新病史并改变下一问题，不强行恢复已经不适合的旧问题。若正有挂起的换算卡，补充病史会取消该卡，避免下一次回答被旧表单截获；已完成的计算记录不会被伪造或重复执行。

observation_feedback为宿主私有待处理状态，仅本次会谈有效。接口失败保留原输入供已有重试动作接续；主动发送另一条新消息沿用原服务的输入替换行为，先前失败的补充仍在消息／事件中，但不会自动声明其已结构化。此版本没有跨消息的任意来源写入权限或跨重启病例恢复。

## 视觉表达

观察卡提供折叠的“补充原话”。失败显示“待重试”，真实协调器接收后显示“已带入本轮问诊”，演示或优先求助未处理时显示“尚未结构化”。带入不代表所有信息均正确解释，仍需核对摘要与原话。当前问题的紧凑卡把补充放进“记录与补充”，不另外占用回答区高度。

摘要阶段的补充失败不能继续突出旧摘要、遮住新错误卡；有新摘要时才启用摘要聚焦。未知／畸形补充状态回退，原话用textContent显示，不执行HTML。

## 验证

回归包含首次／重复读数、另一数字的用药补充、限定范围、原始轮次、候选核对、接口失败后原输入重试、阻止重复已消费任务、挂起表单及优先求助。真实模型检查与本机确定响应检查分开统计；工程通过不代表临床有效性。
