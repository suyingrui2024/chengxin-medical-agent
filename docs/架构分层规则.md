# 架构分层规则

> 状态：已生效（CI 强制）
> 权威实现：`scripts/lint/import_rules.py`（规则细节以脚本 docstring 为准）
> 规模约束：`scripts/lint/module_size.py`（单文件 ≤ 1200 行）

---

## 1. 三层结构

分层不由目录嵌套表达，而是由门禁显式声明：

| 层 | 成员 | 职责 |
|---|---|---|
| **capability** | `extensions/`、`kg/` | 公式/量表/血糖引擎、知识图谱。被广泛复用，必须对业务无知 |
| **feature** | `consultation/`、`conclusion/`、`agent/`、`execution/`、`patient_records/`、`subagents/` | 六条临床工作流 |
| **app** | `server/` | HTTP 表面，压在所有层之上 |

**依赖只能向下。** 能力层不认识功能层；功能包之间互不认识；只有进程入口（`cli`、`desktop_service`）可以 import `server`。

## 2. 为什么这样切

能力层若依赖功能层，就无法脱离某条工作流复用或测试。两个功能包若互相 import，就无法独立修改——改 A 必须回归 B。

这正是 `module_size.py` 管不到的那类腐化：文件可以很小，同时把依赖伸到毫不相干的包里。

## 3. 五条规则

| 规则 | 内容 | 当前状态 |
|---|---|---|
| R1 | 能力包不得依赖功能包 | 0 违规 |
| R2 | 功能包之间不得互相依赖 | 6 处冻结（见 §4） |
| R3 | 仅入口可依赖 `server` | 0 违规 |
| R4 | 禁止循环依赖 | 5 个环冻结（见 §4） |
| R5 | 顶层扁平模块数不得增长 | 65，只许减 |

## 4. 已知债务（冻结而非豁免）

**R2 硬耦合 6 处**——模块级导入，不是延迟绑定：

- `agent._preamble → consultation`：执行层驱动 `ConsultationEngine`
- `subagents.* → conclusion`（5 处）：共享 `BANNED_PHRASES`、`GAP_IMPACTS`、`MEASUREMENT_FACTS` 三张事实表

解除方式是把共享部分抬进能力包，不是放宽规则。

**R4 循环依赖 5 个**：`conclusion` 内部 5 模块、`execution` 内部 4 模块、`consultation_subject ↔ domain`、`extensions.formulas ↔ formulas_extra`，以及一个跨 8 模块的大环。

**另有 3 处函数内延迟导入**（`agent.run`、`consultation.closing_flow`、`consultation.emergency`），是刻意破环的写法，只告警不失败。

## 5. 违规了怎么办

```bash
npm run lint:structure     # 本地跑两个门禁
```

- **模块级跨包导入**：把共享部分移到能力包，或反转依赖方向（调用方传值进来）
- **循环依赖**：反转一条边——把值作为参数传入，或在函数内导入
- **不要**往 `EDGE_BASELINE` / `CYCLE_BASELINE` 加新条目。基线是还债清单，不是许可清单。

环被打破后门禁会提示收紧基线（`R4 baselined cycle is gone / shrank`），照着删即可。
