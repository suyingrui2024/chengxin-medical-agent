# DSH 后台复核与报告分析设计

## 已实现：受限影子复核

DSH 后台复核只在一次前台回复提交后、该回合实际改变病例时运行。触发事件为事实记录或失效、事实恢复、图示自查完成、能力结果完成和摘要就绪。普通追问或没有新增病例信息的回复不再次调用后台模型。

每次任务只接收当前病例版本的结构化快照：已确认事实及其原话证据、当前问题、近期已问问题、风险等级和最近一次已提交文字。它不会接收正在输入的草稿，不调用工具，不写入事实，也不改写急症分流。新消息、事实更正或恢复会取消前一任务；版本不一致的结果会丢弃。

默认 `MEDAGENT_DSH_REVIEW_MODE=shadow`。该模式保留受限建议供开发评估，并公开状态、模式、耗时和发现数量；建议内容不进入患者界面，也不进入下一轮模型上下文。`advisory` 是显式的实验模式：只有与当前病例版本一致的建议才可作为下一轮内部追问参考，不能自动记录事实、给出诊断、覆盖分流，或直接发送给患者。

控制器最多同时运行两个任务，每项八秒截止。容量不足、超时、模型异常和过期结果都以事件记录并安全降级，不阻塞前台问诊。进入 `advisory` 前至少需要通过下面的门槛：

- 使用冻结的合成病例集比较影子结果与临床审核的追问缺口，分别报告遗漏、无依据建议和急症冲突；
- 验证版本失效、取消、容量不足、超时和 DSH 不可用时，患者可见回复保持一致；
- 由临床审核者确认每类建议的用语、证据要求和不可回答范围；
- 在试运行中审查复核延迟、触发率、有效建议率和错误建议率，不能只用调用次数或满意度决定上线。

## P0 已实现：本地报告核对与就诊交接

患者可以在本地界面粘贴文本或 CSV 报告。解析器仅提取项目名、报告数值、单位、参考范围和原文摘录；草稿不写入病例，也不会进入交接摘要。每个项目必须由患者单独确认，才以“患者确认的报告内容”加入当前会谈；确认后的项目可随时移除。审计事件只保存草稿标识、格式、项目数量和项目标识，不保存报告原文或数值。

确认后的报告项目会以受限的结构化字段提供给下一轮医疗控制器和 DSH 后台复核；二者均不得将其当作设备直连、独立临床复核或治疗依据。就诊交接摘要另提供可复制的患者核对版，只汇总已记录事实、已确认报告项目、待补充项和风险状态；用药、过敏和病史保持患者／照护者提供的来源信息，不生成诊断、处方或剂量判断。

## P0 已实现：本人健康档案与问诊衔接

系统只维护一个“我的健康档案”，不创建或切换家属档案。图片识别、患者修正和自测数据都按实际测量时间进入这一本人时间线。只有患者亲自录入、确认或修正的数据可以由患者主动带入一次已明确为“本人”的问诊；孩子或其他家人的问诊不能读取或带入该档案。

带入的数据保留档案标题、测量时间、观察项和修订版本，并以受限结构提供给医疗控制器、就诊交接和 DSH 后台复核。未确认的模型识别不会成为问诊事实。患者更新档案后需要主动更新本次问诊中的引用；删除原档案会同时移除仍在运行的问诊引用。

粘贴文本或 CSV 的报告草稿流程本身不读取图片、扫描件或 PDF，也不以参考范围推断异常。医疗图片由独立的本人健康档案识别流程处理。以下是后续可选的报告分析顾问边界。

报告分析不应复用普通问诊的后台快照，也不能把上传的原始文件直接当作病例事实。第一版应作为一次明确发起、可撤销的“报告解读草稿”流程：

1. 用户选择一份报告并确认要分析的范围；系统只处理本次选择的文件或粘贴内容。
2. 本地解析层提取可审查的候选项目：项目名、数值、单位、报告给出的参考范围、标本/报告日期和解析位置。解析失败或字段缺失必须保留为缺口。
3. DSH 仅接收这份结构化候选表、当前病例中已确认的相关背景，以及明确标记的缺失项。提示词只允许返回“需核对项目”“可能相关的既有事实”“建议向医生或报告方确认的问题”。
4. 界面以逐项草稿展示原始文本、解析值、模型说明和不确定性。用户逐项确认后，控制器才可把其内容作为“患者提供的报告内容”写入病例；拒绝或未确认的项目不得进入事实。
5. 导出时区分原始报告、解析草稿、用户确认记录和模型建议，并允许用户删除本次分析材料。

第一版的输出合同应是固定 JSON，而不是自然语言病历：

```json
{
  "findings": [
    {
      "source_item_id": "stable-parser-id",
      "reported_value": "4.2 mmol/L",
      "reference_range": "3.9–6.1 mmol/L",
      "status": "needs_confirmation",
      "evidence": "报告原文摘录",
      "question": "是否为空腹采样？"
    }
  ],
  "missing_context": ["报告日期"],
  "limitations": ["不能据此确诊或调整治疗"]
}
```

宿主必须校验 `source_item_id` 属于本次解析结果、数值和范围逐字可追溯、问题不含诊断或治疗指令；无出处项一律拒绝。参考范围只按报告原文展示，不能由模型补造。高风险或紧急文本仍交给现有急症规则处理，报告顾问不改变该优先级。

## 实施顺序与验收

1. 为文本、CSV 和结构化导出报告实现本地解析器和无原始内容的审计摘要；扫描件/PDF 在具有可靠文字层和人工核对流程前不自动提取数值。
2. 新建独立的报告草稿状态、确认 API 和版本事件，避免与普通事实写入混用。
3. 用脱敏或合成报告做解析、引用绑定、拒绝无出处项目、删除材料和版本失效的端到端测试。
4. 在影子模式下评估 DSH 草稿；通过临床审核、数据留存审查和错误场景测试后，才考虑面向用户显示草稿。

以上“报告分析顾问”尚未接入。当前可用的是本地解析、逐项确认、受限上下文和就诊交接，不包含模型解读。

## 本地工具

`scripts/evaluate_background_review.py` 接收经独立审核的 JSON 病例：每项须包含 `expected`、`observed` 两个 `inspect_case` 信封和 `safety_passed`。它只计算精确率、召回率和安全通过率，不调用模型，也不会把演示样本当作临床证据。

```bash
PYTHONPATH=src python3 scripts/evaluate_background_review.py \
  --input path/to/reviewer-labelled-cases.json \
  --output /tmp/shadow-review-report.json
```

`medagent.report_drafts.parse_report_draft` 目前支持粘贴的文本行和 CSV，保留每项原文摘录、数值、单位和报告中给出的参考范围。它不会判断异常、不会生成诊断或治疗建议，也不会直接写入病例。扫描件、图片和 PDF 仍需要文字层与逐项人工核对后才能接入。
