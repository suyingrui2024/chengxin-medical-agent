## 2. 阶段二：消融清单（只出清单，不删代码）

判定标准（设计 §2.3，三条缺一不可）：消费点为零 + 消融无损 +
样本充分。离线静态分析的结论是：**没有任何一段提示词或一个输出
字段通过全部三条标准，因此删除清单为空**——这是证据结论，不是遗漏。

### 2.1 经核实“不是死重量”的项（不得凭感觉删）

- 前缀全部章节均被提示词正文或执行代码引用：fact_schema、
  question_catalog、self_check_catalog、available_capabilities、
  adaptive_question_risk_tags 均在 `agent_prompt.txt` 或执行校验中
  有对应消费点。
- 三个自检上下文列表语义不同，不可合并：available（当前可执行）、
  requestable（患者明确请求时可登记）、repeatable（已有读数且可再测），
  提示词第 31–33 行分别定义了各自的工具入口。
- 输出信封已是最小结构：`parse_decision` 强制恰好
  `{tool, arguments}` 两键；`validate_command` 拒绝任何未注册参数，
  每个注册参数或为必填、或为显式可选——信封内不存在“无人读取的
  字段”这一类死重量。
- question_catalog 与 fact_schema 看似重复实则互补：前者给问题
  的 prompt 与 applies_when，后者给事实的值契约；ask_question 的
  候选 ID 依赖前者，record_facts 的值校验依赖后者。

### 2.2 仅可进入“线上消融候选”的项（未证明，不进删除清单）

- 前缀 `content_versions`（极小，收益可忽略）。
- `adaptive_question_risk_tags` 的 cues 映射：提示词正文已逐字列出
  10 个风险标签名，cues 是否仍起作用需线上消融。
- 上下文 `observation_fields_read_only` 与 self_check_catalog 的
  result_key 集合重叠。
- 上下文 `calculation_drafts`（仅有计算草稿时出现，量小）。
- 上述任一项删除都必须先跑线上消融（删除后门禁零退化 + 样本充分），
  本阶段不预设结论。

## 3. 阶段三：实施优化（分批，每批独立过门禁）

### 3.1 A 批（前缀与上下文）：按通路裁剪被证据否决，未落地

deferred 的按通路裁剪要求“证明裁剪不改变候选问题集合”，证明失败：

- `ask_question` 的执行校验（`agent.py`）确实等于候选集
  （applies_in_state + fact_gates + 未记录），但 `ask_patient` 明确
  不走候选集——代码注释原话：主题合法性是“注册字段集，而非动态
  候选列表”，口语主诉可能从未候选过最关键的字段（live-eval
  case3/6 的实证模式）。把 question_catalog 裁剪到候选集会直接
  堵住 ask_patient 的这条合法路径。
- 前缀字节稳定性是故意的缓存属性（`_current_prefix` 注释：供应商
  KV 前缀复用所依赖）；按轮次变化的裁剪前缀会破坏该稳定性，
  节省的约 10% 前缀未必抵得上缓存损失，且无线上 cache 命中率
  数据可供权衡（见 §1.4）。

裁定：A 批回滚，不改前缀与上下文构造。未来若线上数据证明
ask_patient 的主题使用从不超出候选集，或 cache 命中率长期为零，
可重提本批；在此之前不做。

### 3.2 B 批（excerpts 与回喂）：无可安全改动，未落地

核实：子智能体视图只在首调用发送一次，内容摘录已截断在每条
1200 字符，多步增长是 chat 协议固有的（每步回喂 tool_result），
预算（步数/时间/token）与逐字校验管线已设上限。无代码改动。

### 3.3 D 批（视觉重试与缓存）：已落地

`src/medagent/medical_images.py`（`DeepSeekVisionRecognizer`）：

- 有界重试：仅对传输失败（URLError/TimeoutError）重试一次，
  退避默认 0.5 秒（可配 0–10 秒）；提供方错误（HTTPError）与非法
  合同仍立即失败，不重试。动机：单次网络抖动曾导致整次识别失败、
  用户必须重新提交；重试后失败仍为原错误语义。
- 遥测（仅观测，不改返回合同）：`last_usage`（provider usage 的
  prompt/completion/total/cache 整数字段）、`last_duration_ms`、
  `last_retried` 三个实例属性，供审计采集。
- 缓存未做：同一图片按 sha256 缓存识别结果虽有现成键，但会引入
  跨会话状态与失效语义，且识别调用频率低，收益不值得状态风险。

测试：`tests/test_vision_audit.py`（4 项：成功记 usage、网络失败
重试一次、持续失败恰好两次、提供方错误不重试）。
