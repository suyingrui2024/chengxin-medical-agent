本实验用于补充此前人工挑选的公开 DEV 开发任务。使用 SWE-bench Lite 官方 TEST 的 300 条记录，排序后以 `2026101601` 为固定种子洗牌，取前六题；选择文件在环境适配与模型运行前保存。所有选择保留，不以环境难度或运行结果换题。数据文件 SHA-256 为 `7a21f37b8bc179c7db5beeb14e88ac538ba283455c776e6b2535bbfb6e3551b4`，与官方数据文件一致，另核对读取后的 300 条 JSON 完整相等。

合计 8 个待修复、1102 个应保持通过的原始 ID。精确节点优先；只有上游省略参数或使用符号名时才解析对应的全部节点。不把近似前缀的另一个测试替换进来，不删除不通过、跳过或缺失的节点。预检必须证明所有指定原始缺陷失败、全部保持测试通过、参考修复全部通过，才允许开始真实模型调用。

依赖由固定 PyPI wheel 和官方发布文件提供，下载后核对 SHA-256，源码保持选定基础提交的原始 Python 文件。旧版 Sphinx 使用固定官方 standalone Python 3.9.20，Matplotlib 只借用固定 wheel 的编译扩展与生成版本常量；最后一题新增的 `_path` API 从其原始提交 C++ 源码在同一隔离环境编译，未用参考修复替换实现或弱化测试。环境各次失败和修订分别保存，之前失败不回写为成功。

执行使用同一固定 DSH SDK 0.2.0-rc.2、模型、任务文字、文件契约、依赖、网络条件和 8192 输出上限。每题两次重复，分别运行产品执行工作台与独立官方 SDK；`2026101602` 固定每对的先后顺序。每臂共享主任务、子任务、辅助搜索最多 20 次模型请求、600 秒，总计划最多 480 次，父目录硬上限 512 次。正式运行前冻结执行源码和任务配置；运行中修改这些文件会中止实验。

这里相同的是用户任务，双方系统提示和工具运行策略仍分别采用产品配置与独立 SDK 配置。产品增加结构化观察、澄清、变更工具、动态预算提示和短等待后后台移交；独立 SDK 不加载这些产品适配器。这是整体配置对照，不能把差异单独归因于某条提示、某个工具或模型本身。尤其长命令和 `job_output` 的等待策略不同，可能改变耗时与模型请求的消耗方式。

双方任务文字明确保护现有测试与配置；新回归测试仅允许 `regressions/test_*.py`。隐藏测试与参考补丁只位于宿主验收目录，不挂载给候选运行时。产品澄清工具的自动回答仅重复双方初始任务已有的信息，不增加参考答案。根回合结束即关闭对应运行时，不额外给予后台任务完成宽限；终端和子任务使用情况可由实际事件复核。

验收时停止候选运行时，从冻结原始源码重新构建，仅叠加候选实现和允许的新文件，恢复原测试、依赖与配置后应用隐藏测试。分别记录实现是否通过、文件契约是否满足、运行时是否正常完成和三者是否共同成立。修改测试不会让独立实现验收使用篡改后的测试；即使实现正确，违反契约仍独立计为失败。网络保持可用，禁止检索上游答案目前通过共同任务指令约束，不能声称网络硬拦截；需检查工具轨迹后解释结果。

原始字段 `source_and_contract_passed` 的契约门覆盖文件保护、允许的新文件位置、实现修改、请求上限和提供商响应；不自动证明模型确实执行了足够相关的测试、解释准确或满足全部行为要求。测试命令与工具轨迹需另外审阅。`runtime_completed` 表示 SDK 回合正常收尾，也不代表任务正确。保留这三个原始字段，不能在看到结果后更改原评分；附加行为审阅应独立列出。

文件清单实际忽略 `.git`、Python/pytest 自动缓存和 `.pyc/.pyo`，不是对所有生成字节的完整保护证明。任务文字未明确写出这些自动缓存例外，属于方法表述的局限；本轮保持原任务和检查器不变，后续任务契约应明确与实际比较范围一致。直接调用系统 Python 也不一定采用历史解释器或 `lib` 布局的项目源码，双方均有固定测试启动器可用；不能将环境使用差异单独归因于模型能力。

## 运行中发现的验收缺失

原候选清单拒绝全部符号链接。Matplotlib 的原有测试会在 `result_images` 生成指向固定基准图片的链接；第一次 Matplotlib 25311 产品运行留下 54 个这种链接。原报告因此只有 `source_readable=false`，没有运行独立实现验收，却仍将 `source_correct` 写为 false。这表示未评估，不能解释为实现错误。

原模型计划、源码、任务、测试节点与原始报告全部保留。另按 [补充规则](evaluations/2026-10-16/v0.10.2/supplemental-plan.json) 对两臂、两次重复的全部候选执行统一的零模型请求审计：对普通文件使用 `O_NOFOLLOW` 读取并校验，只保存链接文字，不读取宿主目标；恢复原测试、配置和依赖，叠加实现字节后，最后创建链接，交由同一隔离验收器解析。特殊文件或无法保持受保护输入的目录别名明确标为未评估。缺失、跳过或失败的测试仍不能通过。

补充审计独立记录“通过／失败／未评估”，不能静默覆盖原布尔值。补充代码在合成本地安全检查后、第一次补充候选验收前冻结，其哈希写入审计报告。已完成检查证实上述候选实现通过；从归档字节和链接元数据重建后也重现该结果。这是评测器漏验的纠正，不是产品代码在实验期间获得改进。完整计划结束后还需补齐全部候选的同一审计。
