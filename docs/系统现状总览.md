## 这个产品是什么

门诊式医疗问诊智能体（研究原型）：患者通过桌面应用与问诊引擎对话，
引擎按**假设驱动**的流程问诊、收集结构化事实、评估风险，最后产出
**结论单**（分诊建议 + 自护指导 + 患者教育）。全程本地落盘，
模型调用经过明确的数据出域闸门（见 [数据出域与隐私](数据出域与隐私.md)）。

三条硬边界，写进门禁而不是写在承诺里：

1. **不做临床决策**——结论单只分诊与自护，处置词与剂量被
   `guards/` 与 `subagents/coordinator/validate.py` 拦截；
2. **患者原话不进搜索**——所有出站查询过 `WebTools.search` 的
   内置脱敏闸门，病例原文片段命中即拒；
3. **数据不无声出域**——每条出站路径都有开关或闸门，事件日志只存
   元数据与内容哈希。

## 架构：四类职责，有检查的依赖边界

```
app          server                    HTTP 面与装配根
feature      consultation  conclusion  execution  patient_records  subagents
capability   extensions  kg  facts      可复用能力与事实表
kernel       core  guards  dialogue  clinical  reports  review  infra  shared_types
entry        cli  desktop_service      进程入口，不是新的职责层
```

- 功能包使用能力包与共享内核，应用层组装它们；能力包与内核之间按实际规则引用，不能产生模块级循环。
- 模块级依赖检查与运行时调用是两件事：问诊调用结论单、派生医疗子智能体的函数内依赖明确保留，不能把门禁通过表述为完全独立。
- 包数量、模块数量与规模会随开发变化，以 `scripts/lint/` 当前检查输出为准。Python 规模检查扣除 docstring 后计算，不能直接把物理行数当成违规指标。
