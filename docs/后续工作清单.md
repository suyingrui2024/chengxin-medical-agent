## 批次 1：测试夹具集中（12 处跨测试导入 → `tests/support/`）

**现状**（精确数字，2026-11-02 实测）：12 条不同的跨测试导入边，7 个测试文件被当作夹具使用：

```
被复用的夹具文件                          被导入次数
tests/records/test_patient_calculations.py     4
tests/consultation/test_self_check_conversation.py  2
tests/dialogue/test_repeated_observations.py   2
tests/consultation/test_consultation.py        2
tests/dialogue/test_location_answers.py        1
tests/kernel/test_calculation_supplements.py   1
```

**为什么是债**：`test_patient_calculations.py` 被四个领域的测试导入——改它的任何一个
helper，都要同时理解 records、consultation、kernel、extensions 四处的用法。夹具没有
自己的家，就没有单一责任。

**步骤**：
1. 盘点每个夹具文件被外部实际引用的名字（`from tests.X import Y as alias` 逐条列出）
2. 把这些名字搬进 `tests/support/`（按领域建模块：`support/patient_calculations.py`、
   `support/self_check.py`…），原名在新处保留导入别名不改调用点
3. 原测试文件里只留下真正的测试
4. `naming.py` 已允许 `tests/support/` 无 `test_` 前缀（R3），无需改门禁

**验收标准**：
- `grep -r "from tests\.\w* import test_" tests/` 零命中（新增一条门禁到 `naming.py` R4 旁，防止复发）
- pytest 2023 passed / **11958 subtests 不变**（夹具搬移不得改变任何用例）
- 被搬移的每个 helper 带一行 docstring 说明它构造的是什么场景

- **复杂度**：中（12 处改写 + 7 个文件的重构，但全部机械）
- **预计改动**：~15 个文件，净减约 100 行重复
