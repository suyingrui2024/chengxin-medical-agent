## 批次 1：✅ 测试夹具集中（17 处跨测试导入 → `tests/support/`，已完成）

**现状**：~~12 条~~ **17 条**跨测试导入边，13 个测试文件被当作夹具使用。
初盘的正则只匹配 `from tests.<区域> import test_<名>` 一种形状，漏掉了
带子模块路径的（`from tests.dialogue.test_repeated_observations import …`）、
`import tests.x.test_y as m` 的、以及导入名以 `test_` 开头但模块只有两段的
（`from tests.consultation import test_consultation as offline`）——**用正则
做导入分析漏了 5 条**；R5 门禁因此用 AST 而不是正则。已完成（见提交记录）：

```
被复用的夹具文件                          被导入次数
tests/records/test_patient_calculations.py     4
tests/consultation/test_self_check_conversation.py  2
tests/dialogue/test_repeated_observations.py   2
tests/consultation/test_consultation.py        2
tests/dialogue/test_location_answers.py        1
tests/kernel/test_calculation_supplements.py   1
```

**为什么是债**：`test_patient_calculations.py` 被四个领域的测试导入——改它的任何一个
helper，都要同时理解 records、consultation、kernel、extensions 四处的用法。夹具没有
自己的家，就没有单一责任。

**步骤**：
1. 盘点每个夹具文件被外部实际引用的名字（`from tests.X import Y as alias` 逐条列出）
2. 把这些名字搬进 `tests/support/`（按领域建模块：`support/patient_calculations.py`、
   `support/self_check.py`…），原名在新处保留导入别名不改调用点
3. 原测试文件里只留下真正的测试
4. `naming.py` 已允许 `tests/support/` 无 `test_` 前缀（R3），无需改门禁

**实际结果**：2023 passed / 11958 subtests 恒定；净减 905 行（-1153/+248）；
support 从 5 个模块增至 14 个；`naming.py` 新增 R5（AST 扫描，防复发，3 个新测试）。

**验收标准**：
- `grep -r "from tests\.\w* import test_" tests/` 零命中（新增一条门禁到 `naming.py` R4 旁，防止复发）
- pytest 2023 passed / **11958 subtests 不变**（夹具搬移不得改变任何用例）
- 被搬移的每个 helper 带一行 docstring 说明它构造的是什么场景

- **复杂度**：中（12 处改写 + 7 个文件的重构，但全部机械）
- **预计改动**：~15 个文件，净减约 100 行重复

## 批次 5：工程基线（2026-11-03 新增，已完成）

核查中发现的三个不需要产品决策就能修的缺口：

1. **版本号单一真源** — 原本版本号在四处：`package.json`、`pyproject.toml`、
   `src/medagent/__init__.py`，以及写进每条 `agent.started` 审计事件的
   `policy_version` 字符串。没有任何东西比对它们，改版本漏改一处不会报错——
   而漏改的那一处正是审计记录里读到的那个。现在真源是 `__init__.py`，
   `policy_version` 运行时派生，脚本 `scripts/lint/version.py` 校验另外两个
   清单文件（7 个测试）。
2. **CI 超时余量** — 浏览器套件是流水线最长的一根柱子（每个 spec 文件起一次
   server），原先和 pytest 挤在同一个 job、同一个 60 分钟超时里。现在拆成
   独立 job，4 个 shard 各占一个 runner；`playwright.config.mjs` 的端口与输出
   目录参数化，`scripts/test/ui-ci.mjs` 支持 `UI_SHARD`/`UI_PORT`/`UI_OUTPUT_DIR`。
3. **文档索引** — `docs/` 下 69 篇设计文档混着"当前有效的规则"和"已被取代的
   历史设计"，读者无从判断。现在有 `docs/README.md` 索引（状态、最后更新、
   行数），`scripts/lint/docs_index.py` 生成并校验"每篇都在索引里"（5 个测试）。
