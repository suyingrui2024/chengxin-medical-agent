## 文件归属

- `src/medagent/`：当前运行代码；领域包保留现有依赖边界，不为目录整齐破坏接口。
- `src/medagent/web/js/app/`：页面装配、状态、导航和问诊交互。
- `src/medagent/web/js/records/`：档案；`execution/`：执行工作台；`structured/`：结构化卡片；`appearance/`：外观。
- `scripts/app/`：人工启动命令；`config/`：两层配置；`build/`：构建；`evaluation/`：评测；`maintenance/`：归档等维护；`audit/`：代码审计；`lint/`：门禁；`test/`：测试入口。
- `tests/`：当前可执行测试；共享夹具进 `support/`，不要导入另一个测试文件获取夹具。
- `config/playwright/`：浏览器、桌面和真实模型测试配置；根目录仅保留自动发现入口。
- `docs/`：根目录仅导航；现行文档按 getting-started、architecture、features、development 分类；archive 保存历史，evaluations 保存报告与归档清单。
- `data/`：当前知识数据；`research/` 统一保存 benchmarks、experiments、tools；冻结依赖放外部 `_archives`。
- `.runtime/`、`.venv/`、`node_modules/`、`dist/`、`test-results/`：本地生成物，不进入源码版本管理。

## 后续变更原则

一个功能变更应能沿“入口 → 所属领域 → 测试”定位。新增文件先判断职责归属；移动文件同时更新代码、测试、平台脚本和打包清单。目录变化须由静态引用图检查，初始化由单一入口显式调用。样式迁移保持规则顺序，不能用文件行数减少代替行为验证。

归档不改写 Git 历史、不影响当前运行，恢复步骤见 [评测归档说明](../evaluations/README.md)。本轮本地验证结果在完成后填写，不将历史测试数当作本次通过数。
