# 发布门、阶段提交与临床评测框架

本文件描述 v0.11.17 之后新增的 P0 工程约束。它改善工程可追踪性和失败降级，
不构成临床审核、医疗有效性验证或生产数据治理方案。

## 1. 回复发布门

患者可见回复在写入会谈记录前由 `ReplyPublicationGate` 做确定性检查：

- 回复阶段必须与当前病例阶段一致；
- 文字与快捷选项必须满足长度、控制字符和唯一值约束；
- 已命中急症时只允许控制器生成的关闭会谈急救回复，且必须包含 120 指引；
- 已命中尽快就医时只允许 `urgent` 或更高优先级的回复；
- 已关闭的会谈不能发布普通问题或摘要。

失败不会再次请求模型。系统发布固定的安全降级回复，保留既有记录，并写入
`reply.publication_blocked` 事件。通过时写入 `reply.publication_allowed`。

## 2. 阶段提交

会谈内部在处理事实、图示任务或更正时可能暂时调整阶段。只有一条回复真正准备
发送给患者时，`commit_phase` 才会提交一次患者可见的阶段变化，并产生：

```json
{
  "event_type": "case.phase_transition",
  "payload": {
    "transition_id": "uuid",
    "from": "history",
    "to": "observation",
    "reason": "已核对的动作原因",
    "state_revision_before_commit": 12
  }
}
```

这避免事件轨迹把未发布的中间状态误写成患者经历过的流程。

## 3. 请求追踪

患者端可在请求头提供格式受限的 `X-Request-ID`。服务会在响应头回传它；不合法或
缺失时生成新的 ID。一次前台会谈还会生成 `trace_id` 和模型决策 `decision_id`。
同一次提交产生的模型、工具、分流、发布和回复事件共享这些字段。

追踪标识本身不包含患者文本或身份信息。可选 JSONL 事件日志仍可能包含健康信息，
因此仅适用于当前研究原型的明确本地操作；它不替代加密、授权、留存期限或删除机制。

## 4. 临床评测输入合同

`scripts/evaluation/medical/evaluate_medical_release.py` 只对外部审核并标记为 `approved` 的病例做确定性
评分。它拒绝未标注审核者和审核时间的病例，避免把合成工程夹具称作临床基线。

```bash
PYTHONPATH=src python3 scripts/evaluation/medical/evaluate_medical_release.py \
  --input path/to/clinically-reviewed-cases.json \
  --output /tmp/medical-release-report.json
```

评测合同检查预期和观测到的风险级别、允许的回复类型、必需事件。病例内容、规则、
审核标准和发布阈值仍需由有资质的临床审核者提供与签署。
