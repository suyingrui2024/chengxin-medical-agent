# 代码与命名规范

> 状态：文件命名已由 CI 强制；提交信息与分支为约定，评审时人工把关
> 权威实现：`scripts/lint/naming.py`（规则细节以脚本 docstring 为准）
> 覆盖范围：`.py`／`.js`／`.mjs`／`.cjs`／`.css`
> 相关：架构分层见 `架构分层规则.md`，测试组织见 `../tests/README.md`

## 1. 判断一个文件名的标准

只有一条：**读者在打开文件前，能不能从名字预测里面有什么。**

按这个标准，坏名字可以分成两类，处理方式不同。

**没有约定的坏名字**——`utils`、`extra`、`manager`、`tmp`。它们描述的是"还没想清楚"或"写完的时间"，不是内容。这类必须改，因为名字不含信息时，文件必然长成下一个调用者需要的样子。

**有局部约定的名字**——`core.py`。在本项目里，它承载所属包的状态所有权或核心入口：`consultation/core.py` 定义 `ConsultationEngine` 并装配职责组件，`consultation/agent/core.py` 定义 `AdaptiveConsultationEngine`，`server/core.py` 定义 `HandlerCore`。职责明确的组件按领域命名，如 `planning.py`、`emergency.py`、`closing_flow.py`。

判据是"换掉它能不能让读者更快找到东西"，不是"这个词抽象不抽象"。

## 2. 硬规则（`naming.py` 强制）

| 规则 | 内容 | 为什么 |
|---|---|---|
| **R1** | 不得命名为 `utils`／`util`／`helpers`／`helper`／`common`／`shared`／`misc`／`stuff`／`tmp`／`temp`／`scratch`／`miscellaneous` | 这些名字不描述内容，等于宣布"什么都能往里放" |
| **R2** | 名字里不得出现日期词：`extra`、`old`、`new`、`backup`、`bak`、`orig`、`final`、`late`、`legacy`、`tmp`、`temp`（**任意位置**），以及结尾的版本号 `v2` 及以上、裸 `2`／`3` | 这类词记录的是写作时间，不是内容。两个文件的正确做法是把职责切开、两边都起名，而不是把第二个叫"附加" |
| **R3** | `tests/` 下的 `.py` 必须是 `test_*.py`（`conftest.py`、`__init__.py`、`support/`、`fixtures/` 除外） | pytest 只收集 `test_*`。此前 84 项测试因为命名不符从未执行过；共享夹具放 `tests/support/` |
| **R4** | **`tests/` 顶层不得有 `test_*.py`** | 测试按被测包分组（`tests/conclusion/`、`tests/execution/`…）。允许顶层放一个，下一个也会放那里——162 个文件平铺就是这么长出来的 |

**R2 查任意位置，不只查后缀。** 这条规则是针对
`styles-08-settings-and-late-refinements.css` 写的，而日期词在名字中间——只查后缀的门禁会看着它走过去。

**R1／R2 覆盖五种扩展名。** 只管 `.py` 的那一轮里，样式表长出了
`styles-01-tokens-base-execution.css`：8 个编号分片、4 个用 `-and-` 焊了三件事、1 个按写作批次命名，门禁一次都没响。只管一种语言的门禁，就只保护一种语言。

`_copy` 不在 R2 里：`test_close_copy.py` 测的是收尾**文案**（close copy），"copy" 在这里是领域词。规则误伤一次合法用法，就会被整体删掉，那才是真的失去防护。

名字中间的 `_and_` 也不查：`test_worry_and_goal.py` 确实同时测 worry 和 goal。`-and-` 的问题是样式表特有的——它把一个纯按行数切出来的分片，按三个不相干的主题命名。

## 3. 文件放哪里

- 共享测试夹具、构造器、契约辅助 → `tests/support/`。放在别处会被当成测试模块，R3 会拒绝。
- **测试按被测包分组**，目录名与 `src/medagent` 的包名一致；一个测试只属于一个目录，主要断言哪个包就放哪个；真的横跨三四个包，放 `tests/integration/`。因此 `test_x.py` 从 160 个平铺文件变成了 13 个领域目录，pytest 节点名随之变化（`tests/conclusion/test_conclusion.py` → `tests/conclusion/test_conclusion.py`）。
- 一个文件只承担一个职责。`formulas.py`（8 个通用公式）与 `department_formulas.py`（34 个科室公式）按规模切开，两边都按内容命名；合并后的 `FORMULAS` 表对调用方仍是一个入口。
- 公开类名可以比文件名宽（`session_registry.py` 里是 `ExecutionManager`）。文件名服务包内阅读，类名服务调用方，两者不必同形；但文件被改名后，docstring 要说明为什么。

### 前端资源：按业务职责管理

```text
src/medagent/web/
  index.html
  js/
    app.js              唯一页面入口
    app/                bootstrap、events、state、context、问诊/设置/导航
    records/            健康档案
    execution/          DSH 工作台、产物与图表
    structured/         结构化问题、定位与任务卡
    appearance/         首屏外观偏好
  css/
    styles.css          唯一完整级联清单
    fonts.css           桌面启动页也使用的字体入口
    base/               8 个有序基础分片
    appearance/         皮肤与外观
    features/           档案、自查、重排、执行与图表
  assets/
    fonts/
    illustrations/
```

`app/bootstrap.js` 显式创建功能 UI、绑定事件并读取服务状态。导入业务模块本身不查询 DOM、不注册事件；外观脚本为避免首屏闪烁，仍在页面头部先行应用偏好。重连只重新读取状态，重复启动不会再次绑定按钮。

问诊草稿按会谈隔离，档案和执行工作台各自拥有内部状态。跨功能回调在启动时注入，不再使用可变的 `runtime.*Impl` 回填。

`css/styles.css` 按原有生效顺序声明全部样式：皮肤、字体、基础分片、功能覆盖。基础分片是历史级联切片；移动或整理规则必须保留级联语义。本轮只移除同一作用域内完全重复的规则并保留最后一次，不以大规模重排换取目录整齐。

`tests/architecture/test_static_assets.py` 检查页面、样式、ES 模块和资源清单的引用闭合，以及基础分片的完整顺序。移动代码同时修改浏览器测试、Node 测试、Electron 启动页和 Python 包资源清单。JS/PowerShell 中嵌入的 Python 模块路径由 `test_embedded_python_paths.py` 检查。

## 4. 提交信息

格式：`type(scope): 祈使句，小写开头，说做了什么`

```
test(docs): fail the build when a doc names a module that moved
refactor(kernel): group the 59 flat modules into seven cohesive packages
fix: the bugs the new gates found on their first run
```

- `type` 取 `feat`／`fix`／`refactor`／`perf`／`test`／`docs`／`chore`。
- `scope` 写受影响的包或层，可省略。
- **正文说为什么**，不说"改了哪些行"——那是 diff 的职责。一个缺陷被修掉，要写清楚它此前为什么没被发现。
- 禁止：无类型前缀（`Update`、`Add`、`合并`）、`fix bug`、`misc changes`。仓库历史前 300 条提交里有 13 条 `Record`、9 条 `Add`、5 条 `合并`，读起来无法判断影响面——那是历史，不再新增。

## 5. 分支

**一个分支一件事。** 分支名描述这件事，不描述过程中碰到的所有事。

反例：`feat/calculations-kg-and-test-coverage` 同时含"计算科目""知识图谱""测试覆盖"三件事，看分支名无法判断它是否该合、合了要回归什么。

正例：`feat/department-formulas`、`refactor/server-dispatch-split`、`test/coverage-gaps`。

## 6. 门禁

| 命令 | 管什么 |
|---|---|
| `npm run lint:structure` | 模块规模（≤1200 行）+ 依赖方向（R1–R6）+ **文件命名（五种扩展名）** + 大资产基线 |
| `npm run lint:python` | ruff：E9 + F 组（未定义名、坏 `__all__`、未使用导入／变量、重定义…）+ **B 组整组**（B023 在 `tests/` 与 `scripts/evaluation/` 豁免） |
| `npm run format:check` | prettier：web／desktop／scripts 的 js、css、html、json |
| `npm run test:python` | pytest 全量（`unittest discover` 会静默跳过 pytest 风格模块，不要用） |

CI 在 `main-quality.yml` 逐项执行，任一项失败即阻断。
