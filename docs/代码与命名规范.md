# 代码与命名规范

> 状态：文件命名已由 CI 强制；提交信息与分支为约定，评审时人工把关
> 权威实现：`scripts/lint/naming.py`（规则细节以脚本 docstring 为准）
> 相关：架构分层见 `架构分层规则.md`，测试组织见 `../tests/README.md`

---

## 1. 判断一个文件名的标准

只有一条：**读者在打开文件前，能不能从名字预测里面有什么。**

按这个标准，坏名字可以分成两类，处理方式不同。

**没有约定的坏名字**——`utils`、`extra`、`manager`、`tmp`。它们描述的是"还没想清楚"或"写完的时间"，不是内容。这类必须改，因为名字不含信息时，文件必然长成下一个调用者需要的样子。

**有局部约定的名字**——`core.py`。单看是空壳词，但在本项目里它是固定约定：`consultation/core.py`、`consultation/agent/core.py`、`server/core.py` 各自装一个由多个 mixin 拼成的类的**基座**，与同目录的 `agent.py`／`patient.py`／`closing.py` 并列，且类名直接对应（`HandlerCore`、`ConsultationEngineCore`）。改这类名字会让文件名与它定义的类脱节，是净损失，所以门禁放行。

判据是"换掉它能不能让读者更快找到东西"，不是"这个词抽象不抽象"。

## 2. 硬规则（`naming.py` 强制）

| 规则 | 内容 | 为什么 |
|---|---|---|
| **R1** | 不得命名为 `utils`／`util`／`helpers`／`helper`／`common`／`shared`／`misc`／`stuff`／`tmp`／`temp`／`scratch`／`miscellaneous` | 这些名字不描述内容，等于宣布"什么都能往里放" |
| **R2** | 不得带批次或版本后缀：`_extra`、`_old`、`_new`、`_backup`、`_bak`、`_orig`、`_final`、`_tmp`、`_temp`、`_v2` 及以上、裸 `_2`／`_3` | 后缀记录的是写作时间，不是内容。两个文件的正确做法是把职责切开、两边都起名，而不是把第二个叫"附加" |
| **R3** | `tests/` 顶层的 `.py` 必须是 `test_*.py`（`conftest.py`、`__init__.py` 除外） | pytest 只收集 `test_*`。此前 84 项测试因为命名不符从未执行过；共享夹具放 `tests/support/`，该目录不受此规则约束 |

`_copy` 不在 R2 里：`test_close_copy.py` 测的是收尾**文案**（close copy），"copy" 在这里是领域词。规则误伤一次合法用法，就会被整体删掉，那才是真的失去防护。

## 3. 文件放哪里

- 共享测试夹具、构造器、契约辅助 → `tests/support/`。直接放 `tests/` 顶层会被当成测试模块，且 R3 会拒绝。
- 一个文件只承担一个职责。`formulas.py`（8 个通用公式）与 `department_formulas.py`（34 个科室公式）按规模切开，两边都按内容命名；合并后的 `FORMULAS` 表对调用方仍是一个入口。
- 公开类名可以比文件名宽（`session_registry.py` 里是 `ExecutionManager`）。文件名服务包内阅读，类名服务调用方，两者不必同形；但文件被改名后，docstring 要说明为什么。

## 4. 提交信息

格式：`type(scope): 祈使句，小写开头，说做了什么`

```
test(docs): fail the build when a doc names a module that moved
refactor(kernel): group the 59 flat modules into seven cohesive packages
fix: the bugs the new gates found on their first run
```

- `type` 取 `feat`／`fix`／`refactor`／`perf`／`test`／`docs`／`chore`。
- `scope` 写受影响的包或层，可省略。
- **正文说为什么**，不说"改了哪些行"——那是 diff 的职责。一个缺陷被修掉，要写清楚它此前为什么没被发现。
- 禁止：无类型前缀（`Update`、`Add`、`合并`）、`fix bug`、`misc changes`。仓库历史前 300 条提交里有 13 条 `Record`、9 条 `Add`、5 条 `合并`，读起来无法判断影响面——那是历史，不再新增。

## 5. 分支

**一个分支一件事。** 分支名描述这件事，不描述过程中碰到的所有事。

反例：`feat/calculations-kg-and-test-coverage` 同时含"计算科目""知识图谱""测试覆盖"三件事，看分支名无法判断它是否该合、合了要回归什么。

正例：`feat/department-formulas`、`refactor/server-dispatch-split`、`test/coverage-gaps`。

## 6. 门禁

| 命令 | 管什么 |
|---|---|
| `npm run lint:structure` | 模块规模（≤1200 行）+ 依赖方向（R1–R6）+ **文件命名** + 大资产基线 |
| `npm run lint:python` | ruff：未定义名、未定义注解、`assert` 误用、broken `__all__`、raise-from、循环变量 |
| `npm run format:check` | prettier：web／desktop／scripts 的 js、css、html、json |
| `npm run test:python` | pytest 全量（`unittest discover` 会静默跳过 pytest 风格模块，不要用） |

CI 在 `main-quality.yml` 逐项执行，任一项失败即阻断。
