# 代码与命名规范

> 状态：文件命名已由 CI 强制；提交信息与分支为约定，评审时人工把关
> 权威实现：`scripts/lint/naming.py`（规则细节以脚本 docstring 为准）
> 覆盖范围：`.py`／`.js`／`.mjs`／`.cjs`／`.css`
> 相关：架构分层见 `架构分层规则.md`，测试组织见 `../tests/README.md`

---

## 1. 判断一个文件名的标准

只有一条：**读者在打开文件前，能不能从名字预测里面有什么。**

按这个标准，坏名字可以分成两类，处理方式不同。

**没有约定的坏名字**——`utils`、`extra`、`manager`、`tmp`。它们描述的是"还没想清楚"或"写完的时间"，不是内容。这类必须改，因为名字不含信息时，文件必然长成下一个调用者需要的样子。

**有局部约定的名字**——`core.py`。单看是空壳词，但在本项目里它是固定约定：`consultation/core.py`、`consultation/agent/core.py`、`server/core.py` 各自装一个由多个 mixin 拼成的类的**基座**，与同目录的 `agent.py`／`patient.py`／`closing.py` 并列，且类名直接对应（`HandlerCore`、`ConsultationEngineCore`）。改这类名字会让文件名与它定义的类脱节，是净损失，所以门禁放行。

判据是"换掉它能不能让读者更快找到东西"，不是"这个词抽象不抽象"。

## 2. 硬规则（`naming.py` 强制）

| 规则 | 内容 | 为什么 |
|---|---|---|
| **R1** | 不得命名为 `utils`／`util`／`helpers`／`helper`／`common`／`shared`／`misc`／`stuff`／`tmp`／`temp`／`scratch`／`miscellaneous` | 这些名字不描述内容，等于宣布"什么都能往里放" |
| **R2** | 名字里不得出现日期词：`extra`、`old`、`new`、`backup`、`bak`、`orig`、`final`、`late`、`legacy`、`tmp`、`temp`（**任意位置**），以及结尾的版本号 `v2` 及以上、裸 `2`／`3` | 这类词记录的是写作时间，不是内容。两个文件的正确做法是把职责切开、两边都起名，而不是把第二个叫"附加" |
| **R3** | `tests/` 顶层的 `.py` 必须是 `test_*.py`（`conftest.py`、`__init__.py` 除外） | pytest 只收集 `test_*`。此前 84 项测试因为命名不符从未执行过；共享夹具放 `tests/support/`，该目录不受此规则约束 |

**R2 查任意位置，不只查后缀。** 这条规则是针对
`styles-08-settings-and-late-refinements.css` 写的，而日期词在名字中间——只查后缀的门禁会看着它走过去。

**R1／R2 覆盖五种扩展名。** 只管 `.py` 的那一轮里，样式表长出了
`styles-01-tokens-base-execution.css`：8 个编号分片、4 个用 `-and-` 焊了三件事、1 个按写作批次命名，门禁一次都没响。只管一种语言的门禁，就只保护一种语言。

`_copy` 不在 R2 里：`test_close_copy.py` 测的是收尾**文案**（close copy），"copy" 在这里是领域词。规则误伤一次合法用法，就会被整体删掉，那才是真的失去防护。

名字中间的 `_and_` 也不查：`test_worry_and_goal.py` 确实同时测 worry 和 goal。`-and-` 的问题是样式表特有的——它把一个纯按行数切出来的分片，按三个不相干的主题命名。

## 3. 文件放哪里

- 共享测试夹具、构造器、契约辅助 → `tests/support/`。直接放 `tests/` 顶层会被当成测试模块，且 R3 会拒绝。
- 一个文件只承担一个职责。`formulas.py`（8 个通用公式）与 `department_formulas.py`（34 个科室公式）按规模切开，两边都按内容命名；合并后的 `FORMULAS` 表对调用方仍是一个入口。
- 公开类名可以比文件名宽（`session_registry.py` 里是 `ExecutionManager`）。文件名服务包内阅读，类名服务调用方，两者不必同形；但文件被改名后，docstring 要说明为什么。

### 前端资源：`web/` 按种类分目录

```
src/medagent/web/
  index.html          页面，唯一入口
  css/                样式（入口是 css/styles.css）
  js/                 脚本（入口是 js/app.js，ES 模块）
  assets/             非代码资源
    fonts/            两份 Noto CJK + OFL 与来源清单
    illustrations/    定位图、腋温图 + 图示来源清单
```

在这之前是 **55 项平铺在一个目录**：29 个脚本、17 个样式表、两份 39 MB 字体、图片、许可证文本、HTML 平级。平铺不是偷懒——旧的静态处理器只服务顶层文件名。放开子目录之后，"哪些是代码、哪些是资产"从名字就能看出来。

代价是**每一条引用都要跟着动**，所以 `tests/test_static_assets.py` 把整张引用图跑一遍：页面的 `href`／`src`、样式表的 `@import` 与 `url()`、ES 模块的 `import`／`export ... from`、清单里的 `file`，任何一条指向不存在的文件都失败。移动目录却没有这条测试，等于把 55 个引用交给浏览器去发现。

### 样式分片：编号是级联顺序

`css/styles.css` 是唯一的 `@import` 清单，编号分片必须全部被导入、只导入一次、且顺序与编号一致（有测试）。分片是**按行数切**的，不是按主题切：一个分片里落进哪个主题取决于它的行号落在哪。

所以分片名只承担"主要主题"，文件头注释列出它实际包含的全部内容：

```
01-tokens.css — cascade slice 1 of 8; styles.css imports these in order.
   Holds: design tokens, base elements, execution layout, artifact previews.
```

按主题重新切分意味着重排 7000 条规则，而唯一的验证手段是肉眼比对渲染结果——这个代价换不来一个更好听的文件名。

## 4. 提交信息

格式：`type(scope): 祈使句，小写开头，说做了什么`

```
test(docs): fail the build when a doc names a module that moved
refactor(kernel): group the 59 flat modules into seven cohesive packages
fix: the bugs the new gates found on their first run
```

- `type` 取 `feat`／`fix`／`refactor`／`perf`／`test`／`docs`／`chore`。
- `scope` 写受影响的包或层，可省略。
- **正文说为什么**，不说"改了哪些行"——那是 diff 的职责。一个缺陷被修掉，要写清楚它此前为什么没被发现。
- 禁止：无类型前缀（`Update`、`Add`、`合并`）、`fix bug`、`misc changes`。仓库历史前 300 条提交里有 13 条 `Record`、9 条 `Add`、5 条 `合并`，读起来无法判断影响面——那是历史，不再新增。

## 5. 分支

**一个分支一件事。** 分支名描述这件事，不描述过程中碰到的所有事。

反例：`feat/calculations-kg-and-test-coverage` 同时含"计算科目""知识图谱""测试覆盖"三件事，看分支名无法判断它是否该合、合了要回归什么。

正例：`feat/department-formulas`、`refactor/server-dispatch-split`、`test/coverage-gaps`。

## 6. 门禁

| 命令 | 管什么 |
|---|---|
| `npm run lint:structure` | 模块规模（≤1200 行）+ 依赖方向（R1–R6）+ **文件命名（五种扩展名）** + 大资产基线 |
| `npm run lint:python` | ruff：未定义名、未定义注解、`assert` 误用、broken `__all__`、raise-from、循环变量 |
| `npm run format:check` | prettier：web／desktop／scripts 的 js、css、html、json |
| `npm run test:python` | pytest 全量（`unittest discover` 会静默跳过 pytest 风格模块，不要用） |

CI 在 `main-quality.yml` 逐项执行，任一项失败即阻断。

## 7. 已知欠账

命名层面的债已清完（`formulas_extra` → `department_formulas`、`manager` → `session_registry`、两个测试辅助文件归入 `tests/support/`、`web/` 三目录重排、8 个样式分片去批次名、9 个 UI 模块统一 `-ui-` 位置）。仍未处理的是：

- **8 处星号导入，全部是门面包的重导出**（`consultation`、`consultation/agent`、`execution`、`patient_records/store`、`server`、`subagents/coordinator` 的 `__init__.py`）。它们原先有 46 处，另外 26 个模块已改为显式导入自己用到的名字：每个文件开头现在能直接读到"我用了 `Event`、`Phase`、`uuid4`"，而不是一句 `import *`。剩下的 8 处保留，因为那些 `__init__.py` 用 `__all__ = list(_PREAMBLE_ALL) + [...]` 把整个前缀声明成了包的公开面；把星号拆掉，`__all__` 就会指向不存在的属性。要真正收紧，得先把这些包的公开面收窄到它们自己的类，那是设计决定，不是机械替换。
- **F401 仍不可用，但原因换了**。原来是 32 处星号导入，现在是 `conclusion`／`subagents`／`patient_records` 三个包的 `__init__.py` 靠重导出对外供名却没写 `__all__`，467 个名字被判为未使用。补上 `__all__` 就能开 F401；猜着补会把真正的公开面写错。
- **注释里的批次标记**（`Batch A`／`Batch C rework (G-02)` 等 20 余处）。项目有意保留它们作为 `git log --follow` 之外的追溯线索（见 `tests/README.md`），不由本次清理。
