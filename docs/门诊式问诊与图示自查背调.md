# 门诊式问诊与图示自查智能体背调

> 本文保留立项背调。项目后来已实现工程原型并接入 DSH；现行能力及限制以[产品与技术设计](首版产品与技术设计.md)为准，本文的未来时态不代表当前代码状态。

检索截至 2026 年 10 月 15 日。当前目标是先设计具有门诊交互流程的医疗智能体：理解主诉，持续获取相关病史，必要时通过示意图引导患者完成合适的自查或测量，再结合反馈调整询问与解释。首期不额外微调，视觉动作纠正留作后续能力。首个临床任务及适用人群尚待确定。

这一方向比同时构建公式平台、营养估算、手环预警和医保接口更集中。已有研究支持结构化问诊、图文辅助理解和部分远程观察的可行性；但这些证据不能直接合成“已拥有完整随身医生”的结论。最值得验证的是：在一次明确健康问题的交互中，能否获得更可靠的信息，同时降低患者的理解和完成负担。

## 主要结论

1. 门诊式问诊适合作为当前核心。医学沟通框架可以指导流程，语言模型负责自然交互和灵活追问，结构化状态用于控制遗漏、冲突和过早结束。
2. 图示自查值得作为产品重点，但应拆开评价理解、操作、观察可靠性和后续行动。图片更直观，不等于自查结果更准确，也不保证长期使用率提高。
3. 首期可以不额外微调。优先投入临床共同设计、任务定义、交互状态与评价；后续是否训练由具体失败类型决定。
4. 自查应逐项选择，不做通用查体指令生成器。不同观察的可靠性、风险和所需设备差异很大。
5. 视觉能力适合先检查取景与完成条件，再验证特定动作，最后研究临床解释；动作外观合格不能直接说明体征阴性。

## 门诊交互应学习哪些内容

Calgary–Cambridge 框架把沟通分为开始会谈、收集信息、体格检查、解释与计划、结束会谈，并把组织结构与建立关系贯穿全程。它提供的是过程框架，具体疾病需要询问什么仍需临床知识与适用规范支持。[原作者对框架的说明](https://asmepublications.onlinelibrary.wiley.com/doi/10.1111/j.1743-498X.2007.00159_1.x)

因此，不宜仅复制医生说话的语气，或把主诉、现病史、既往史写成依次填满的问卷。应复现功能：听懂患者想解决的问题，理清时间线，识别会改变判断的信息，解释为什么需要观察，并在结束前确认理解与后续安排。

| 环节 | 智能体需要完成的工作 | 候选交互设计 |
| --- | --- | --- |
| 开场与确定问题 | 确认替谁咨询、主要困扰及患者目标 | 先允许自然叙述，再核实最主要的问题 |
| 初步紧急程度判断 | 判断是否需要立即改变交互路径 | 必要时提前转入求助提示，不要求先完成全部病史 |
| 现病史 | 理清何时出现、如何变化、相关表现和已采取措施 | 对关键缺口定向追问，避免一次列出很多问题 |
| 相关背景 | 获取会影响当前判断的用药、过敏、既往及其他背景 | 已有信息复用，但询问是否发生变化 |
| 定向观察或自查 | 选择有价值且适合完成的观察 | 显示一个任务，说明目的，允许跳过或反馈做不到 |
| 解释与计划 | 区分已知、未知与需要进一步核实的事项 | 简短主结论，依据和细节按需展开 |
| 结束与后续 | 确认关键理解，整理摘要及重新求助条件 | 支持复述或示范确认，而非只问是否看懂 |

这些环节允许回跳。患者补充新的服药信息或自查反馈后，系统可能需要重新核对病史，也可能需要结束当前流程。紧急程度判断应持续存在；相关用药与过敏史可能需要提前询问。

## 真实问诊研究

### 中国眼科问诊前采集研究

2026 年 10 月 5 日发表的一项广州单中心随机试验纳入 172 名非急诊预约患者。采用症状逻辑树等设计的智能体在病史质量评分上更好，但交互中位时长为 11.2 分钟，住院医师组为 3.1 分钟。引入眼部体征后，住院医师的表现改善更大。研究仍处于已接受论文的提前发布阶段。[原始论文摘要](https://www.nature.com/articles/s41746-026-03232-x)

这支持问诊采集的可行性，也说明信息更完整可能付出时间代价。设计中需要同时评价关键遗漏和患者负担；不能把病史采集优势外推到查体与完整诊疗能力。

### PreA 门诊流程研究

PreA 在中国两家中心、24 个专科开展随机试验，最终分析 2,069 人。患者独立使用组的专科医生会谈时间从对照组 4.41 分钟降到 3.14 分钟，但此前患者另需与系统交互约 3.51 分钟。因此，这项研究支持改善门诊工作流，不能直接表述为减少患者全程耗时，也不是居家独立诊疗验证。[原始论文](https://www.nature.com/articles/s41591-025-04176-7)

### 交互式评价与多模态研究

CRAFT-MD 强调在患者对话中评价病史获取和推理；MediQ 研究何时继续追问。它们说明，最终答题成绩不足以评价问诊过程，也不能认为多问问题自然改善表现。[CRAFT-MD](https://www.nature.com/articles/s41591-024-03328-5)、[MediQ](https://arxiv.org/abs/2406.00922)

AMIE Video 2026 年预印本已经研究实时视频对话及虚拟查体。其局限分析同时指出：模型可能看到线索却未采取合适行动，部分细微表现仍难识别，主要评价来自模拟会谈。它是架构参照，不是当前项目可直接复用的完整医生能力。[研究全文](https://arxiv.org/html/2608.09861v1)

## 图示说明的证据

一项纳入 54 个随机试验、其中 42 个进入荟萃分析的研究发现，图片辅助健康信息总体改善理解与记忆，但研究异质性显著。它为图文设计提供总体支持，不能直接证明本项目的自查操作或长期留存会改善。[研究摘要](https://www.sciencedirect.com/science/article/pii/S073839912030197X)

原始随机试验也提供支持。例如，1996 年伤口照护说明研究对 234 名成功电话随访者的分析发现，加入卡通图后，阅读说明、回答问题和自述每日照护的表现更好。但它是特定年代、场景和随访方式的结果，不能直接作为手机问诊产品的预计提升比例。[原始研究摘要](https://onlinelibrary.wiley.com/doi/abs/10.1111/j.1553-2712.1996.tb03431.x)

设计上建议采用图配少量文字，保留口头或语音说明选项。图里要明确左右、方向、起始位置和本步目标；需要动态展示的任务可在静态卡片验证后比较短动画。纯图片也可能被误解，应由目标用户解释图意并实际演示，而不是由开发团队凭直观判断通过。

AHRQ 的 teach-back 与 show-me 方法分别用于确认患者能否用自己的话表达要点、能否实际完成操作。它更适合作为设计原则：确认系统是否解释清楚，而不是考核患者或仅询问是否理解。[AHRQ 工具](https://www.ahrq.gov/health-literacy/improve/precautions/tool5.html)

## 自查能覆盖到什么程度

远程自查的适用性需要逐个项目评价。2022 年一项 32 人肩部研究中，视频指导自查的总体一致性差异较大，活动范围相关项目较可靠，肩关节不稳定相关项目较差；而且研究中存在远程指导，不能外推到完全无人协助的家庭使用。[原始研究](https://pubmed.ncbi.nlm.nih.gov/35562030/)

另一项 62 人研究在特定肩袖病变任务中报告医师引导自查的初步可行性，但同样是明确任务和受控流程。两项工作共同提醒，应评价具体项目、指导方式及对照金标准，而不能给整个远程查体打一个统一准确率。[原始研究](https://pubmed.ncbi.nlm.nih.gov/32871264/)

| 类别 | 候选用途 | 当前设计取舍 |
| --- | --- | --- |
| 图示定位与描述 | 标注症状部位、区分左右、梳理变化 | 适合作为低负担交互起点，不将其包装为客观查体 |
| 已有设备的测量辅助 | 依设备及临床规范指导记录体温或其他读数 | 核验设备、方法和时间；图示不能保证仪器本身准确 |
| 照片采集 | 提高局部、整体或对照照片的可用性 | 先验证取景质量，不直接承诺从照片排除疾病 |
| 经过筛选的简单活动观察 | 在明确适用条件下记录可见表现 | 逐项临床审核，区分因疼痛、理解或镜头问题未完成 |
| 需要专业触诊、听诊或施加特定力量的检查 | 获取难以从手机直接观察的信息 | 不能用一张示意图默认替代专业人员或专用设备 |
| 可能诱发症状或增加跌倒等风险的操作 | 特定临床任务 | 首版不默认加入，须另行论证收益与风险 |

上述分类是产品筛选框架，不是可直接发给患者执行的检查清单。首版任务应由临床人员确定适用性、停止条件和结果用途。

未做、没看清、做不到、用户称没发现异常与可靠观察到阴性，必须分别保存。尤其不能以一次完成质量不足的自查支持排除性结论。

## 视觉反馈的成熟程度

在一项 24 人、6 种膝髋相关康复动作的前瞻性研究中，Motion Coach 的纠错评价与物理治疗师具有较高一致性。它采用姿态估计和预先配置的时空约束；样本、评审人数和动作范围均有限，且存在厂商利益关系。这支持特定动作核验的技术可行性，不能证明通用视觉模型能核验任意医学自查。[原始研究](https://www.jmir.org/2021/7/e26658/)

TrueImage 2.0 的作者预印本研究了向患者反馈照片清晰度、光照等质量问题，并开展 98 人前瞻性试点。这是比直接解释病变更接近首期需求的参照；本轮使用作者预印本，不将其当作已验证的诊断系统。[作者论文](https://arxiv.org/abs/2209.09105)

还存在重要反面证据：2026 年 O-RA 随机试验在 40 名无膝骨关节炎症状或诊断的老年人中测试动作分析应用。应用组训练依从性更低，动作正确性未显著改善；作者指出稳定性和操作困难。它不是问诊自查试验，但足以提醒团队：额外技术交互可能增加负担。[原始试验](https://rehab.jmir.org/2026/1/e80971/)

建议按以下顺序验证：

1. 画面是否可判断，例如部位入镜、遮挡、光照和相机位置。
2. 某个已定义任务的可见动作是否满足具体条件；无法判断时明确返回未知。
3. 如需输出角度等量值，单独核对尺度、视角和误差，不从二维关键点直接宣称精确三维测量。
4. 最后验证这些观察能支持什么临床解释。动作质量合格不等于病变不存在。

视觉模型应能返回无法判断；不确定时不能通过无限重试逼迫患者完成任务。需要保留无需拍摄、稍后补充或转为其他获取方式的路径。

## 图示自查任务的设计

建议把一项自查设计成可调用、可退出、可记录的任务。它包含目标、适用条件、所需设备、图示步骤、停止条件、结果选项和临床用途，而不仅是一张图片。

| 属性 | 设计要求 |
| --- | --- |
| 目的 | 解释本次观察能帮助澄清什么 |
| 适用性 | 哪些患者及当前情境下可以使用，哪些需要跳过 |
| 示意 | 一步突出一个主要动作，标明方向与必要细节 |
| 操作说明 | 保留少量具体文字，必要时可播放语音 |
| 完成反馈 | 支持已完成、做不到、不舒服、没看懂及暂时跳过 |
| 观察结果 | 用户自述与相机评估分开，保留来源 |
| 质量 | 单独记录是否有足够信息可解释，以及不足的原因 |
| 后续关系 | 明确结果会触发什么追问或解释，哪些结论不能据此得出 |
| 内容版本 | 图、文字、规则与审核来源同步固定版本 |

图示优先采用经审核的固定素材，或由经过审核的参数化图形生成。生成式图片可以用于素材制作和探索，但实际患者指引要核对解剖关系、左右方向、动作和文字；不应把会话中临时生成的图直接视为临床内容已正确。

## 问诊智能体的候选结构

首期可以采用一个对话协调器，连接结构化病例状态、症状相关问诊规则、自查任务库和输出核验。逻辑职责清晰后再决定是否拆成多个智能体，研究中的双智能体架构不是必须复制的部署形式。

病例状态保存患者原话、症状时间线、已确认信息、未知和冲突项、相关背景、观察来源、当前待解决问题、已经执行的任务及其质量。病史中的缺失信息不能自动变成阴性。

对话模型提出下一步询问或任务，规则与任务契约核对是否适用。用户反馈进入状态后重新规划；重复询问、无价值检查和过长说明应能被检测并纠正。问诊控制应关注必要信息是否充分，而非固定轮数或模型自称有多大把握。

核心循环是“听取并理解—确定关键缺口—提出一个主要问题或任务—接收与核验反馈—更新情况”。用户可以中断、补充、纠错或不完成某项任务。风险线索出现时可改变当前流程，不要求按原定顺序收集完所有信息。

结束时提供短摘要：当前了解到的情况、仍不能确定的事项、下一步安排及何时需要重新求助。完整病史与依据按需展开，避免每轮都输出长篇分析。

## 如何学习门诊医生

建议邀请临床人员共同标注少量经授权且适合研究的标准化会谈，先使用模拟患者与合成病例。标注的不只是医生问了什么，还包括为什么此时问、答案会改变什么、何时应停止追问或转入观察，以及如何确认患者理解。

把临床沟通过程、症状相关内容和患者端表达方式分别管理。真实门诊中也可能存在时间压力、诱导提问或沟通缺陷，不应把原始对话不加筛选地当成理想模板。首期不微调，可以先把这些知识用于提示、规则、自查任务和评价量表。

## 验证方案

先分别检验问诊、图示和视觉，再开展组合评价，才能解释收益来自哪里。

| 实验 | 比较条件 | 主指标 |
| --- | --- | --- |
| 问诊流程 | 通用对话模型、相同模型加过程与状态约束、临床参照 | 必要信息遗漏、错误记录、危险线索处理、重复问题、完成时间与负担 |
| 图示说明 | 相同内容的简短文字、图文卡片、可选短动画 | 无额外帮助的正确完成率、理解、操作错误、跳过和完成时间 |
| 视觉反馈 | 无反馈、取景质量反馈、特定动作反馈 | 无效观察被误判有效的比例、无谓重拍、错误纠正、净完成效果 |
| 问诊加自查 | 问诊单独使用与加入经过验证的自查任务 | 关键决策改善、额外负担、不恰当安心与不必要升级求助 |

文字组也应写得清楚简短，不能故意使用冗长说明制造图文优势。比较图文、动画与视觉时应保持任务难度和临床内容一致。

问诊评价使用多轮病例，患者只在被问到时提供隐藏信息，并允许未知、纠错和情绪表达。临床审核者在不知组别时评价必要信息与重大错误，不能只用另一个模型评分。真人参与时，用户研究、真实健康数据处理及临床研究所需条件应在相应阶段明确。

理解、操作正确、自查可解释、行动恰当及未来合理需要时愿意复用，分别报告。满意度、点击完成和持续聊天不等于临床价值。对健康服务，日活也不适合作为唯一产品成功指标。

## 当前建议的首版边界

优先完成一套门诊式短会谈流程，以及少量具有明确用途的图示任务。通用交互骨架可以先建立，但疾病相关追问和自查解释应在少数经审核的问题范围内验证。

首批可研究的交互包括症状部位标注、已有设备读数采集和照片取景指导；具体医学自查动作待临床审核与用户试验后选定。这样可以先验证图示能否帮助患者提供更可用的信息，再决定哪类动作值得引入视觉模型。

这份背调未实现系统、生成患者指引素材、测量使用率或完成临床性能实验。下一阶段建议先形成问诊状态图、临床内容范围和自查任务卡规范，再讨论实现。
