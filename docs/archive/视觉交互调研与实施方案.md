# 知微医疗智能体：视觉交互调研与实施方案

更新：2026-10-19

## 实施记录

2026-10-19 已完成 P0 的首轮实现：患者端自检进入任务聚焦模式；摘要增加待核对、来源展开、更正完成反馈和一次撤销；风险建议按常规、尽快评估和立即行动分级呈现；摘要的“待核对、已确认、自动结束但未核对”由后端明确传递；急救行动提供受限的 `tel:120` 入口；步骤切换会移动键盘焦点并播报新的操作说明。患者关键辅助文字提升到 14px，并增加 320px（相当于 1280px 视口下 400% 放大）的无横向滚动回归。P1 的腋温图示已改为无五官、无服装、无肤色主体的局部轮廓：每步仅突出擦干、探头接触点或读数记录，文字操作说明仍由 HTML 提供。P2 的独立工作区仍待后续迭代。

## 1. 结论

知微需要继续加强视觉交互，但重点应放在“帮助用户完成医疗任务”，而不是增加装饰、人物设定或动画。当前项目已经具备自检卡、身体定位、问诊摘要、风险中断、文件预览和图表等基础能力；下一阶段应把这些能力统一成一套低认知负担、可核对、可恢复的患者交互系统。

优先建设五项：

1. 当前任务聚焦：每个时刻只突出一个问题、一个动作或一个核对决定。
2. 医疗行动卡：把普通提醒、尽快处理和立即求助做成稳定、可扫描的行动结构。
3. 可核对记录：明确区分“患者原话、系统整理、患者已确认”，并允许就地更正。
4. 自检视觉语言：使用中性的部位轮廓和器械位置示意，不使用强调人物性格的插画。
5. 测量与文件工作区：对话负责解释与引导，结构化结果在独立区域查看、修改和比较。

不建议让模型即时生成任意医疗界面。医疗交互应由受控组件、固定数据契约和经过验证的状态机渲染；模型只选择允许的组件并提供受约束的数据。

## 3. 当前项目评估

### 已经做对的部分

- 患者视图与研发视图分离，避免把运行细节暴露给患者。
- 自检已经采用单步展示、步骤进度、跳过入口和完整说明折叠。
- 问诊记录位于独立侧栏，支持“已提供 / 待确认”状态和更正。
- 急救状态会中止普通会谈，显示单一、高对比度的行动卡。
- 测量结果、文件预览和图表已经是结构化对象，不只是模型生成文本。
- 关键触控控件已有 44px 目标尺寸，窄屏和原生桌面已有回归截图。

### 当前主要问题

1. **同时争夺注意力的区域过多。** 欢迎页和自检页同时出现侧栏、顶部状态、会谈标题、智能体身份、阶段栏、问诊记录和输入区。执行任务时，用户仍需在多个区域判断“现在应该看哪里”。
2. **自检仍偏“插画展示”。** 测温人物占据较大视觉面积，但器械接触点和动作关系不够醒目；人物造型本身会被用户评价，而不是自然退到说明背景。
3. **信息状态依赖小字。** “患者自述、质量未评价、待核对”等关键语义有时位于次级文字中，不容易快速辨认。
4. **记录侧栏适合浏览，不够适合修改。** 用户能看到“更正”，但还缺少统一的就地编辑、变更前后对比和撤销反馈。
5. **对话与结构化结果的边界还不稳定。** 自检、摘要、计算、文件和运行状态各自形成卡片，但缺少统一的对象标题、状态、主操作与历史入口。
6. **图表能力已有技术基础，患者叙事层不足。** 图表需要同时给出数据范围、测量时间、来源和可访问的文字摘要，避免用户只凭曲线自行判断医学含义。

## 4. 建议的信息架构

### 4.1 患者端保持四种界面状态

| 状态 | 页面主角 | 保留的辅助信息 | 应弱化的内容 |
| --- | --- | --- | --- |
| 对话 | 当前问题与回答 | 本次已记录信息数量、紧急求助入口 | 完整记录列表、历史执行细节 |
| 自检 | 当前一步的动作与输入 | 1/3 进度、跳过、展开完整说明 | 侧栏导航、问诊记录正文、非当前消息 |
| 核对 | 结构化摘要与可修改字段 | 原话来源、修改历史、确认按钮 | 普通聊天气泡 |
| 行动 | 现在需要做的医疗行动 | 触发条件、联系人/电话、简短原因 | 继续聊天和次要建议 |

桌面端可保留并列面板，但主任务至少占可用宽度的三分之二；移动端进入自检、核对或紧急行动时使用全宽视图。

### 4.2 统一的结构化对象外观

所有测量、摘要、换算、文件和执行结果统一为：

1. 对象名称：例如“腋温记录”。
2. 明确状态：待填写、待核对、已确认、失败、已过期。
3. 核心值或当前动作。
4. 来源与时间。
5. 一个主操作，最多两个次操作。
6. 历史和技术细节默认折叠。

避免在同一卡片上同时出现多个徽标、说明段、按钮组和内嵌卡片。

## 5. 分阶段实施方案

### P0：先降低认知负担

#### A. 任务聚焦模式

- 自检开始后收起左侧导航和右侧问诊记录，仅保留返回、跳过和紧急求助。
- 当前动作使用一句大标题；辅助提示限制为一行；完整说明放入可展开区域。
- 输入框只在需要输入读数的步骤出现，不在准备和放置步骤持续占位。
- 步骤切换后把键盘焦点移到新步骤标题，并通过 `aria-live` 播报状态。

涉及文件：[self-check.css](../src/medagent/web/self-check.css)、[structured-ui.js](../src/medagent/web/structured-ui.js)、[app.js](../src/medagent/web/app.js)。

#### B. 风险行动卡统一

- 固定三种行动级别：继续观察、尽快联系医疗服务、立即求助。
- 标题使用行动句，例如“现在拨打 120”；正文只保留触发条件和必要限制。
- 图标、标题和辅助文本共同表达级别，禁止只靠红/黄/蓝颜色。
- 紧急卡中只保留一个主操作；原因和依据折叠显示。

#### C. 核对与更正闭环

- 每项事实显示“用户原话 / 系统整理 / 是否确认”。
- 点击字段进入就地修改，保存后短暂显示“已更新”，并提供一次撤销。
- 修改涉及风险评估时，在对应字段旁明确提示“已重新评估”。
- 未知、未询问和用户否认使用不同文本，不仅依赖圆点颜色。

#### D. 无障碍基线

- 所有可点区域最小 44×44 CSS px。
- 焦点轮廓至少 2px，并与相邻颜色有足够对比。
- 图示必须有等价文字步骤；SVG 区域提供名称、角色和选中状态。
- 异步状态、保存完成、错误和重试结果使用语义化状态消息播报。
- 验证 320px 宽、200% 和 400% 放大，不产生双向滚动。

### P1：重做关键医疗视觉

#### E. 自检图示系统

- 使用统一的中性人体轮廓，不画五官、表情、衣服或品牌人物。
- 只强调三种信息：身体部位、器械位置、动作方向。
- 当前接触点使用高对比描边或局部放大，不用大面积肤色作为主体。
- 每一步只绘制该步需要的物体；说明书、体温计、手臂位置分别出现。
- 视觉素材继续使用仓库内 SVG，保证缩放、主题适配和可访问标注。

建议测温三帧：

1. 腋窝局部 + 擦干动作。
2. 腋窝截面/局部轮廓 + 探头放置点 + 手臂夹紧方向。
3. 体温计屏幕 + “数值、单位、测量时间”三个记录槽。

#### F. 身体定位升级

- 首屏保留正面/背面中性轮廓和大部位热区。
- 选择大部位后进入局部图，而不是在全身图中继续堆叠小目标。
- 明确显示用户自己的左右方向，避免观察者左右混淆。
- “说不清 / 范围不确定”作为同等级选择，不强迫用户精确定位。
- 选择结果以文本芯片同步呈现，使颜色和图形之外仍有明确确认。

#### G. 测量趋势

- 体温等时间序列优先使用“数值卡 + 简短趋势 + 折线/点图”。
- 图中每个数据点提供时间、数值、测量部位和来源。
- 关键值始终在图外以文字显示；拖动或悬停只用于补充细节。
- 不由前端颜色自行判断正常/异常；风险解释使用后端确认的临床规则结果。

### P2：建立智能体工作区

#### H. 对话与结果并列

- 桌面端借鉴 Canvas/Artifacts：左侧保留对话，右侧显示当前摘要、报告、图表或文件。
- 用户可选中右侧具体字段要求修改；修改请求回到受控工具，不直接编辑医疗事实存储。
- 移动端不做双栏，使用可返回的全屏结果页或底部抽屉。
- 结果对象保留版本、来源和最近更新时间，避免 AI 每轮生成一个不可追踪的新副本。

#### I. 智能体过程反馈

- 只显示对用户有帮助的状态：正在整理、等待你确认、正在执行、需要处理、已完成。
- 长任务显示已完成的真实阶段和可取消入口，不显示没有依据的百分比或剩余时间。
- 失败时提供“发生了什么、已保留什么、现在可以做什么”三段式恢复卡。
- 技术日志、模型调用和内部智能体树继续只出现在研发视图。

## 6. 明确不采用的方向

- 不加入持续出现的医生头像、拟人助手或夸张表情。
- 不使用 3D 人体、写实皮肤或可能让用户误认为诊断成像的视觉。
- 不让模型生成任意 HTML、任意颜色或新的医疗操作流程。
- 不把重要风险、关键数值或下一步只放在悬停、动画或折叠层中。
- 不用大量徽标表示细微状态；优先使用清楚的标题和动作语言。
- 不为了“更智能”展示思维链、内部推理或多智能体对话。
- 不用不确定的进度百分比和完成时间制造虚假确定性。

## 7. 视觉规范建议

| 项目 | 建议 |
| --- | --- |
| 主色 | 现有深绿继续用于主操作与品牌，不同时承担“正常”的医学含义 |
| 风险色 | 红色仅用于立即行动；琥珀用于需要注意；每种状态同时配图标和文字 |
| 背景 | 任务区域使用单一浅背景，减少卡片套卡片和多层边框 |
| 字号 | 当前动作 24–28px；核心数值 36–44px；正文不低于 16px；辅助文字不低于 13px |
| 间距 | 以 8px 网格为基础；同一任务中的主操作位置保持稳定 |
| 动效 | 只用于步骤切换、保存成功和状态变化；支持 `prefers-reduced-motion` |
| 图标 | 使用统一线宽的功能图标；图标不单独承载含义 |
| 图示 | 中性轮廓、局部优先、明确接触点；不塑造角色形象 |

## 8. 验收方法

每个阶段同时做行为、视觉和可访问性验证：

1. 用户是否能在 3 秒内说出当前需要做的动作。
2. 是否能在不阅读展开说明的情况下完成主要路径。
3. 是否能正确跳过、取消、返回、修改和恢复。
4. 关键行动是否在不依赖颜色、动画和鼠标悬停时仍然明确。
5. 键盘焦点顺序、屏幕阅读器状态播报和 44px 目标是否通过。
6. 320px、常见桌面宽度、短窗口和 Windows 125%–200% 缩放是否通过。
7. 患者视图是否完全隐藏技术日志、模型调用和内部智能体状态。
8. 视觉变化是否保持事实来源、风险规则和观察结果的数据契约不变。

建议先完成 P0 的任务聚焦、风险卡和核对闭环，再进入图示重绘。这样可以先解决注意力分散和错误恢复，再用统一框架承载新的自检图形。
