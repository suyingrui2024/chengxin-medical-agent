# 知识库与知识图谱：现状与数据缺口

> 2026-10-28。本文记录**已建成的机制**与**尚未拿到的数据**，两者不要混为一谈。

## 一、建成了什么

`src/medagent/kg/` —— 一个受治理的概念存储，不是图数据库。

| 文件 | 职责 |
|---|---|
| `store.py` | SQLite 三张表：concept / alias / relation；来源与审核状态**不可为空** |
| `normalize.py` | 最长匹配分词，返回**带位置的命中**，不只是概念集合 |
| `seed.py` | 从仓库既有内容生成种子，不发明任何临床内容 |
| `loaders.py` | 外部术语表的导入器（TSV / 纯列表） |

**为什么不是图数据库**：本项目是本地单机应用，已有 Python 运行时。为几百到几万条三元组引入 Neo4j 或 NebulaGraph，运维成本远超收益。SQLite 是标准库，随包分发，零依赖。

**为什么 relation 表现在是空的**：关系（症状 → 疾病）是临床判断，必须来自已审来源。种子阶段凭空补边，等于给"没有来源的断言"披上数据结构的外衣。

## 三、口语说法：已打通一半

**做法**：`red_flags.json` 的正则里本来就写着患者的说法（`叫不醒`、`抽风`、`嘴唇发紫`、`上不来气`、`呕血`）。`scripts/build/derive_alias_candidates.py` 把这些字面量抽出来，作为红旗概念的别名。

**为什么这不是编造**：产品每一轮都在用这些正则做决策。把「叫不醒」登记为 unresponsive 的别名，只是让概念层承认规则层已经认定的事实，没有新增任何临床断言。

**效果**：红旗语料覆盖率 **32% → 65%**，只用了 25 条别名。

**再加一层：模型提议（`model-aliases.tsv`）**。剩余 13 条漏识别交给子智能体，约束「只能从库里 585 个规范术语里原样选一个，不确定就填 null」。结果 **12/13 映射成功，1 条正确拒绝**——拒的正是「心口窝疼」（可能指上腹也可能指心前区）。人工截取最小子串后覆盖率到 **97%**。

⚠️ **97% 是样本内数字**：别名正是从这 13 条句子里抽的，再在同一批上打分。它衡量的是回归风险，不是泛化能力。真实水平在 65%–97% 之间，需要留出集才能确定。

**代价**：否定样本命中率 67% → 78%。别名多了，否定句里也会命中——但否定判断由红旗层单独处理（`negation_exempt_patterns`），概念层不做这件事。

**审核面**：`data/kg/candidates/triage-aliases.tsv` 是人工审核入口，把某行标成 `rejected` 就不再加载。默认加载，因为不加载等于概念层无视产品已经在用的说法。

## 四、歧义追问：判定已实现，接线未做

模型无法映射的说法（如「心口窝」）可以追问患者，但**顺序不能错**。

实测发现：

| 输入 | 红旗 | 该怎么做 |
|---|---|---|
| 心口窝疼得厉害，一阵一阵冒汗 | **已触发** | 立即升级，**不许追问** |
| 心口窝有点不舒服 | 未触发 | 追问「胸口还是上腹」 |

`medagent/kg/ambiguity.py` 实现了这条判定：红旗非空即返回 None，只有「无红旗 + 部位歧义 + 有主诉标记」才提议追问。结果以 `kg.ambiguous` 事件记录，**不改变任何决策**。

为什么只记录不接线：往问诊流程里插一个问题属于临床交互变更，要评审。判定逻辑先跑起来，等真实对话积累后再决定接不接。

## 五、仍然存在的缺口

**1. 一半的口语说法仍然匹配不到。** 25 条覆盖了红旗这一块，但「心口疼」→「胸痛」这类非红旗表述仍无来源。剩下的是问诊主诉用语，任何公开数据集都不提供。

**2. 官方术语表拿不到。** 卫健委《常用临床医学名词（2023年版）》是 385 MB 纯扫描件（`/Font` 0、`/Image` 3878、`/ToUnicode` 0），只能 OCR；医学术语的 OCR 错字不可接受。

**3. ICD-10 层级未建模。** 章/节是分组节点、本身不是概念，为避免悬空引用，层级边未导入。

**4. 全部导入数据是 `imported_pending_review`。** Wikidata 由社区维护，ICD 编码也不等于诊断标准。这份库只能用于术语归一与候选提示，**不能支撑临床决策**。


```python
from medagent.kg import ConceptStore, Normalizer, seed

store = seed.build(registry)          # 或 ConceptStore.open("kg.db")
normalizer = Normalizer(store)
normalizer.find("我这几天心口疼")      # -> [Match(start=4, end=7, text='心口疼', ...)]
```

`find()` 返回 `start/end`，调用方可以高亮命中的原文——本产品必须能解释自己为什么这么理解，不能悄悄替换概念。
