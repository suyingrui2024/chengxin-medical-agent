# 可视化简化设计文档

> 版本：v1.0（2026-10-24）；状态：**仅设计，未实施**。本文档不改任何产品代码，
> 实施前需用户批准；批准后按 §4 分阶段实施，每阶段过 §4 的验收才算完成。
> 目标：达到 Muse 这类产品的水准——只有一个主面，对话占绝对主导，其他一切
> 藏起来、只在需要时出现一层；层级靠留白和字号撑，不靠面板和色块撑。
> 范围：桌面端视口（视觉走查默认 1440×900）；不做移动端适配。

## 0. 参照标准：什么叫“Muse 式简洁”

本文档用以下可操作定义代替“感觉更简洁”，实施验收以 §4 的数字为准：

1. **一个主面**：任一时刻，屏幕上只有一个信息主面（问诊时是对话，结论时是结论）。
2. **一个主动作**：任一状态只有一个视觉主按钮；其他动作是安静的文本按钮或菜单项。
3. **渐进披露**：次要信息默认收起或退到下一层，到达任一功能不超过 2 次点击。
4. **横幅至多一条**：同一时刻问诊页顶部至多出现一条横幅，按优先级取胜者，其余排队或折叠。
5. **患者视角**：患者默认界面不出现开发者口径（指标、模式、运行记录、协议版本）。

### 1.2 结论卡：字段陈列，不是叙事

结论卡渲染（`src/medagent/web/structured-ui.js:1736-1948`）默认把 composer 的全部字段
一次性平铺为带标题的区段：

| 顺序 | 区段 | 来源 |
|---|---|---|
| 1 | 问诊结论 kicker + 处置（级别色标 + 文本 + 窗口） | `structured-ui.js:1736-1755` |
| 2 | 叙事（定性句 + 程度句 + 推理段，推理段仅 directions_visible 时出现） | `:1758-1788` |
| 3 | 可能的方向（仅 directions_visible 时出现，含弃权文案） | `:1791-` |
| 4 | 还缺的信息（每条含 label + impact） | gaps 区 |
| 5 | 现在能做的事（do / avoid / measure 分组 + 过敏提示） | `:1854-1872`，过敏提示 `:1870` |
| 6 | 出现以下情况请立即就医（return_now_if） | `:1876-1888` |
| 7 | 接下来（outlook + 随访到期文案） | `:1889-1901` |
| 8 | 延伸阅读（链接 + 引用句） | reading 区 |
| 9 | 就诊提示 + 免责声明 | `:1940-1948` |

**为什么挤**：每个字段各配一个 `h4` 标题和一套边框/底色，9 个区段等于 9 次“请注意我”；
处置、叙事、方向三者说的其实是同一件事（结论是什么、为什么、还有哪些可能），却以
三个并列区块出现；“还缺的信息”在问诊刚结束、用户最需要安心时，以清单形式先于
“现在能做的事”出现，情绪顺序也是反的。

### 1.6 视觉走查：能发现“坏了”，发现不了“挤了”

走查树（`tools/visual-audit/audit.mjs:284-791`）共 30 节点：落地页、问诊各步骤、
摘要待确认、对话记录展开、已记录信息抽屉、已关闭结论单、会谈记录列表、健康档案页、
记录血糖、上传图片、设置外观、模型服务配置、主题变体、研发态 5 节点。走查只断言
“到达、横向溢出、问诊面板宽度是否被收缩”（`audit.mjs:1-20`），不度量默认可见块数、
点击深度、信息层级。因此 29/30 通过与“感觉挤”可以同时成立——走查是几何门禁，
不是简洁门禁，简化实施必须另补 §4 的指标。

### 1.7 最挤的三处（核心判断）

1. **结论卡 9 区全展开**（§1.2）：用户最需要一句话的时刻，给了九段话；且处置/叙事/
   方向三重表达同一结论。
2. **问诊页的叠加层**（§1.1）：页眉 4 层 + 欢迎插画卡片 + 抽屉 7 样 + 可叠加横幅，
   对话主面被围在中间。
3. **设置页的子智能体运维面板**（§1.5）：患者产品里出现指标与回退按钮，是视角错位，
   不是排版问题；只靠调样式修不好，必须退到开发者层。

## 2. 简化原则

### 2.1 渐进披露规则（实施时逐条对照）

1. **默认只剩主面与主动作**：问诊默认可见 = 对话消息 + 输入框 + 一个主按钮
   （开始问诊 / 发送）；其余一切默认收起、折叠或退到下一层。
2. **收起要有计数，不要静默消失**：收起的区段标题行保留，带数量（如“还缺的信息 · 3”、
   “现在能做的事 · 5”），点击展开；展开状态用 `aria-expanded` 表达，键盘可操作。
3. **横幅至多一条，按优先级取胜**：紧急求助 > 连接异常 > 再分诊提示 > 基线引用提示。
   落选横幅不丢弃：折叠为抽屉顶部或对话内一行小字；基线引用提示在同一会话内只
   出现一次，关闭后不再以横幅出现（抽屉顶部留一行“已参考档案”即可）。
4. **低频操作退到拥有它的卡片里**：用药提醒时间不在随访列表后单列一块，收进对应
   随访卡片的展开区；档案基线表单不在档案页首屏全展开，收进“我的基线”折叠区。
5. **开发者内容退到开发者层**：患者默认界面不出现指标、模式、运行记录、协议版本；
   需要时进研发模式（现有 `developer-only` 门控，`styles.css:1010`）或设置页内默认
   收起的“高级”区。
6. **层级靠字号与留白，不靠色块**：区段之间用间距分隔，不用每个区段配边框/底色/
   图标；颜色只保留三档处置色与分级色点（红/黄/绿/灰），其余一律中性色。
7. **一屏一标题**：每个视图只有一个视觉主标题；页眉的英文 eyebrow、副标题、提示行
   合并为至多一行说明，隐私提示退为输入区下方一行小字。

### 2.2 不变的红线

- **K1–K8 问诊内核不动**：不改问题选择、红旗判定、处置计算、结论拼装逻辑；
  本文档只改前端呈现层级与披露状态。
- **方向/科室 shadow 门控不动**：只改“可见时如何排布”，不改“何时可见”；
  `directions_visible` / `department_visible` 的判定与 P1 裁定原样保留，
  narrative.reasoning 的门控（`structured-ui.js:1776`）同样原样保留。
- **不删功能，只改披露与层级**：结论卡 9 区、档案 4 区、设置 4 区的信息一个不少，
  全部在 2 次点击内可达；删除任何信息都需另行立项，不在本设计内。
- **桌面视口**：以 1440×900 走查视口为准；不引入移动端断点与手势交互。
- **无障碍不降级**：收起/展开必须键盘可达、有焦点样式、有 `aria-expanded`；
  颜色不作为唯一信息载体（分级色点旁保留文字，现状已做到，保留）。

## 3. 分面方案

### 3.1 问诊主面

- **页眉**：去掉英文 eyebrow 与独立描述段；保留一行标题（“先说说，哪里不舒服？”）+
  一行说明；隐私提示（勿输身份信息）移到输入区下方小字，与 composer-note 合并为一行。
- **顶栏面包屑**：并入侧栏顶部或去掉；问诊视图内不再单独占一层。
- **欢迎态**：去掉轨道插画与 mini-tag，保留标题 + 一行说明 + 主按钮；两张 starter 卡片
  降为两行安静的文本链接（“最近有些不舒服 →”“替家人问一问 →”），不再用卡片色块。
- **输入区**：composer-context 提示行只在会话开始前出现一次，问诊开始后隐藏；
  composer-note 只保留字数统计，Enter 提示并入输入框 placeholder。
- **事实抽屉**：保留滑入抽屉（披露方式已对），内容缩减为两样：事实列表 + 报告项摘要。
  移出项去向：当前步骤块 → 对话内已有“当前这一步”消息，不再重复；来源图例与更正提示 →
  合并为列表底部一行小字；“添加报告内容 / 就诊交接摘要”按钮 → 结论卡底部操作区；
  删除 → 会谈记录条目菜单；“查看本次运行记录”已是 developer-only，保持。
- **横幅**：按 §2.1 第 3 条取胜者；基线引用提示首次出现后，用户关闭即在本会话内
  不再以横幅出现，抽屉顶部留一行“已参考档案（慢病/过敏/用药）”。

### 3.2 结论卡：默认只展开两段，其余收起带计数

默认展开（唯一展开项是处置与叙事，理由：用户最先需要“结论是什么 + 为什么”）：

1. **处置**：级别色标 + 一行处置文本 + 窗口。保留三档色（urgent 改红后的既有语义不变）。
2. **叙事**：定性句 + 程度句（两段，不配小标题）。

默认收起（标题行 + 计数，点击展开；展开后内容与现状一字不改）：

3. 可能的方向（仅 directions_visible 时存在；shadow 下该行根本不出现，不留“已隐藏”占位）。
4. 还缺的信息 · N。
5. 现在能做的事 · N（含 do / avoid / measure / 过敏提示，现状分组保留，展开后可见）。
6. 出现以下情况请立即就医（return_now_if）——例外：处置为 urgent_today 时本区默认展开，
   因为此时它是主动作而非次要信息。
7. 接下来（outlook + 随访到期文案）。
8. 延伸阅读。
9. 底部操作区：就诊交接摘要 / 打印 / 导出 / 添加报告内容（从抽屉移入，见 §3.1）+
   免责声明一行小字。

信息无丢失对照：收起只是 `hidden` + `aria-expanded=false`，DOM 内仍可达；验收时用
脚本断言 9 区字段在展开后与现状逐字一致（见 §4）。

### 3.3 健康档案页：时间线为主面，其余折叠

- **默认主面 = 时间线**：条目按时间倒序，条目行只显示类型、标题、时间与状态
  （已解读徽标保留，因它是条目状态而非新区块）。
- **基线表单**：收进“我的基线”折叠区（默认收起，标题行带“已填写 / 未填写”状态）；
  展开后表单与现状一致。
- **成员列表**：收进“家庭成员”折叠区，行只显示姓名与“本次问诊对象”状态；
  切换/改名/归档在行内展开或菜单中，不再平铺操作按钮。
- **趋势区**：按测量类型折叠（血糖 / 血压 / 体温 / 体重 / 血氧各一行，带最新值与时间），
  展开后见现状趋势图与描述性统计（统计口径不变，只作记录、不下判断）。
- **条目详情对话框**：转录观测默认展开；解读节默认收起，标题行带分级色点与等级文字
  （如“解读 · 黄”），点击展开见完整解释与行动；问诊带入面板收进详情底部“带入本次问诊”
  折叠区；测量弹窗保持模态（已是按需出现，不动）。
- **顶部操作**：记录血糖 / 上传检查图片保留为主按钮区的两个安静按钮，不再配提示条；
  `#records-notice` 只在有待处理事项（如识别失败）时出现。

### 3.4 会谈记录、随访与用药：随访卡片是唯一主角

- 会谈记录视图默认只显示历史列表；随访区保留，但每张随访卡片默认只显示到期与原因
  两行，操作（记录结局、发起再分诊）收进卡片内展开区。

### 3.5 设置页：患者设置与开发者设置分层

- **患者设置（默认展开）**：外观（主题与字号保留，但 6 套主题以紧凑列表呈现，
  不再每套配大色板预览）/ 模型服务 / 界面与数据（去掉禁用的“测试视图”占位控件，
  该入口只在研发模式下出现）。
- **开发者设置（默认收起的“高级”区，患者模式下整个区不渲染，与现有
  `developer-only` 门控一致）**：子智能体四类模式 + 指标文本 + 全部回退按钮。
  指标文本只在高级区展开后加载（现状 `app.js:2942` 的 best-effort 拉取保留，
  但不再在患者设置页触发请求）。
- **版本与协议行**：从侧栏底部移出，只在高级区底部以一行小字出现。

### 3.6 视觉语言收敛（跨面通用）

- 区段分隔：间距 + 一条细分割线（或纯间距），不用卡片套卡片；结论卡本身保留一张卡，
  卡内各区不再各自成卡。
- 标题层级：视图主标题 20–22px；区段标题 15px 半粗体；正文 15–16px；次要说明
  14px 弱色。现状 6623 行的 `styles.css` 不新增色板与字阶，只复用既有 token。
- 主按钮：每视图至多一个实心主按钮；其余动作用文本按钮；危险操作（删除、归档）
  用弱色文本按钮，不用红色实心按钮。
- 插画与装饰：欢迎态插画与轨道装饰删除后不再补同类装饰；品牌只保留侧栏与登录态
  的一处标识，不在每个视图重复出现。
