- 为孩子或家人代问时，后续信息标记为照护者来源；
- 呼吸道定向问题结束后、背景采集前调用适用的体温任务；
- 跳过任务保存为未知且未执行；
- 用户报告 40℃以上读数触发升级路径，来源和质量不自动升级为设备直连；
- 更正产生新事实并保留被替代事实；
- 插件卸载撤销其服务注册。
- 一轮多个字段可以同时提议，并保留连续原文引文；无效事实批次不写入；
- 同一批次字段顺序不改变照护者来源；年龄数值必须符合原文；
- 未注册工具拒绝执行，工具返回错误后可重新规划；
- 摘要提前结束被拒绝，摘要核对后才完成；
- 后端失败明确显示，重试使用原始患者输入；
- 每轮调用次数、事实写入次数、主题澄清次数有上限；
- 同一问题重复展示也产生新的动作版本；
- 症状更正使依赖观察失效，历史仍保留；
- 真实 DSH 请求不包含宿主工具，也不额外上传会话日志或插件清单；
- 患者 API 经真实 DSH 完成多事实更新后，危险输入不再请求模型。
- 图形界面可以完成演示问诊、图示翻步、摘要回看、真实事件筛选和记录导出；
- 图形化连接配置不回显密钥，配置变更保留旧会谈，非法配置不替换有效后端；
- 图库预览不会创建会谈或写入观察；手机视口没有横向溢出；
- 事实更正保留原值；响应丢失后读取已保存进度，患者输入按普通文本展示。
- 独立 Electron 窗口可完成问诊、配置和图示预览；无桌面凭证的请求被拒绝，退出后私有服务回收。桌面测试需要系统图形会话。

界面的实际截图、评审路径和数据限制见 [图形界面设计与检查](图形界面设计与检查.md)。测试截图使用离线演示与合成病例；真实模型仍需单独评价。

## 2. 工程验收门

进入任何用户研究前，以下条件必须全部满足：

| 类别 | 必须达到的条件 |
| --- | --- |
| 状态 | 缺失、未知、否认、完成失败和低质量观察在序列化后仍可区分 |
| 并发 | 普通并发输入拒绝混写；紧急输入及主动求助可优先处理中断等待；迟到结果不得覆盖状态；不同会谈互不污染 |
| 事件 | 所有患者输入、事实更新、风险评估、模型选择、自查和系统回复可按会话重放 |
| 模型失效 | 超时、非 JSON、越权动作和服务不可用明确返回错误或重新规划，不静默退成演示，不阻断输入急症门 |
| 内容 | 问题、规则、图示和任务各有明确版本；摘要能指出使用版本 |
| 接口 | 无效 JSON、空消息、超限请求、无效会话和不可编辑字段返回明确错误 |
| 前端 | 动态患者内容不进入 `innerHTML`；键盘可完成主要流程；紧急提示不依赖颜色理解 |
| 数据 | 默认无持久化；启用日志时明确位置、权限、保留期和删除方式 |

建议增加属性测试或模糊测试，重点验证任何输入都不会让运行时抛出未处理异常，不会把 `unknown` 自动转成 `absent`，也不会在急症关闭后继续普通问诊。

## 3. 标准化病例集

由至少两名具有相关临床经验的审核者共同编写病例蓝图，并在开发集、冻结测试集和最终盲测集之间隔离。每个病例不只给最终诊断，而要标注：

- 患者开场会主动说出的信息；
- 只有被问到才提供的信息；
- 必须获得、可选获得和不应询问的信息；
- 会改变分流或下一问的答案；
- 明确危险信号及其否定、含糊和间接说法；
- 患者可能出现的纠错、跳过、跑题和情绪表达；
- 可调用的自查任务、停止条件和允许用途；
- 理想结束条件及不允许出现的结论。

首轮建议先做 60 个病例：20 个通用主诉，20 个发热/呼吸道主诉，10 个急症中断，10 个高混淆或纠错病例。每个蓝图至少生成两种表达，避免测试只记住固定词语。

## 4. 问诊对照实验

保持底层模型一致，比较：

1. 通用聊天提示；
2. 固定问卷；
3. 当前结构化状态与固定问题顺序；
4. 相同医疗工具控制器与直接模型后端；
5. 相同医疗工具控制器与 DSH 后端；
6. 经临床审核后的内容版本。

直接模型与 DSH 组必须核对底层模型、协议、提示和上下文是否相同。DSH 适配器可能支持不同协议，未对齐的比较只能评价整个配置，不能把差异归因于框架本身。额外报告端到端延迟、模型请求数、输入输出 token、工具拒绝率和重试率。

主要指标分别报告：

- 必要信息召回率；
- 无关或重复问题数量；
- 危险信号正确升级率及误升级率；
- 阴性、未知和来源记录错误率；
- 在信息尚不充分时结束的比例；
- 交互轮数、用时和患者主观负担；
- 摘要与会谈事实的一致性；
- 发生更正后，下游依赖结论被正确失效的比例。

临床审核者应在不知道实验组的情况下评分。不能只让另一个语言模型充当裁判；模型评分可以做预筛，但需与人工评价的一致性单独报告。

## 5. 图示自查实验

体温任务先比较三组：同内容短文字、图文卡片、图文加可选短动画。任务使用相同数字体温计类型和相同测量标准，避免设备差异掩盖说明效果。

每位参与者完成后测量：

- 不求助时的正确完成率；
- 关键步骤遗漏与顺序错误；
- 测量方法、部位和时间能否正确记录；
- 因不理解、设备不可用、不适或其他原因退出的比例；
- 完成时间、主观负担和之后能否复述关键点；
- 重复测量与研究人员参考操作的差异。

参与者点击“完成”不能作为操作正确。研究人员应根据预先定义的可观察标准盲评。图示涉及的左右、探头位置、姿势和设备说明需先由临床人员及目标设备专家审核。

## 6. 视觉核验的进入条件

只有固定任务本身通过用户研究后，才训练或接入视觉核验。按顺序验证：

1. 相机是否拍到需要的区域，光线和遮挡是否允许判断；
2. 已定义动作的可见条件是否满足；
3. 数值估计相对参考测量的误差；
4. 观察结果是否真正改善后续判断。

每一级必须允许返回“无法判断”。前一级未通过时不得进入后一级，也不得以动作外观正确推断医学体征阴性。

## 7. 安全停止条件

出现以下任何情况，应停止真实用户扩大试验并复核：

- 明确急症输入后仍继续普通问诊；
- 将未知、未做或低质量观察写成阴性；
- 模型绕过允许问题集合或修改确定性风险结果；
- 自查导致伤害、近失事件或明显延误求助；
- 摘要虚构用户未提供的药物、过敏、病史或测量值；
- 未经同意将真实健康信息发送到外部模型或写入持久日志；
- 同一会话的并发写入造成事实顺序或归属错误。

停止后保留相关事件轨迹和内容版本，在修复、根因分析和新增回归病例完成前不恢复该路径。

## 15. v0.9.5 患者计算确认
