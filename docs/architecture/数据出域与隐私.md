# 数据出域与隐私（现状审计）

> **状态：实测审计（2026-11-04）。** 每一条陈述都对应本仓库当前代码的
> 具体位置，不是设计承诺。设计与硬规则的出处：
> [联网与子智能体工具设计](../features/联网与子智能体工具设计.md) §4.4、
> [患者纵向医疗数据与图片识别归档设计](../features/患者纵向医疗数据与图片识别归档设计.md) §12。
> 行为层由 `tests/architecture/test_data_egress.py` 与
> `tests/subagents/test_web_tools.py` 钉住。

## 1. 一句话结论

患者数据离开本机的**唯一常态通道是问诊决策的消息体**——这是产品的
功能本身（把患者的话交给问诊模型）。除此之外的每一条出站路径
（图片识别、联网搜索、联网抓取、连接测试）都是显式开关或脱敏闸门
之后的；事件日志、患者档案、会话记录全部只落在本地。

## 2. 出域清单（什么出、去哪、何时）

| 路径 | 出什么 | 去哪 | 何时 | 闸门 |
|---|---|---|---|---|
| 问诊决策 | 对话消息（含患者原话、结构化事实） | 模型端点（见 §4） | 每轮问诊 | 端点必须 HTTPS 或回环；事件只记元数据 |
| 图片识别 | 图片 + 固定识别提示词 | 已配置的视觉端点 | 仅当部署显式配置了视觉模型 | 离线模式明确"不发送图片"；URL 禁带凭据/查询串 |
| 联网搜索 | 检索 query | 模型供应商的搜索工具 | 仅 `MEDAGENT_WEB_TOOLS` 开启且日预算内 | `scrub_free_query`：PII 正则删除 + 病例原文片段命中即**整条拒绝** |
| 联网抓取 | URL | 注册域名 | 同上 | SSRF 校验：仅 https 公网、私网/回环 IP 拒、每跳重定向复检、≤256KB |
| 连接测试 | 固定探测消息 | 模型端点 | 设置页点"测试" | 消息即 `Connection test. No patient data.` |

## 3. 明确不出域的东西

| 数据 | 在哪 | 保护 |
|---|---|---|
| 事件日志 | 本地 `events.jsonl` | `model.requested` 只存 backend/model/字数/`content_sha256`——**完整 prompt 曾被逐字写入，已改**（`infra/backends.py::request_event_payload`）；被拒的搜索 query 不进 `web.blocked` 事件 |
| 患者档案 | 本地 `patients.sqlite3` | 从不出站；所有写入先过 `patient_records/validation.py` |
| 会话记录 | 本地会话目录 | 模型密钥在持久化前被 scrub、自由文本限长（`execution/session.py::persist`） |
| 模型调用的完整审计 | 无默认路径 | `review/audit_recording.py` 需审计工具**显式**传 directory，生产接线不存在 |
| 执行工作区 | 本地 `MEDAGENT_EXECUTION_ROOT` | worker 环境是白名单（PATH/locale/无凭据代理），回环地址钉进 `NO_PROXY` |

## 4. 模型端点的两种部署

- **`compatible`**：进程内直连 `MEDAGENT_LLM_BASE_URL + /chat/completions`，
  API key 走 `Authorization` 头。端点在装配时被
  `require_https_or_loopback_endpoint` 检查（明文远程拒绝），重定向
  **一律不跟随**（一次重定向就能把 Authorization 头带去别处）。
- **`dsh`**：消息以 JSON 走 stdin 交给 DSH 桥进程——患者的话是数据，
  永远不进命令行参数。桥的错误码是白名单短 token，**从不携带
  error.message**（那可能含 prompt 与患者数据）。

## 5. 联网搜索的脱敏管线（§4.4 硬规则）

三条搜索路径，全部收口在 `WebTools.search` 的**内置闸门**：

1. **患者教育**：`build_education_query` 受控词表拼装，患者原文不参与。
2. **指南复核**：`scrub_free_query` 预脱敏——删邮箱/身份证/手机号/
   绝对日期/精确年龄；脱敏后仍命中病例原文片段（≥8 字连续子串，
   片段表 = 主诉取值 + 全部 fact evidence）→ 整条拒绝，落 `web.blocked`。
3. **subagent**：query 来自模型 arguments，因此 `WebTools.search`
   在方法内先过同一管线（fail-closed），调用方必须传入
   `patient_query_fragments(state)` 的片段表——这正是**曾经缺失**
   的一条：分支视图可以携带 evidence 原话，模型把它们编进搜索词
   就等于把患者的话发给检索供应商。2026-11-04 起由架构门禁钉住。

## 6. 本地落盘边界

| 环境变量 | 缺省 | 放什么 |
|---|---|---|
| `MEDAGENT_PATIENT_DATA_DIR` | `<应用数据>/Chengxin/patient-data` | 患者档案 sqlite、图片资产 |
| `MEDAGENT_SESSION_DATA_DIR` | `events.jsonl` 同级 | 会话记录与事件日志 |
| `MEDAGENT_EXECUTION_ROOT` | `<source>/workspaces` | 执行工作台的项目目录 |

除此之外，进程会写的患者相关位置只有 DSH 桥的一次性临时目录
（`TemporaryDirectory`，桥结束即删）。没有遥测、没有崩溃上报、
没有第三方统计。

## 7. 门禁（改代码时会被这些拦住）

| 门禁 | 拦什么 |
|---|---|
| `tests/architecture/test_data_egress.py` | ① `model.requested` 事件负载元数据化（不许存回 prompt 全文）；② 每个 `.search(` 调用点在白名单内，且 query 出自受控构造或传入片段表；③ 出站片段表只有 `patient_query_fragments` 一份定义 |
| `tests/subagents/test_web_tools.py` | 行为：命中片段 → `query_blocked`、零外发请求、`web.blocked` 不带 query 原文；PII 从 `query_as_sent` 与外发消息体中删除；干净 query 原样通过 |

## 8. 残余风险（诚实的边界）

- **fetch 的 URL 内容**：SSRF 校验管的是"去哪"，不管 URL 查询参数里
  被模型塞了什么。缓解：URL 只能来自搜索结果（引用真实性靠结构纪律），
  且搜索 query 已脱敏；但"模型拼一个带参数的 URL"这条路径没有内容级
  检查。
- **模型供应商侧留存**：消息离开本机之后供应商如何保留、是否用于
  训练，代码无法约束——这是部署者的合同问题，不是代码问题。
- **姓名识别靠片段表兜底**：规则无法可靠识别中文姓名，
  `forbidden_fragments`（主诉与 evidence 原话）是兜底；一段既不在
  结构化字段里、也不出现在 evidence 里的自由文本姓名，规则层看不见。
