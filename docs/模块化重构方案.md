# 知微项目模块化重构方案

> 状态：待评审（仅方案，未改代码）
> 目标：把 9 个"巨无霸"文件按职责拆开，降低耦合与冲突面，使后续维护可独立进行；同时建立"防回潮"机制，避免再次膨胀。
> 原则：对外接口面极小 → 可保留公开名重导出，测试几乎零改动。

---

## 1. 现状证据（实测）

后端 `src/medagent/` 共 91 个模块，已有清晰的子包边界（`kg/` 7 模块、`extensions/` 14 模块、`content/`）。问题集中在 6 个超大文件：

| 文件 | 行数 | 内部构成（实测顶层定义） |
|------|------|--------------------------|
| `consultation.py` | 3,481 | `ConsultationEngine` 类 + `UserInput` 数据类 + 拒绝/合并文本归一化函数群 |
| `agent.py` | 3,093 | `AdaptiveConsultationEngine` + 信封纠错 + 能力广告 + 拒绝项剥离 |
| `server.py` | 2,468 | `MedicalAgentServer` / `Handler` + 用药计划 + 状态持久化 |
| `conclusion.py` | 2,389 | `compose_conclusion` + 叙述/去向/调整/目标处理等纯函数群 |
| `patient_records.py` | 1,748 | `PatientRecordStore` + 校验 + 患者/条目/趋势 CRUD |
| `subagents.py` | 1,715 | `SubagentCoordinator` + 内容索引 + 知识检索 + token 估算 |

前端 `web/`：`structured-ui.js` 10,780 行（卡片渲染）、`app.js` 129KB（主控制器）、`styles.css` 140KB（全站样式）。

**关键利好——对外接口面极小**（实测外部导入）：

```
consultation → ConsultationEngine, StaleActionError, UserInput
agent        → AdaptiveConsultationEngine
conclusion   → BANNED_PHRASES, chief_matches_pathway, format_window_text,
               spoken_close_line, PRIOR_RANK, _self_care_group
patient_records → PatientRecordError, PatientRecordConflict, default_patient_data_root
server       → main, Handler, MedicalAgentServer
```

含义：拆分内部实现、在原路径做**重导出 shim**，外部与测试无需改动（测试仅依赖上述名字 + `from medagent import conclusion as m` 模块引用）。

---

## 2. 总原则

1. **保留公开名重导出**：把 `consultation.py` / `conclusion.py` 改为同名**包**，`__init__.py` 重导出所有被外部/测试引用的名字（`ConsultationEngine`、`UserInput`、`_self_care_group`、`compose_conclusion` 等）。其余文件（agent/server/patient_records/subagents）拆出子模块后，在原文件顶部做 `from .x import *` 式重导出，或直接更新约 20 个 import 站点（均为相对 import，改动极小）。
2. **测试零改动优先**：凡测试 import 的私有名（`UserInput`、`_self_care_group` 等）一律随包 `__init__` 保留。
3. **分阶段、可回滚**：每个文件独立成一步，每步后跑 `pytest` + `playwright.ci.config.mjs` 全量套件（已有 338 用例）。
4. **每新文件头部加一句职责注释**，沿用本项目"设计文档驱动"的纪律（参照《问诊结论单设计文档》）。

**`subagents/` 包**

### P1 — 引擎与编排（外部依赖基类 + 异常）

**`consultation/` 包**（与上面 conclusion 同级，但这里指引擎本体）
- `consultation/engine.py`：`ConsultationEngine` 生命周期（open/answer/close）、状态机

- `consultation/transitions.py`：状态转移辅助

**`agent/` 包**
- `agent/engine.py`：`AdaptiveConsultationEngine(ConsultationEngine)`
- `agent/envelope.py`：`_decision_envelope_guidance`、`_recorded_denies_token`、`_strip_denied_items`
- `agent/capabilities.py`：`_capability_advertisement` + 能力分发

### P2 — 前端（已确认 `type="module"`，直接 export/import）

**`web/components/`** —— 按卡片类型拆分 `structured-ui.js`：
- `cards/summary-card.js`、`cards/conclusion-card.js`、`cards/observation-card.js`
- `cards/scale-form.js`、`cards/formula-form.js`、`cards/illustration.js`、`cards/emergency.js`
- `structured-ui.js` 退化为编排器：导入各卡片渲染函数并按 payload 类型分发
- 公开契约：每个卡片模块 `export function renderXxxCard(ctx)`，`structured-ui.js` 维持现有对外函数名（供 `app.js` 调用）

**`web/app/`** —— 拆分 `app.js`（风险较高，放最后）：
- `app/session.js`（会话生命周期）、`app/render.js`（渲染调度）、`app/settings.js`、`app/followups.js`、`app/desktop-bridge.js`
- 以 `app.js` 作为入口，按现有 `import` 重组，不改 HTML 加载顺序

### P3 — 最高风险，最后做，带兼容层

**`server.py`**：`Handler` 内路由共享实例状态（`self.engine`/`self.store`）。
- 抽 `server/medication.py`、`server/persistence.py` 低风险先行；
- 路由拆分建议引入**上下文对象**（`ctx`）替代散落的 `self.*`，再按咨询/记录/工作区/工具分组挂载，保留 `Handler`/`MedicalAgentServer`/`serve`/`main` 公开名。

**`styles.css`**：已自带分节注释，按表面拆分：
- `styles/base.css`、`layout.css`、`components.css`（卡片）、`forms.css`、`settings.css`、`emergency.css`、`desktop.css`
- 由主 `styles.css` 按顺序 `@import` 串联（注意层叠顺序）；或加一个极小拼接步骤。

## 4. 防回潮机制（直击"为了好管理"）

1. **模块规模红线 lint**：新增 `scripts/lint/module_size.py`，CI 中校验任何 `.py` / `.js` 单文件行数 ≤ 1200（阈值可调），超限即失败。
2. **包职责注释**：每个新文件头部必须有一行职责说明。
3. **拆分后回归门**：每步提交必须 `pytest` 全绿 + `playwright.ci.config.mjs` 全量通过（现有 338 用例），CI `continue-on-error` 已覆盖已知 11 项。

## 6. 已识别风险与对策

- **测试 import 私有名**：`UserInput`、`_self_care_group`、`from medagent import conclusion as m`——通过包 `__init__` 重导出解决，测试零改动。
- **server 路由共享 self 状态**：先抽无状态辅助（medication/persistence），路由拆分用 `ctx` 对象隔离，保留公开名。
- **前端非 ES 模块顾虑**：已确认 `app.js` 为 `type="module"`，拆分用 import/export，无需运行时改造。
- **样式层叠顺序**：`@import` 顺序与现有保持一致，UI 全量用例覆盖主要表面。

---

## 7. 范围说明

- 本方案**只重组文件边界，不改业务逻辑/算法/文案**。
- 不做性能优化、不做新功能、不改动 `kg/`、`extensions/` 等已良好模块化的部分。
- 数据文件（`data/kg/*`）、测试夹具（`tests/fixtures/*`）不在拆分范围内。

### UI 验证

- **全量 52 个 spec 文件全部通过**（`npm run test:ui:ci`，19m38s）。
- 拆分过程中逐个用例做过 A/B 对照：`calculation-supplements`、`observation-completion`、`visual-consultation`、`measurement-supplements`、`workspace` 等在**原始文件上同样失败**，说明当时红的是既有问题，不是拆分引入。这些问题后来单独修掉了（见下）。
- **连跑隔离**：整套原本共用一个 demo 服务 + 一个患者库，文件之间会继承上一份留下的随访、用药提醒、待识别条目，失败集合随文件顺序漂移。`scripts/test/ui-ci.mjs` 改为**每个 spec 文件单独一次 `playwright test`**（`reuseExistingServer: false` → 一文件一服务 + 重建数据目录），`test:ui:ci` 指向它，`test:ui:all` 保留单次全量。
- **CI 门禁**：`.github/workflows/main-quality.yml` 的 `Run the whole browser suite` 已从 `continue-on-error: true` 改为**阻断门禁**（job timeout 提到 60 分钟）。

### 拆分之外顺带修掉的产品缺陷

- `presentation.py` 用「回复文本 == 问题 prompt」判定 `canonical`，桥接句一加就变 false，前端因此丢掉 `spec`：急诊 6 项安全信号网格与短标题整块消失。改为「消息以 prompt 结尾也算 canonical」。
- 900×648 下 `#view-consultation` 按内容撑到 608px 而 `main` 只有 574px，输入框被顶到视口外 13px。改为 flex 列 + `minmax(0, 1fr)`，滚动交给会话区。
- 移动端 `.surface-actions` 绝对定位换行后盖住「当前这一步 · 展开对话记录」，按钮点不到。≤700px 改回文档流。
- `structured-ui` 拆分时暴露的潜伏 bug：task 家族对导入的 `let illustrationSequence` 做 `++`（只读绑定），抛错被渲染器 fallback 静默吞掉。改为可变 `{ value }` 持有对象。
