# 设置视图改造方案

版本：v1.0（2026-10-22）
状态：已定稿，按此实施
缘起：产品负责人提出——把外观等偏好收进"设置"，采用 Muse 式形态：
侧栏进入后，主区整幅展开为一个结构清晰的设置界面。
关联：《知微视觉改版设计说明》§4.8（测试视图移出患者界面）由本方案完成落地。

## 1. 目标与边界

**目标**：全应用只有一个设置入口、一处设置界面。偏好类设置（外观皮肤、
字号、界面模式）从弹窗与侧栏散落状态，收敛为一个占满主区的设置视图，
左侧分类、右侧内容，即选即生效。

**边界**：
- 只动呈现与导航，不新增设置项、不改任何设置的语义与持久化键。
- 模型配置表单（后端模式、密钥、知情同意）本轮**不搬**：它是有保存/
  取消语义的事务性表单，留在对话框里是恰当的；设置视图给它一个
  "模型服务"分区与入口。待表单字段稳定后可再议整体迁入。
- 问诊进行中进出设置，会话与草稿不得丢失（视图切换本来就不卸载
  问诊视图，本方案不得引入会重置状态的实现）。

## 2. 现状盘点（改造前）

| 设置 | 现在在哪 | 机制 |
|---|---|---|
| 皮肤（6 主题 + 跟随系统） | 顶栏"外观"按钮 → 模态对话框 #appearance-dialog | themes.js：showModal、打开聚焦已选项、radio change 即时 apply + 保存（localStorage / 桌面端 API），状态文案 #appearance-status |
| 字号（小/标准/大） | 同上对话框内（2026-10-22 视觉改版新增） | themes.js 同文件，键 chengxin.fontscale.v1 |
| 界面模式（患者/研发） | 侧栏底部下拉 .workspace-mode（视觉改版时由顶部降位至此） | app.js 监听 #workspace-mode change |
| 模型与运行配置 | 侧栏"模型服务"按钮 + 顶栏 backend-pill → 对话框 #settings-dialog | app.js openSettings()，表单提交保存 |
| 本机数据说明、版本 | 侧栏底部 local-note / version-line | 静态 |

问题：三个入口、两种容器（模态/下拉）、一处重复（模型服务有两个
触发点），且外观模态框在小屏上挤压色卡与字号选项。

## 3. 目标形态

### 3.1 入口与导航

- 侧栏底部新增独立导航项 **设置**（齿轮图标，与"模型服务"按钮合并：
  原按钮移除，其功能进入设置视图的模型服务分区）。
- 顶栏"外观"按钮**移除**（顶栏只保留面包屑、连接状态、离线标识与
  研发模式下的 backend-pill——后者为状态显示兼入口，保留）。
- navigate() 白名单新增 `settings`，页标题"设置"，视图节点
  `<section class="view" id="view-settings">`，与既有视图同一切换机制；
  设置不是研发视图，患者模式可用。

### 3.2 布局

参照 Muse 设置页，适配知微的单列语言：

- 容器 max-width 1020px 居中（比问诊列宽，因设置含并置选项）。
- 左分类栏（200px）：外观 / 模型服务 / 界面与数据；右内容区为
  对应分区，**单页滚动 + 分类锚点**（不做多页签切换，设置总量小，
  一屏滚完更易找；分类点击滚动定位并高亮）。
- 移动端（≤700px）：分类栏变顶部横排锚点，内容单列。

### 3.3 分区内容

1. **外观**：皮肤选项由模态内的小色卡放大为卡片网格（2 列，色卡
   预览区加高、主题名 + 一句说明），单选语义与 `name="appearance"`
   不变；下方字号三档分段控件（`name="fontscale"` 不变）；
   状态文案沿用 #appearance-status 位置（迁到分区底部）。
2. **模型服务**：一行摘要（当前运行方式的中文名，如"离线演示"）+
   按钮"打开模型与运行配置"（触发既有 #settings-dialog，不改其
   内部）；摘要文本随 #backend-pill 的现有状态同步（只读展示，
   数据来自既有 state/backend 标签，开工时以实际字段为准）。
3. **界面与数据**：界面模式下拉（.workspace-mode 整块迁入本分区，
   app.js 的 change 监听按 id 不受影响）；本机数据说明（local-note
   的文案迁入为静态说明行）；版本行迁入分区底部。

### 3.4 机制复用与改动点

- **themes.js**：删除 dialog 相关逻辑（showModal、遮罩点击关闭、
  打开时聚焦）；保留 apply/持久化/storage 同步；sync() 在脚本加载
  时执行一次（视图在 DOM 中常驻，radio 状态随时正确）；change
  监听从 dialog 改挂到设置视图容器（事件委托到 document 或视图
  节点均可，取视图节点）。
- **app.js**：navigate 白名单 + 标题映射 + 存储说明映射各加一项；
  删除此前"把 .workspace-mode 搬到侧栏底部"的临时代码（改由 HTML
  直接落位设置视图）；#open-settings 监听保留（改挂设置视图内的
  新按钮 id 或复用同一按钮元素移动——取移动元素、改文案，监听
  不动）。侧栏"模型服务"按钮即该元素时，将其迁入设置视图并
  更名为"模型与运行配置"，侧栏底部以"设置"导航项替代。
- **index.html**：新增 #view-settings 骨架；#appearance-dialog 整段
  删除，其 fieldset 内容迁入外观分区；顶栏移除外观按钮。
- **CSS**：新增设置视图样式（appearance.css 或 styles.css 改版段）：
  分类栏、分区标题、皮肤卡网格放大、锚点高亮；删除仅服务于模态
  的对话框专有样式时须确认无其他引用。
- **测试**：tests/ui/appearance.spec.mjs 同步改造（入口改为点"设置"
  导航 → 外观分区；聚焦与溢出断言改对视图节点）；其余引用
  #appearance-dialog 的检索清零。

## 4. 实施步骤

- S1 方案入库（本文）。
- S2 骨架：#view-settings + navigate 接入 + 侧栏"设置"项，先空跑
  切换无误。
- S3 外观迁入：fieldset DOM 迁移 + themes.js 去对话框化 + 样式。
- S4 模型服务与界面模式迁入：摘要 + 入口按钮 + .workspace-mode 落位。
- S5 测试更新与回归：appearance.spec.mjs、node --check、pytest 全量、
  截图走查（桌面/移动、切主题与字号即时生效、问诊进行中往返设置
  状态不丢）。

## 5. 验收标准

- 全应用设置入口唯一（侧栏"设置"）；顶栏无外观按钮；旧对话框
  #appearance-dialog 不复存在。
- 皮肤/字号切换即时生效且刷新后保留（持久化键不变，桌面端保存
  路径不变）；appearance.spec.mjs 更新后通过。
- 问诊进行中进入设置改皮肤，再回问诊：会话、已答进度、输入草稿
  均在（走查验证）。
- pytest 全量绿；截图：设置视图桌面、移动、外观分区各一，与问诊
  页风格一致（同一套令牌）。

## 6. 风险与回退

- 主要风险在 themes.js 的时序（它在首屏绘制前运行）：去对话框化
  后须保证 apply() 与 dataset 设置不晚于原逻辑；DOM 迁入不改变
  radio 的 name/value，storage 事件同步逻辑保持。
- 全部改动为前端静态资源，独立分支提交，回退即还原文件。
