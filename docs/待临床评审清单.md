# 待临床评审清单

> 目的：本系统已上线的医学内容均为工程版（engineering v1），评测门只能证明
> 内部一致性，不能替代临床判断。本清单把所有"等临床评审"的条目收敛到一处：
> 每项注明内容位置、当前状态、风险、需要评审人决定的事与通过标准。
> 评审人只需按清单逐项给出「通过 / 修改（附意见）/ 否决」，工程侧据此修订并留痕。
>
> 关联决策：《问诊结论单设计文档》D1–D6、《顶级医疗智能体改造设计文档》开放决策。
> 状态图例：🟢 已对患者可见 · 🟡 已计算但未对患者可见（shadow） · ⚪ 未启用

## C1 红旗表（分诊安全底线）🟢

- 位置：`src/medagent/content/red_flags.json`（v1.0.0）
- 内容：6 条红旗——unresponsive（无反应）、seizure（抽搐）、cyanosis（发绀）、
  severe_breathing（严重呼吸困难）、chest_pain（胸痛）、major_bleeding（大出血），
  每条含精确短语 + 改写正则 + 组合规则三层匹配。
- 当前证据：工程评测语料上各条召回 1.000（发布门 PASS），但语料为工程构造，
  不是临床病例集。
- 请评审决定：① 6 条是否齐全，有无遗漏的高危情形（如过敏性休克、意识模糊、
  咯血、中风征象）；② 每条的触发短语/正则是否会漏掉口语表达；
  ③ 命中后的处置文案（立即急救/拨打 120）是否恰当。
- 通过标准：评审人签字确认条目与阈值，或给出增补清单由工程侧实现后复评。

## C2 自我护理内容（结论单）🟢

- 位置：`src/medagent/content/self_care.json`（v1.0）
- 内容：6 组——generic_routine / generic_urgent / respiratory_routine /
  respiratory_urgent / chest_routine / chest_urgent，随结论单展示给患者。
- 请评审决定：① 每组的建议（休息、补液、观察要点等）是否安全、不过界；
  ② 是否涉及不应给出的具体用药/剂量建议（OTC 范围，关联 D 决策）；
  ③ urgent 组的求助阈值是否与红旗表一致。
- 通过标准：逐组确认或给出改写文本。

## C3 鉴别方向与患者表述（结论单方向）🟡

- 位置：`src/medagent/content/differentials.json v1.2.0（含主诉口语词扩展与否定修复），2026-10-23 扩展）
- 内容：8 条路径、25 个假设——呼吸道（上呼吸道感染、下呼吸道感染/肺炎可能、
  哮喘急性发作、流感样疾病）、胸痛（急性冠脉综合征可能、非心源性胸痛），
  以及新增的腹痛（阑尾炎、急性胃肠炎、消化道出血、消化不良）、头痛（脑膜炎、
  突发剧烈头痛、偏头痛/紧张性）、头晕（耳石症、后循环卒中、体位性低血压/
  贫血）、腰痛（机械性、神经根受压、马尾等严重问题）、泌尿（膀胱炎、肾盂
  肾炎、结石）、皮疹（荨麻疹、接触性皮炎、皮肤感染/带状疱疹）；每条假设含
  label 与 patient_label（患者可见名）、支持/反驳条件、先验带。新增 6 组
  自我护理条目（`content/self_care.json`）一并纳入 C2 评审范围。
- 当前状态：方向已在后端计算与评测，但默认不对患者展示
  （`MEDAGENT_CONCLUSION_DIRECTIONS` 未开启），即 D2 处于 shadow。
- 请评审决定：① patient_label 的通俗表述是否准确、会不会造成误解或恐慌；
  ② 不确定性措辞阶梯是否恰当；③ 哪些假设绝不能出现在患者面前。
- 通过标准：确认后才可开启患者可见；未确认前保持 shadow。

## C8 性别与妊娠状态问题（活体评测第二轮新增）🟢

- 位置：`src/medagent/content/questions.json`（v2026-10-23.v2）新增 `sex`、
  `pregnancy_status` 两题，engineering-v1。
- 内容：`sex`（opening 期、choice 男/女、非阻塞字段）补齐此前 fact schema
  完全缺失的性别信息；`pregnancy_status`（history 期）在腹痛/盆腔/尿路类
  主诉下询问是否怀孕及月经是否推迟——活体评测 case8 实证：22 岁右下腹痛
  病例中异位妊娠、卵巢扭转等核心鉴别此前无任何合规采集路径。条目已声明
  `excludes_fact_equals: {sex: [male]}` 与 `age_between_when_known: [12, 55]`
  两项适用条件，待下一波次引擎实现求值后生效；当前仅按主诉词集触发。
- 请评审决定：① 问法（措辞、选项）是否恰当、是否冒犯；② 适用范围口径
  （主诉词集、年龄带 12–55、男性排除）是否合适；③ 妊娠相关鉴别是否应更
  前置或扩大到其他主诉（如晕厥、阴道出血）。
- 通过标准：逐题确认或给出改写文本与范围口径。

## C9 暴露史与患者自述体温问题（活体评测第二轮新增）🟢

- 位置：同 C8 文件，新增 `recent_exposures`、`reported_temperature` 两题，
  engineering-v1。
- 内容：`recent_exposures` 在皮疹/过敏类主诉下结构化询问第一次吃的食物、
  新用的药、新接触的东西（此前暴露信息只能埋进 skin_details 叙述文本，
  无字段承接）；`reported_temperature` 询问患者自述量过的体温，与宿主
  图示自查的只读测量字段 `temperature_c` 明确区分、互不覆盖。
- 请评审决定：① 暴露史的问法覆盖面是否足够（食物/药物/接触物之外是否
  应含职业、环境、宠物等）；② 自述体温在判断中的权重口径——与测量值
  冲突时以何者为准、是否需要在结论中标注来源。
- 通过标准：逐题确认或给出改写文本。

## C10 通路特异安全网文案 return_now_if（活体评测第二轮新增）🟢

- 位置：`src/medagent/content/self_care.json`（v1.1）新增
  `return_now_if.by_pathway`，engineering-v1；`src/medagent/conclusion.py`
  按病例活跃通路选取，无通路时回退通用四项。
- 内容：8 条通路各自的「出现以下变化请立即求助」清单——back（大小便异常、
  会阴麻木新出现或加重、下肢无力加重）、abdominal（呕血或大便发黑、腹痛
  迅速加重、高热）、headache（意识改变、喷射样呕吐、肢体无力、突发有生
  以来最剧烈头痛）、urinary（腰痛伴高热、完全尿不出）、dizziness（言语
  不清、肢体无力新出现、走路不稳明显加重）、chest（出冷汗、疼痛放射到
  下颌或手臂、呼吸困难）、respiratory（呼吸困难加重、嘴唇发紫、高热
  不退）、skin（口唇或舌头肿、呼吸不畅、皮疹迅速扩散伴发热）。活体评测
  case5 实证缺陷：腰痛病例的结论单此前只有通用四项，无腰痛特异红旗。
- 请评审决定：① 逐条清单是否完整、有无遗漏的通路特异危险信号；
  ② 阈值表述（如「高热」的度数口径）是否需要量化；③ 与 C1 红旗表、
  通用四项之间有无矛盾或重复。
- 通过标准：逐条确认或给出改写文本；未确认前可由工程侧回退为通用四项。

## C11 触发词与支持词口语扩展（活体评测第二轮）🟡

- 位置：`src/medagent/content/differentials.json`（v1.2.1）各通路
  `chief_complaint_contains_any` 与 radiculopathy 的 support 词表；
  `questions.json`（v2026-10-23.v2）各通路题 `applies_when` 词表，
  engineering-v1。
- 内容：纯匹配词表扩展，不改变任何医学边界——腹部增「肚子不舒服/肚子
  难受/胃不舒服/腹部不适/肚子胀」、尿路增「老想上厕所/尿的时候疼/尿不尽」
  等口语说法，头痛增「脑袋疼/头胀」、腰背增「腰扭了/闪腰」等；活体评测
  实证：口语主诉下通路触发失败 2/8、问题候选漏字段 3 例。radiculopathy
  support 增「窜到大腿/过电/放射痛/腿发麻/窜」等——case5 患者原文
  （放射痛、腿麻、过电样窜痛俱全）此前因词表不覆盖而完全未浮出该方向，
  已加回归测试锁定。
- 请评审决定：抽查新增词有无过宽触发（如「心慌」进入胸痛通路、「身上痒」
  进入皮肤通路是否恰当），有无仍遗漏的高频口语说法。
- 通过标准：抽查确认或给出增删清单。

## 评审流程（建议）

1. 评审人按 C1→C7 顺序评审，安全底线（C1/C7）优先。
2. 每项结论记入本文件末尾「评审记录」表：日期、评审人、结论、后续动作。
3. 工程侧按意见修订内容版本（version 递增），重跑发布门，附结果再报。
4. C3/C5 的启用开关只在对应项「通过」后由用户下令开启。
