# 问诊结论单设计文档

**知微 · 健康记录与问诊助手（chengxin-medical-agent）**

版本：v1.3（2026-10-26）
状态：阶段 A 已实施（见 §12）；§13 受限可见与七段关单已实施、独立监督员签字可提交（待主会话亲验推送，见 §13.9）；阶段 B/C 待开放决策 D1–D6（其中 D2 见 §13.7 部分裁定：剂量一律不给）
前序文档：《顶级医疗智能体改造设计文档》（阶段 0–4 已实施完毕）
本文范围：问诊结束时给患者的最终回复——"结论单"——的定位、结构、生成与评测。不改动问诊内核契约 K1–K8。

---

## 0. 为什么有这份文档

2026-10-22 实测发现：普通患者走完问诊、确认摘要后，结束页只有一份只读记录。引擎算出的去向建议埋在摘要末尾，安全警示藏在折叠条里，随访计划一度根本没有送达前端（已修复，main `1cb56b4`）。但修复的只是"呈现管道"，没有解决更根本的问题：

**这个产品一直在以"记录员"的定位回复患者。** 它回答的是"你的信息我整理好了"，而患者打开问诊时心里只有四个问题：

1. 我这可能是什么、严不严重？
2. 我现在该做什么、去哪、多快？
3. 在家能做点什么？
4. 出现什么情况必须马上去医院？

问诊流程（采集）只是手段，结论才是产品。本文定义结论的形态、生成方式与质量门。

## 1. 定位（已与产品负责人确认）

### 1.1 定位陈述

**分诊与解释者：不出确诊，但出结论。**

临床上一次合格的全科首诊，产出本来就不是确诊，而是三样东西：**鉴别方向**（最可能是什么、最危险的是什么）、**处置去向**（观察 / 门诊 / 急诊，及时间窗）、**安全网**（恶化信号与复诊条件）。这正是本产品的产出定义。它卡在合规边界内侧：不做疾病确诊、不替代医生诊疗，但把"所以我该怎么办"回答完整。

### 1.2 与旧定位的差异

| | 记录员（现状） | 分诊与解释者（目标） |
|---|---|---|
| 回复主体 | 事实清单 + 一句免责 | 结论单：去向、方向、行动、安全网、预期 |
| 免责声明的位置 | 第一句、主体 | 尾注，一次 |
| 患者下一步 | 自己判断 | 明确给出，含时间窗 |
| 问诊问题的价值标准 | 字段完整性 | 是否改变结论（见 1.3） |
| 交接摘要 | 主角 | 退为次级产物，一键给医生 |

### 1.3 从答案倒推问题（设计原则）

问诊流程的每个问题都应能回答："它会改变结论的哪一部分——去向、鉴别排序、安全网还是随访？"改变不了任何一部分的问题，不应问，或不应以现在的方式问。本原则不要求立即重构采集流程，但作为后续所有问题增删的评审标准写入本文。

### 1.4 合规边界（硬约束）

- 不出现确诊式表述（禁用语清单见 §6.3）；鉴别方向一律以不确定性措辞给出（§6.2）。
- 不提供处方药建议；非处方药是否纳入 v1 由开放决策 D2 定，在此之前居家建议只含非药物措施与就医指引。
- 急症路径不变：红旗命中时走现行急症路径（单一行动指令），结论单不生成、不介入，不允许结论生成引入任何延迟或稀释。
- 结论单的每一句临床内容必须可溯源到：分诊规则、经校验的假设证据、或经审定的内容资产（§5）。**模型自由生成不得进入结论单的临床句子**——与内核"模型提议、确定性校验"的既有协议一致。

## 2. 目标与非目标

**目标**

- G1：每次问诊关闭（确认关闭与 urgent 关闭；急症关闭除外，见 §1.4）都产出一份结构化结论单，并成为关闭态的主视图。
- G2：结论单的去向、鉴别、安全网、随访全部由确定性管线从既有状态生成，可评测、可回归。
- G3：建立结论质量的评测门（§8），未过门的内容层级（鉴别）不上患者界面。

**非目标**

- 不做诊断、不做治疗方案、不做用药决策。
- 不改变采集流程与分诊规则本身（仅消费其结果）。
- 不替代交接摘要（handoff）；结论单面向患者，交接摘要面向医生，两者数据源同源、读者不同。

## 3. 结论单结构

结论单由七个区块组成，顺序即阅读优先级。普通形态下 D1–D6 必备，D7 为入口型区块。

### D1 一句话去向（必填，置顶）

- 内容：处置层级 + 时间窗 +（可选）建议科室，一句话。
  例："可以在家先观察；如果明天体温仍高或症状加重，请在 48 小时内到线下医疗机构就诊。"（v1 默认不细到科室，见下条与 D3。）
- 数据来源：分诊层级（state.risk）与关闭原因的确定性映射（§5.2）。科室提示的粒度由开放决策 D3 定，v1 默认只给"线下医疗机构 / 发热门诊"级别，不细到科室，除非主诉路径有审定映射。
- 呈现：关闭页第一屏第一行，独立色块（复用现有 summary-route 样式族）；紧急层级时带 `role="alert"`。

### D2 可能的方向（条件必填，可弃权）

- 内容：2–3 个鉴别方向，分两组呈现：
  - **更可能的方向**（common_condition，证据支持较强）；
  - **需要排除的方向**（serious / red_flag_condition，即使先验低，只要假设仍 active 且有证据或红旗未消解，必须出现）。
- 每个方向：一句患者语言的名称 + 一句依据（"你提到 X、Y"）+ 一句不契合点（若有，如"但你没有 Z"）。依据只能来自假设的 evidence_for / evidence_against 原文引用（§5.3）。
- 弃权：不满足 §5.4 的证据条件时，本区块整体替换为弃权文案："目前的信息还不足以给出可能的方向——这也是建议你线下评估的原因之一"，且 D1 的时间窗不得因此放宽。
- 呈现：每方向一张小卡；"需要排除"组带警示色边。

### D3 信息缺口（可选，最多 3 条）

- 内容：本次未能确认、且会影响判断的事实（如"没有测体温"），每条说明它影响什么（"体温读数会影响对感染程度的判断"）。
- 数据来源：CaseState 中 assertion=unknown 的事实，按其对 active 假设的 discriminating 价值排序（复用假设的 discriminating_questions 映射）。
- 作用：把"未知"从记录噪音变成行动提示——患者可在随访时补测，或就诊时告知医生。

### D4 现在能做的事（必填）

- 内容：居家观察与护理要点、明确不要做的事（如"不要自行服用抗生素"）、复测建议（如"今晚再测一次体温并记录"）。
- 数据来源：**新增内容资产 `content/self_care.json`**（§5.5），按主诉路径 / 处置层级索引，临床审定后才可上线；查无条目时退化为通用观察要点（休息、补水、记录症状变化）——通用条目同样需审定。
- D2 弃权时 D4 仍必填（行动建议不依赖鉴别成立）。

### D5 立即就医信号（必填）

- 内容：即现有 `return_now_if` 清单，与 D1 同级呈现要求：展开、不可折叠。
- 数据来源：现有摘要管线（_summary_payload）原样复用，本设计只规定其在结论单中的位置与呈现等级（已在 `1cb56b4` 落地）。

### D6 预期与随访（必填）

- 内容：典型病程预期一句话（来自 self_care.json 的 course 字段，无条目时省略不编造）+ 升级条件句。随访的到期时间与可记录结局只在随访卡呈现（已在 `1cb56b4` 落地），D6 不重复细节，仅通过 schema 的 follow_up 字段引用（§7 去重规则①）。
- 升级条件句必填："如果到 {随访到期} 还没有好转，或出现 D5 中任何信号，请线下就医，不要等随访。"

### D7 交接摘要入口（必填，次级）

- 一行入口："就诊时可把本次记录给医生看" + 现有交接摘要打开方式。不占用结论单主体版面。

### 3.3 三种形态（按风险层级）

| 层级 | 形态 | 区块 |
|---|---|---|
| EMERGENCY | 极简：只有行动 | 一句指令（立即拨打 120 / 前往急诊）+ 命中信号；无 D2–D7（现 notice 块行为不变） |
| URGENT（紧急关闭） | 压缩 | D1（role=alert）+ D5 + D6 的 24 小时随访；D2 只保留"需要排除"组；无 D3、D4 展开（D4 只给一句"不要在家自行处理耽误就诊"类审定句） |
| ROUTINE（确认关闭） | 完整 | D1–D7 全量 |

### 3.4 患者目标先行句

普通与紧急形态下，D1 之前可加一句先行句，直接回应患者自述目标（patient_goal 事实）：如目标为"想知道严不严重"，先行句为"先说你最关心的：目前没有提示严重情况的信号，但有两点需要排除——"。

实现前提（如实说明）：patient_goal 目前是自由文本问答（questions.json 中 input=text），**不存在现成的目标分类**。先行句依赖一个新增的确定性小分类器：对 goal 原文做关键词归类（严重程度关切 / 是否需要就医 / 居家处理 / 用药咨询 / 其他），归类命中才生成先行句，未命中则不生成（不猜测患者意图）。分类词表作为内容资产维护并配单测。v1 可选项，阶段 C 落地（§9）。

### 3.5 咨询对象适配（称谓与行动人）

结论单的读者不总是患者本人。按 subject_profile（consult_for 事实）适配：

- 为自己咨询：主语"你"，行动人即本人。
- 为孩子 / 其他家人咨询：患者以第三人称出现（"孩子"或已记录的称谓），行动指令指向照护者（"请您留意孩子……"）；D4 的执行者是照护者，D5 的观察者也是照护者，措辞模板必须带 subject 参数，不允许把成人模板原样套到儿童病例上。
- 儿童病例的 D2/D4 内容条目必须来自对应年龄段已审定条目；无审定条目时 D4 退化为通用观察要点 + 更强的就医倾向（window 不放宽）。

## 4. 数据模型

新增序列化结构 `ConclusionSheet`，挂载方式与 follow_up 完全同构：

- `AgentReply.conclusion: Optional[Dict]` 正式字段，进入 `to_dict()`；
- `CaseState.conclusion: Dict` 持久字段，进入 `CaseState.to_dict()` 投影；
- presentation 新增块类型 `conclusion`（§7）。

Schema（v1）：

```jsonc
{
  "version": 1,
  "tier": "routine | urgent",   // emergency 不生成患者结论单（§1.4）；该枚举仅保留给影子/审计记录
  "disposition": {
    "level": "emergency_now | urgent_today | routine_visit | self_care",
    "window_hours": 48,              // null 表示立即
    "text": "一句话去向（渲染后文本）",
    "department_hint": null          // 或审定映射给出的科室
  },
  "goal_line": null,                 // 或先行句文本（阶段 C）
  "directions": [                    // D2；弃权时为空数组且 abstained=true
    {
      "hypothesis_id": "uri",
      "patient_label": "上呼吸道感染",   // 只用患者语名称（§5.3 第 5 条）；临床 label 留在假设对象内
      "group": "likely | rule_out",
      "certainty": "more_likely | possible | cannot_exclude | no_signal_yet",
      "support_quotes": ["嗓子疼"],   // 必须为患者原话逐字子串（校验同 K 系协议）
      "against_note": "但你没有鼻塞、流鼻涕"
    }
  ],
  "directions_abstained": false,
  "gaps": [                          // D3
    { "fact_key": "temperature_c", "label": "体温", "impact": "会影响对感染程度的判断" }
  ],
  "self_care": {                     // D4
    "do": ["多休息，多喝水"],
    "avoid": ["不要自行服用抗生素"],
    "measure": ["今晚再测一次体温并记录"]
  },
  "return_now_if": ["意识异常或抽搐", "…"],   // D5，与摘要同源
  "outlook": "这类情况通常 3–5 天逐渐缓解",     // D6，可为 null
  "follow_up": { "kind": "routine_checkin", "due_in_hours": 48 },
  "generated_by": "conclusion-composer/v1",
  "content_versions": { "differentials": "…", "self_care": "…" }
}
```

不变量：

- I1：`directions[*].support_quotes` 每条必须是患者原话的逐字子串——复用 `validate_workspace` 的同一校验，通不过的方向整条剔除（与假设校验的"伪造引用整条拒绝"一致）。
- I2：`group == "rule_out"` 的方向不得因排序被截断丢弃（见 §5.3 选取规则）。
- I3：结论单生成失败（任何异常）时，关闭流程回退到现行摘要视图，**永不阻塞关闭**（fail-open 到旧行为，与内核隔离原则一致）。
- I4：同一会话只生成一次（关闭时）。关闭后更正事实的路径在现有实现中是"重开会话"（closed_reason 清空、回到问诊流程，见 consultation.py 的 reopen 分支），再次关闭时重新生成并递增 version，事件流留痕 `conclusion.generated`；旧版本结论单不删除，开发者视图可对比。
- I5：患者视图在重开已结束会话时走**事件重放**（前端以事件中保存的 reply 快照重建视图，见 web/app.js 的 replay 路径）——因此 conclusion **必须进 reply.to_dict()** 才会在重开时出现；CaseState 投影中的 conclusion 供开发者视图与随访引用，两处缺一不可。

## 5. 生成管线（ConclusionComposer）

新模块 `src/medagent/conclusion.py`，纯函数式：`compose(state) -> Optional[ConclusionSheet]`。

挂载点（单点后处理，不散落到各关闭分支）：两个引擎的 submit 出口统一后处理——当本轮 reply 使会话进入 Phase.CLOSED（reply.phase == "closed"）且 tier 非 emergency 时调用 composer 并把结果写入 reply 与 state。确定性引擎的关闭入口有三处（摘要确认、_urgent 紧急关闭、摘要自动关闭），自适应引擎有 confirm 快路径与继承的紧急路径——出口后处理一处覆盖全部，且天然覆盖"重开→再关闭"的再生成（I4）。双引擎各加一条平价测试（复用 test_closed_outcome.py 的模式），杜绝再次出现双引擎不一致。

### 5.1 管线步骤

1. **定层级**：tier ← state.risk.level + state.closed_reason。
2. **定去向**（§5.2）：确定性映射表，不查模型。
3. **算鉴别**（§5.3）：关闭时推理一遍（close-time reasoning pass）。
4. **选缺口**（§5.4 附带）：unknown 事实按判别价值排序取前 3。
5. **配行动**（§5.5）：查 self_care.json。
6. **组装与措辞**（§6）：模板渲染 → 禁用语 lint → 产出。
7. **留痕**：写入 state.conclusion、reply.conclusion，追加 `conclusion.generated` 事件（含 content 版本与弃权标记）。

### 5.2 去向映射（确定性）

| 条件 | level | window | 文案骨架 |
|---|---|---|---|
| risk=EMERGENCY 或 emergency_route 关闭 | emergency_now | 立即 | 现行急症文案（不变） |
| risk=URGENT 或 urgent_route 关闭 | urgent_today | 今天内 | "建议今天内线下评估" |
| routine + 存在 rule_out 方向 active | routine_visit | 48h | "可在家观察；{window} 内就诊排除 {首要 rule_out 的患者语名称}" |
| routine + 有显著缺口（显著 = unknown 事实命中任一 active 假设的 discriminating_questions，或属测量型事实如 temperature_c） | routine_visit | 72h | 观察 + 补测/就诊条件句 |
| routine + 其余 | self_care | —（随访 72h） | "可先在家观察，我会在 {follow_up} 时来确认" |

映射表是代码内常量还是内容资产，阶段 A 定：建议放代码常量 + 单测锁定（去向是安全逻辑，不是文案）。

**与随访的一致性规则**：D1 的 window_hours 与随访计划的 due_in_hours 必须同源——观察窗的终点就是随访点。urgent_today ↔ 24 小时随访；routine_visit 48h ↔ 48 小时随访；self_care ↔ 72 小时（存在重要未知时随访提前到 48 小时，D1 的条件句引用更近的那个时间点）。实现上 composer 在 build_follow_up_plan 之后运行，直接读 state.follow_up 的 due_in_hours 填 window，禁止两处独立计算。

### 5.3 鉴别生成：关闭时推理一遍

不依赖交互期规划器是否切换到 DifferentialPlanner（该决策仍挂起）。关闭时：

1. `workspace = RuleBasedProposer().propose(state)`；
2. `accepted, rejected = validate_workspace(state, workspace)`——证据逐字校验，伪造/失效引用整条剔除（现成机制）；
3. 选取规则：
   - likely 组：category=common_condition 且 status ∈ {active, supported}，按 prior_band（high > medium > low）与证据数排序，取前 2；
   - rule_out 组：category ∈ {serious_condition, red_flag_condition} 且 status ∈ {active, supported}，**全部保留但最多 2 条**（超出时按 red_flags 未消解优先）；若某 serious 假设已被 refuted，不出现，但在开发者视图留痕；
   - 同一假设只出现一次；总数上限 3：rule_out 优先占位（≤2），likely 填剩余名额（实际 1–2 条），截断只许截 likely 组（不变量 I2）。
4. 每条方向的 certainty 由下表确定性映射（单测逐行覆盖），与 §6.2 措辞阶梯一一对应：

   | group | status | prior_band | 证据（for / against） | certainty |
   |---|---|---|---|---|
   | likely | supported | high | for ≥ 2 | more_likely |
   | likely | supported / active | 其余情形 | for ≥ 1 | possible |
   | rule_out | supported / active | 任意 | 任意（含红旗未消解） | cannot_exclude |
   | rule_out | refuted | — | — | 不进 D2（§6.2 的 no_signal_yet 仅限 D3 / 开发者视图） |

5. **患者语名称（patient_label）**：differentials.json 现有 label 是临床语（如"急性冠脉综合征可能（待排除）"、"下呼吸道感染/肺炎可能"），含术语与内嵌对冲词，不能直接给患者看。阶段 B 的内容工作须为每个假设补 `patient_label`（如"心脏问题（心肌缺血）"、"肺部感染"）；**缺 patient_label 的假设不得进入患者结论单**（只进影子与开发者视图）。certainty 模板只与 patient_label 拼接，避免"不能排除……可能"式双重对冲。

现覆盖范围如实声明：differentials.json v1 只有呼吸道与胸痛两条路径。其余主诉在阶段 A/B 必然走弃权路径——这是预期行为，不是缺陷；覆盖扩张依赖临床审定（开放决策 D1）。

### 5.4 弃权条件（任一满足则 D2 弃权）

- 无任何路径命中主诉；
- accepted 假设为空，或全部假设证据数合计 < 2；
- 主诉路径存在但全部 serious 假设状态不确定且 likely 组为空（信息太薄，不给"看似有方向"的错觉）。

弃权是结论单的一等状态，必须在评测中单独统计弃权率（§8）：弃权率过高说明覆盖不足，过低则怀疑门槛太松。

### 5.5 self_care.json 内容资产（新增）

结构按 （主诉路径 id | 通用） × 处置层级组织，每条含 do / avoid / measure / course 四组短句。要求：

- 每条内容带 `reviewed_by` / `reviewed_at` 元数据，未审定条目运行时视为不存在（查无条目走通用兜底，兜底条目本身亦需审定）；
- 条目可带 `avoid_if` 条件（如已记录服用某类处理、过敏史阳性或未知且条目涉及入口/外用物品）：composer 按当前事实过滤条目，命中冲突的句子剔除；涉及过敏未知的条目默认降级为"如需使用，先咨询医生或药师"句式或整条剔除，二选一在内容审定时逐条定；
- v1 规模目标：覆盖呼吸道、胸痛（与 differentials 路径对齐）+ 通用兜底，共约 3 组；
- 与 red_flags.json、differentials.json 并列纳入版本管理：注意现有 `ContentRepository.versions` 只含 questions / self_checks 两项，differentials 与 self_care 的版本号由 composer 直接读各自 JSON 的 `version` 字段写入 conclusion.content_versions（阶段 A 落地时可顺手把两项补进 versions）。

### 5.6 模型的位置

v1 的 composer **不调用模型**：全部区块来自规则、已校验假设与审定内容。模型润色（如把依据句改得更通顺）列为远期选项，且必须过"临床句子逐字溯源"校验后才可启用，不在本文阶段范围内。

## 6. 话术规范

### 6.1 总原则

- 先结论后依据；先行动后解释；一句一意；不用医学术语而不解释。
- 不确定性要**显性且分级**：患者有权知道我们有几分把握。
- 免责只在尾注出现一次："以上是根据你提供的信息给出的分诊与健康建议，不替代医生面诊。"位置在 D7 之后。

### 6.2 措辞阶梯（确定性映射，禁止自创同义词）

| certainty | 模板 | 适用 |
|---|---|---|
| more_likely | "更像是 {label}" | likely 组、prior=high、supported |
| possible | "可能是 {label}" | likely 组、prior=medium 或证据较弱 |
| cannot_exclude | "目前还不能排除 {label}，这也是建议就诊的原因" | rule_out 组 |
| no_signal_yet | "目前没有提示 {label} 的信号，但 {缺口} 会影响判断" | serious 已 refuted 或证据明确不支持时，仅在开发者视图与 D3 中使用，**不进 D2 主列表**（避免无端制造焦虑），评测阶段再议 |

### 6.3 禁用语清单（lint 硬拦，命中即生成失败走回退）

确诊、确诊为、可以排除、排除……可能、没事、不用担心、保证、肯定是、一定是、必须吃药、建议服用（处方语境）等。清单维护在 composer 内并配单测；临床审定时可增补。

### 6.4 数字政策

- 不给百分比概率（prior_band 是定性分带，禁止换算成数字呈现）。
- 时间窗数字只来自 §5.2 映射与随访计划，不新造数字。
- 体温、评分等患者数据引用必须与事实记录一致（同 I1 校验思路）。

### 6.5 长度预算（可读性即质量）

- 普通形态结论单主体（D1–D6）总字数 ≤ 600 字；每个方向 ≤ 2 句；D4 每组 ≤ 4 条短句。
- 超长即缺陷：评测中统计长度合规率（软指标），composer 单测对示例病例断言字数上限。

## 8. 评测设计

结论单是患者可见的临床内容，上线标准走评测门，不走"看起来不错"。

### 8.1 OSCE 式病例集（新增资产）

- 构成：脚本化病例（结构化事实序列 + 关键原话），覆盖：已有两条路径的典型/边界病例、must-not-miss 病例（如胸痛中的 ACS 模式、呼吸道中的肺炎模式）、信息不足应弃权病例、急症对照（结论单不得稀释急症指令）。
- 规模建议：v1 不少于 60 例，其中 must-not-miss ≥ 15、弃权期望 ≥ 10。来源由开放决策 D4 定（改编公开教学病例 / 临床合作方提供 / 内部编写经临床审定）。
- 病例格式：以**事实脚本**为主——每例给出结构化事实序列（含关键原话），直接构造 CaseState 驱动 composer，结果确定性可复现；另设 ≤ 15 例**全对话病例**走确定性引擎端到端，验证挂载点与重放渲染。标注由两人独立完成、分歧仲裁，标注者资质与 D1 审定人要求一致。
- 标注 schema（每例）：
  - `expected_disposition`：期望去向层级（允许集合，如 {routine_visit, urgent_today}）；
  - `acceptable_directions`：可接受鉴别集合；`must_not_miss`：必须出现的 rule_out 方向（可为空）；
  - `expected_abstain`：是否应弃权；
  - `self_care_forbidden`：本例禁止出现的建议（如对胸痛病例出现"在家观察多喝水"即判有害）。

### 8.2 指标与门槛（发布门）

| 指标 | 门槛 | 性质 |
|---|---|---|
| 去向一致率（落在期望集合内） | ≥ 95% | 硬门 |
| must-not-miss 召回 | = 100% | 硬门 |
| 有害建议率（命中 self_care_forbidden 或禁用语） | = 0 | 硬门 |
| 鉴别 precision@呈现数（呈现方向 ∈ 可接受集合） | ≥ 90% | 硬门（阶段 B 起） |
| 弃权正确率（应弃权例中弃权占比） | ≥ 90% | 软门（报告并人工复核） |
| 弃权率（全集） | 仅监控 | 趋势指标 |
| 证据引用校验通过率 | = 100%（由 I1 构造保证，评测复核） | 硬门 |

### 8.3 影子模式与灰度

- `conclusion_sheet_mode = off | shadow | on` 配置开关（默认 off）。
- shadow：关闭时生成结论单、写事件与开发者视图，**患者不可见**；临床抽审影子样本（建议 ≥ 30 例覆盖各层级）签字后才可置 on。
- 接入现有发布门脚本族：新增 `scripts/evaluation/medical/evaluate_conclusion_sheet.py`，并把上表硬门并入 `evaluate_release_gate.py` 的汇总判定，报告归档 `docs/evaluations/<日期>/`，与阶段 0–4 的做法一致。

### 13.2 受限可见规则（方向）

**核心事实**：composer 的方向选取（`_select_directions`）本身已是证据门——无逐字肯定支撑的方向（引用 gate＋锚定 guard，如 J-07 零证据形）已被剔除，无 patient_label 的方向已被剔除。因此“受限集”不需要新证据机器：**受限集 ＝ composer 现有 directions 列表**，按 composer 现有顺序呈现，不另行排序。

- **受限模式（默认）**：方向段渲染 composer 顺序（rule_out 组在前），rule_out 组以警示样式显著渲染、组标题固定为“需要排除的方向”，不得混进 likely 组当作等可能项；likely 组标题“更可能的方向”；每方向保留依据原话（support_quotes）与不契合点（against_note）；措辞阶梯沿用 §6.2（更像是／可能是／目前还不能排除）。
- **“需要排除”显著性**：rule_out 组独立成组、警示边色、置于 likely 组之前；不得以“排序靠后”或“折叠默认收起”弱化。
- **空集 fail-closed**：directions 列表为空（弃权）时，方向段整体不渲染（不渲染弃权文案、不渲染空壳）。弃权诚实性由段 1 定性、段 6 缺口与段 4 行动共同承担；弃权文案（abstain_text）仅在全量模式与开发者视图保留。
- **全量模式（C3 签核后，env on）**：方向段保持现有渲染顺序与行为不变（likely 组在前），另加推理过程线（narrative.reasoning）。全量模式不改变方向选取与排序。
- **off 模式**：方向段整体不渲染（杀开关，见 §13.3）。

### 13.3 环境变量语义（显式变更，非悄悄翻转）

既有默认（directions 默认 off、department 默认 off）是阶段 A 的影子策略；v1.3 主会话裁定改为默认受限可见。变更写清如下，实施者不得以“兼容旧默认”为由留双份语义：

- `MEDAGENT_CONCLUSION_DIRECTIONS`：`off | restricted | on`，**默认 restricted**（此前默认 off）。
  - `off`：方向段不渲染；推理线不渲染；科室仅跟科室变量（默认不显示）。
  - `restricted`（默认）：方向段按 §13.2 受限规则渲染；推理线不渲染；科室按科室变量默认显示（下条）。
  - `on`：方向段按既有全量行为渲染；推理线渲染；科室显示。
- `MEDAGENT_CONCLUSION_DEPARTMENT`：`off | on | unset`，**默认 unset**（此前默认 off）。
  - `unset`：跟随方向模式——方向模式非 off 时显示科室，off 时不显示。
  - `on`：恒显示；`off`：恒不显示（操作员杀开关，覆盖方向模式）。
- 既有 API 语义：
  - `directions_visible()` 保持“全量”含义不变：仅当方向变量为 `on` 时为真（推理线门与既有调用方不动）。
  - 新增 `directions_restricted_visible()`：方向变量为 `restricted` 或 `on` 时为真。
  - `department_visible()` 按上条科室变量规则重算；缺失 flag 仍按不可见处理（fail-closed）。
- composer 仍是唯一计算可见性的地方（模块化重整 §4.4 冻结契约不动）：sheet 恒载完整 directions 列表；渲染器（结论卡、交接端点、打印）只消费 flag，不得重算可见性，不得以“列表在场”推断可见。
- **既有测试断言的协调**：上述默认变更会命中少数钉死旧默认的断言（已知：test_batch_c_content 3 处、test_conclusion_batch_b 1 处、test_conclusion_narrative 默认 off 用例）。处理原则：**断言只许随新默认更新、不许删除、不许弱化为同义反复**——每处更新须在实施报告中逐条列出新旧断言与行为依据，由监督员核查；除默认变更所涉断言外，既有结论测试零改动。

### 13.4 就诊带话清单（visit_notes，新增 additive 字段）

- **来源（只取已记录事实，不新编临床内容）**：按序取——①主诉原话（chief_complaint 事实值／原话，过长截断 80 字加 …，不得改写）；②担忧原话（worry.object，有则取）；③年龄／基础病（仅会话绑定患者档案时取 state.profile_baseline：出生年换算年龄、慢性病名录，名字原样）；④方向依据原话（support_quotes 去重，最多 3 条）。未绑定档案时只有 ①②④；方向弃权时只有 ①②③。总量上限 8 条。
- **字段**：composer 新增 additive 字段 `visit_notes`（字符串列表）与 `directions_mode`（`off | restricted | on`，记录本次 sheet 的模式）。既有字段一律不动名、不改义；新增字段一律 optional——缺失按旧行为处理（无带话段、方向段按旧 flag 规则），fail-closed。
- **校验器**：结论卡校验器须接纳两新字段（mode 枚举、visit_notes 字符串列表），其余严格性不动；未知字段仍抛错。
- **措辞与 lint**：段标题按 subject_kind 适配（本人：“就诊时请告诉医生”；家人：“就诊时请帮家人告诉医生”）；条目本身为患者／事实原话，lint 处理同 support_quotes（患者原话不触发整单作废）；段标题等系统文案正常过 lint。
- **交接一致性**：交接端点（handoff）白名单须透传两新字段与模式 flag；打印模块按模式渲染方向段与带话段（见 §13.6），不得重算。

### 13.5 安抚收尾与提醒约定

- **安抚收尾句（静态模板，不做新临床推断）**：按处置层级取固定句——routine／self_care：“先别太焦虑，按上面的安排来就好；有变化随时回来问。”urgent：“请按上面的时间尽快就诊，不要等随访。”不得出现诊断、剂量与确定性承诺。
- **提醒约定（D4 机制，分支处理，不得做假按钮）**：实施者先实查随访排定链路（关闭是否已排定可通知的随访、桌面通知读取何种 store）。分支：(a) 关闭已自动排定可通知随访——约定渲染为信息行（“我会在 {due} 小时后来确认”）＋按钮聚焦既有随访卡（真实动作，不新造状态）；(b) 未自动排定但可复用 workspace 草稿排定——按钮走该复用链路；(c) 两者皆无干净路径——不渲染按钮，只渲染信息行，并记跟进项。任一分支都不得出现点击无实际效果的按钮。

### 13.6 渲染层契约（结论卡／交接／打印三处同源）

- 结论卡按 §13.1 顺序重排；方向段 restricted 模式用 composer 顺序＋rule_out 警示样式，全量模式保持既有顺序；科室行仅当 department_visible 为真时输出（`=== true` 严格判断，缺失即不可见）；推理线仅当全量模式时输出。
- 交接端点：方向内容按模式透传（off 时 directions 为 None，绝不泄漏列表）；带话段与科室行按 flag 透传；support_quotes 在交接层仍按既有规则丢弃（医生不需要患者原话证据串，带话段的依据原话除外——带话段是给医生的行动清单，其条目保留）。
- 打印模块：方向段按模式渲染（restricted：composer 顺序＋rule_out 显著；on：既有行为；off：不渲染）；推理线仅 on 时渲染；科室行仅 department_visible === true 时渲染；带话段有项才渲染。
