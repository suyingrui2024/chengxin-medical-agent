# 问诊页去横条与全幅工作面方案

状态：已实施（v1.0，2026-10-22；负责人以"按照你认为合适的修改来改正"确认，开放问题按方案默认执行）
范围：桌面端问诊页。其他视图（记录、档案、设置、研发）不动。

## 一、问题

负责人圈出问诊页的三处（以发病步为例）：

1. **会话态标题行**：会话开始后，`.page-heading` 被 renderCase 改写为
   状态标题（"本次问诊"/"核对本次记录"/"结论与后续安排"等）加两个
   按钮，单独占一横条。所处位置侧栏已高亮、阶段信息聚焦条已承担，
   标题本身是第三重陈述。
2. **页脚注脚**：`.page-footnote` 的研究原型声明常驻问诊页底部，
   是给首次打开者看的声明，不是问诊内容的一部分。
3. **白色区域被收在中间**：内容面被 880px 栏宽、main 内边距、圆角
   卡框收住，四周留米色边；题目内容贴顶排，下方大片空白。

判断：三者是同一件事——问诊页应只剩「侧栏 + 一整块工作面」。
横条撤掉，面铺满，内容在面内居中限宽。

## 二、目标形态

侧栏右侧全部为白色工作面（上下左右顶满，无外边距、无圆角）：
右上角一组动作控件（紧急求助、已记录信息）；中间是内容，横向
居中限宽、纵向居中（内容过长时内部滚动）；底部输入行与面同底、
一条分隔线分开。落地页 hero 保留，坐在工作面顶部。

## 三、逐项处置

1. **标题行**：会话态下整个 `.page-heading` 收起——renderCase 不再
   向该 h1 写状态标题（h1 仅作落地 hero）。阶段信息由聚焦条
   「当前这一步」承担，关闭态由结论单自身标题承担，不丢信息。
   实施时先清点该 h1 的全部写入/读取方再动（吸取去嵌套时的教训）。
2. **动作组去向**：`#urgent-help`、`#toggle-facts` 移出标题行，
   组成 `.surface-actions` 浮于 `.conversation-panel` 右上角
   （绝对定位，高于滚动区，低于抽屉层级）。紧急求助的会话态
   显隐逻辑不变。
3. **注脚**：问诊页删除。声明拆两处安放——欢迎 hero 描述下加
   一行小字（研究原型 · 请勿输入身份信息）；设置「界面与数据」
   底部放完整一行。120 求助指引由紧急求助弹窗承担，不依赖注脚。
4. **全幅工作面**：main 对问诊视图取消内边距；`.consult-grid`
   取消 880 上限；`.conversation-panel` 背景改 `--surface` 白、
   占满工作区余下全部宽高；与侧栏以其右边界线分隔。
5. **内容限宽居中**：各内容容器度量不变（视觉题 760、消息列、
   摘要/结论卡、输入行按现有宽度居中）。`#active-question` 改
   纵向 flex，`.visual-question` 以 margin:auto 上下左右居中，
   消除「上挤下空」；消息流保持顶部起排，不居中。
6. **输入区**：`.conversation-footer` 并入工作面（同底色），
   保持吸底与居中限宽。

## 四、不动的部分

其他四视图的标题与版式；事实抽屉的机制与层级；任务聚焦模式
（本来就是全幅）；矮屏 reflow 层（≤560px 高仍回退页面流，
其涉及 `.page-heading` 的规则随标题行收起平移处理）。

## 五、实施与验收

改动集中在 index.html（移按钮、删注脚、欢迎小字）、app.js
（停写状态标题）、styles.css（工作面与动作组）、patient-reflow.css
（选择器平移）及受影响的规格断言迁移。验收：走查工具整树复跑
（几何口径改为「面板宽 = 工作区宽」）、Playwright 三规格与
pytest、prettier 全绿；重点截图核对落地、发病、量表、摘要、
结论，以及抽屉打开时右上角动作组不被遮挡。
