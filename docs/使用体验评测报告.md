> 走完全部问诊环节后的第一份用户视角评价。**全部证据留底**：
> 截图在 [screenshots/](screenshots/)、每步动作与屏幕内容在
> [steps.jsonl](steps.jsonl)、可复跑的驱动脚本是

> 问诊质量属于临床评测框架，不在本报告范围。

## 一、方法

三个患者画像各开独立会话，逐环节截图；另以 API 直发做坏路径测试。

| 画像 | 路径 | 覆盖环节 |
|---|---|---|
| 🔵 蓝·自护 | 32 岁男性，后脑勺胀痛两天 | 开场 → 安全筛查 → 病史问诊 → **图示定位任务** → 用药/过敏/病史 → 摘要核对 → 确认 → 结论单 |
| 🔴 红·急症 | 58 岁男性，压榨样胸痛 | 主诉一轮直达急救卡片 |
| 🟡 黄·家长 | 代 3 岁孩子问发烧 38.5℃ | **代答入口（孩子）** → 病史 → 体温测量图示任务 |
| ⚫ 坏路径 | API 层 | 空消息 / 5000 字 / 不存在的会话 / 双击发送 / 中途刷新 |

## 二、逐环节评价

### 开场（02-蓝-opening）
三位一体的咨询对象卡（我自己/孩子/其他家人）清晰；"紧急求助"**常驻**
右上角，任何时刻可点。好。

### 安全筛查（09 / 11-蓝-safety-screen）
主诉说完立刻进入红旗筛查：六个危险信号卡 + "有任何一项/都没有/不确定"。
"请逐项查看；有任何一项或不确定，都请如实选择"——明确告知不确定也
要选，比让患者猜好。**这是全产品最关键的一道闸，呈现是合格的。**

### 病史问诊（14 / 17 / 20 / 23）
每题一屏、选项带图标、可展开对话记录核对原话。节奏好，无压迫感。

### 图示定位任务（32 / 35-蓝-location-\*）
人体图带"右/左"标注与"虚线范围仅表示所选大部位；左右以患者自己为准"
的说明——**把"左右以患者为准"写出来是对的**。选完部位后确认按钮
直接变成「**记录：头/面部**」——所见即所记，防误触设计好。

### 摘要核对（50-蓝-summary-sheet）
结构完整："待你核对"徽章、"未确认"与已确认的区分、红旗框常驻、
每条事实带"更正"与"原话与来源"折叠。底部明确
**"系统没有据此作出诊断；请结合症状变化和专业医疗评估决定下一步"**。

### 结论单（53-蓝-after-confirm）
整体判断 → 下一步（可在家观察 + 建议科室：全科医疗）→
就诊时请告诉医生（患者原话）→ 现在能做的事 ·4 → 红旗 ·4 →
接下来 ·2（**"我会在 72 小时后来确认"** 的随访安排）→
"先别太焦虑，按上面的安排来就好" → 免责声明。完整、克制、有人味。

### 急症路径（62-红-escalation）
主诉说完**一轮直达**"立即急救"卡：现在拨打 120 按钮、
"先别慌，按下面的步骤来就可以"的安定语气、已确认情况复述、
"查看触发原因"可展开、"不要继续等待本次对话"。**合格。**

### 代答路径（黄）
"孩子"入口 → 性别 → 年龄 → 主诉 → 一直到体温测量图示任务
（87-黄-severity 之后转入 105-黄-end-state：测一次腋下体温，
准备/放置/读数三步图示 + "没有体温计 / 做不到/不舒服 / 暂时跳过"
三个体面的退出按钮）。代答全程不需要家长冒充本人身份。好。

### 坏路径
- 空消息：400 `invalid_message`「消息不能为空」✓
- 不存在的会话：404 `session_not_found` ✓
- 异常输入后的恢复文案："我没能确认年龄。请写成'8个月'或'32岁'
  这样的格式。"——**给格式示例的错误恢复，教科书级**（114 图）
- 双击发送：未见可见的重复消息（发送中按钮禁用生效）

## 三、发现清单（按严重度）

| # | 级别 | 发现 | 证据 |
|---|---|---|---|
| F1 | 🟡 待确认设计意图 | 家长已明确报"发烧 38 度 5"，引擎仍从头发起体温测量任务，**没有"已记录你报的读数"的衔接说明**。若"必须实测验证"是有意设计，卡片应说明"你报的数值已记下，但为了准确建议按下面步骤实测一次"——否则家长会觉得没被听见 | 105-黄-end-state.png |
| F2 | 🟡 一致性 | UI 输入框计数 0/2000，但 API 接受了 5000 字消息（200）且**静默吞掉、无任何截断或提醒**——API 与 UI 上限不一致 | steps.jsonl #110 |
| F3 | 🟡 恢复体验 | 问诊中途刷新页面**回到开始页**，不自动恢复进行中的会话；侧栏"最近问诊"可手动回去，但患者未必意识到。桌面壳是否有会话恢复需复核 | 116-坏路径-after-reload.png |
| F4 | 🟢 可用性 | 结论单的折叠区（"现在能做的事 ·4"）默认收起，**视觉上与静态标题难区分**——首次使用者可能以为没有内容。有计数提示，影响小 | 53-蓝-after-confirm.png；渲染器 `collapse(..., expanded=false)` |
| F5 | 🟢 措辞 | 同为"否认"语义：急症筛查按钮叫"都**没有**"，warning_ 类红旗题叫"**没有**"——两个词，增加一丁点认知负担 | 11 vs 各 warning 题 |
| F6 | 🟢 小项 | 开场"为谁咨询"只能点选，但底部自由文本输入框是激活的——患者打字不会得到明确反馈（可在该题禁用输入或提示"请点选上方卡片"） | 02-蓝-opening.png |

**没有发现阻塞级问题。** 三条安全边界（红旗筛查、急症直达、免责声明）
在真实操作路径上全部成立。

## 四、总体评价（用户口吻）

> "问诊过程中我从来没担心过它乱下结论——每条记录都能展开看原话，
> 结束时它明说'没有据此作出诊断'。胸痛那次它一轮就让我打 120，
> 没有浪费我时间。如果要说别扭的地方：我说了孩子烧 38 度 5，
> 它还让我从头再量一次，也没解释为什么；刷新之后它忘了我正在问诊。"
