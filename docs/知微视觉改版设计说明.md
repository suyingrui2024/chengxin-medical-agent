# 知微视觉改版设计说明

**知微 · 健康记录与问诊助手（chengxin-medical-agent）**

版本：v1.0（2026-10-22）
状态：已实施（V1–V3，2026-10-22，见 docs/evaluations/2026-10-22/视觉改版实施报告.md；偏差与未达量化门如实记录于报告）
范围：仅呈现层（web UI 的样式、布局与组件视觉）。不改问诊逻辑、内核契约 K1–K8、临床文案语义与分诊规则。
参照系：Muse 网页端的设计语言（借语言，不抄布局——理由见 §0.3）。

---

## 0. 为什么改

### 0.1 现状诊断（2026-10-22 实测，基线 main `107218c`）

视觉审查（11 屏走查）与样式表统计给出同一结论：现在的界面像"电子病历后台"，不像"一个人在跟你说话"。

| 症状 | 证据 |
|---|---|
| 字普遍太小 | styles.css 共 368 处 font-size，其中 ≤12px 的 225 处（8px×12、9px×22、10px×37、11px×65、12px×89）；根字号 14px |
| 靠边框分层级 | styles.css 中 `border: 1px solid` 79 处；卡片套卡片，处处描边等于处处无重点 |
| 三列抢注意力 | 左导航 + 中问诊 + 右事实面板并立；右侧 17 项信息全程在场，与每一步问题竞争 |
| 状态重复表达 | 连接/会谈/记录数在顶栏、侧栏、右面板各说一遍 |
| 重点不落在行动上 | 急症屏的作答按钮曾在卡片折线以下；结论单上线前摘要以未完成的观察卡开头（已修） |
| 品牌色面积过大 | 默认主题整屏鼠尾草绿（--paper #f5f6f2 / --sidebar #eef2ec），低对比的"绿雾"削弱层级与警示色的冲击力 |

tier-1 三项（焦点黑框、右面板截断、计数误标）已于 2026-10-22 修复；本文覆盖其余 tier-2/3 与整体设计语言。

### 0.2 参照系：Muse 网页端好在哪

不是配色，是克制。具体五条，本文逐条转成设计条款：

1. **一列叙事**：居中单列、行宽克制，注意力只有一个焦点，其余皆退后。
2. **排版分级**：字号/字重/留白拉开主次，边框与底色用得极省。
3. **字够大、气够透**：正文与辅助文字都有明确的尺寸下限与行高。
4. **状态只说一次**：同一信息全界面只有一个出处。
5. **行动随情境出现**：操作元素在需要时出现，不常驻陈列。

### 0.3 不能照抄的部分（医疗约束）

Muse 网页端是低风险开放对话，可极简到近乎空白；问诊不行：

- 红旗/急症语义必须**抢眼且常驻可达**，不许被极简主义稀释（120 行动区、立即求助信号）；
- 结构化输入（选项、量表、人体图）是问诊数据质量的来源，必须比自由文本更顺手，而非藏进聊天流；
- 已记录信息要可查、可更正（事实面板不能删，只能降级为次级层）；
- 患者群体含老年人与照护者，字号与点击区只有下限、没有"设计感折衷"。

结论：借设计语言（排版、留白、克制、单列），保留医疗骨架（结构化步骤、安全语义、记录可达）。

## 1. 设计原则

- **P1 一列叙事**：任何时刻屏幕上只有一个主角——当前问题、急症行动、或结论单。其余内容降级、收起或移出视线。
- **P2 排版分级，不靠描边**：层级依次用 字号差 → 字重差 → 留白差 → 底色差 表达；边框只用于输入控件与警示容器，不用于一般卡片。
- **P3 字号底线**（患者界面）：正文 16、次级 14、辅助 12.5、任何可见文字 ≥12（徽标数字等清单内例外除外）；行高 ≥1.6。研发界面密度另行豁免（§4.8）。
- **P4 状态只说一次**：每种状态指定唯一出处（§5 表），他处不得复述。
- **P5 行动优先于信息**：每一步先呈现"要做什么"，解释与记录随后；主要行动按钮在首屏可达范围内。
- **P6 安全语义只增不减**：改版不得降低任何警示的视觉强度、出现位置与可达性；急症红、警示黄的语义面积可以扩大，不得缩小。
- **P7 克制动效**：过渡 150–250ms、只表达状态变化；尊重 prefers-reduced-motion；无弹跳、无装饰动画。

## 2. 设计令牌（收敛现有 themes.css 体系，不另起炉灶）

### 2.1 字阶

| 角色 | 尺寸/行高 | 用途 |
|---|---|---|
| display | 26 / 1.35 | 页面主标题（首页问候、关闭态标题） |
| title | 20 / 1.4 | 当前问题标题、卡片主标题 |
| body | 16 / 1.75 | 正文、结论单正文、消息气泡 |
| secondary | 14 / 1.7 | 次级正文、选项说明、事实值 |
| caption | 12.5 / 1.6 | 辅助说明、时间、来源标注 |
| minimum | 12 | 全局下限（徽标计数、图注为例外清单，需逐项登记） |

- 现有 6 个配色主题保留，但字阶全主题统一，不随主题漂移。
- 新增**字号档位设置**（小/标准/大）：以缩放系数（0.94 / 1 / 1.12）作用于字阶令牌，默认标准；补上外观设置只有配色、无字号的历史欠账。
- 标题字体：默认主题现用衬线（Chengxin Serif SC）作标题——这是知微区别于通用聊天产品的品牌特征，建议保留于 display/title 两级（开放决策 DV1）。

### 2.2 间距与形状

- 间距基数 4：4/8/12/16/24/32/48 七档，组件内距不小于 12，区块间距 24 起。
- 圆角收敛三档：8（控件）/ 12（卡片）/ 16（大容器）；现 --panel-radius 随主题 12–16 漂移，统一为令牌。
- 阴影收敛三档：无（平面区块，默认）/ 轻（悬浮卡）/ 重（弹层）；一般卡片默认无边框无阴影，以底色差与留白分层。

### 2.3 颜色

- **纸面降饱和**：默认主题纸面由 #f5f6f2 改为近白 #fbfcfa，侧栏底色与纸面拉开一档即可；品牌绿（--primary #235f4e）只出现在行动按钮、选中态、标题点缀，不做大面积底色（开放决策 DV2）。
- **语义色专属**：红只给急症与立即求助，黄只给警示与待确认，紫（--info）只给计算/工具类信息；不得挪作装饰。
- **对比度**：正文对底色 ≥ 4.5:1，辅助文字 ≥ 3:1 且不小于 12.5px；现 --muted #586b60 在 #f5f6f2 上约 4.6:1，纸面改近白后复核全部主题。

### 2.4 焦点与交互态

- 统一焦点环：2px 主色外环 + 2px 偏移，键盘与程序聚焦同一外观（替代现黑/橙粗框，且不牺牲可见性——tier-1 修复是"程序聚焦不画框"，本条进一步统一为"该画时画得体面"，无障碍底线不退）。
- 悬停/按下态只改底色与 1px 以内的位移，不改布局尺寸；选中态用填充（--selected）不用描边加粗。

## 3. 布局

### 3.1 桌面（≥1101px）

- 骨架：**窄侧栏（232px）+ 居中单列（max-width 720px）**。问诊内容列居中，行宽对齐阅读舒适区；现三列中的右事实面板退出常驻（§3.3）。
- 侧栏只保留：品牌、新问诊、导航（问诊/会谈记录/健康档案）、最近问诊；连接状态按 §5 移至顶栏唯一出处；"测试视图"切换移出患者界面（§7）。
- 顶栏极简：左为面包屑（患者服务 / 问诊），右为连接状态与外观入口，仅此两件事。

### 3.2 问诊进行中

- 内容列自上而下：阶段标题（title 级）→ 当前问题卡 → 已答记录（弱化为时间线，默认只展开最近一轮，其余折叠为"展开对话记录"——沿用现聚焦视图机制，把它从"摘要专用"推广到全程）。
- 输入区（composer）固定于列底，圆角 12、轻阴影；快捷回复在输入区上方横排，可换行，不抢正文。

### 3.3 信息面板（事实）降级为抽屉

- 入口：内容列右上固定芯片"已记录 N 项 · 查看"，点击从右侧滑出抽屉（宽 360px），含事实列表与更正入口；Esc/点外关闭。
- 芯片上的 N 是全界面唯一的记录计数出处（P4）。
- 关闭态：抽屉默认关闭，结论单为唯一主角；交接摘要入口在结论单 D7（既有设计不变）。

### 3.4 关闭态

- 顺序沿用结论单设计：结论单 → 随访卡 → 本次记录（记录模式）→ 交接入口，全列居中，结论单的去向横幅为全页第一视觉落点。
- 页面标题 display 级一句话（如"本次问诊已整理"），不与结论单标题重复表述同一信息。

### 3.5 移动端（≤700px）

- 单列全宽，内容边距 16；抽屉改为底部弹层（高度 ≤ 80dvh）；composer 贴底且不被安全区遮挡。
- 急症屏：行动区（拨打 120）固定于首屏上部，作答按钮在首屏内（见 §4.5）。

### 3.6 首页

- 首屏内必须完整露出：问候标题、开始问诊卡组、输入框——现 hero 过高导致三者沉底的问题以"标题区高度 ≤ 28dvh"硬约束解决。
- 历史问诊入口降为标题下一行文字链，不与开始卡争版面。

## 4. 组件规范

### 4.1 问题步（question）

- 标题 title 级（20px），补充说明 secondary 级置于标题下 8px；不再用卡片描边包裹整步，以留白成段。
- 选项为整行可点击行（高度 ≥ 52px）：左侧单选标记，右侧 chevron 可省；选中填充 --selected；"都没有/都没有这些"类否定项与肯定项同权同尺寸（现急症筛查中否定项弱于肯定项的问题在本条一并纠正）。

### 4.2 快捷回复（quick replies）

- 字号 14、内距 10×16、圆角全圆；只承载短答，不承载长句；超过 6 个时横向滚动而非缩字。

### 4.3 严重度量表

- 0–10 改为色带渐变（绿→黄→红，随分值语义）+ 大点击区（每格 ≥ 44px）；已选分值以 body 级数字回显（"你选了 4 分"），确认按钮在未选时禁用态与可选态须有明确差异（现"先选择分数"弱区分问题在此解决）。

### 4.4 人体图定位

- 图形放大到内容列宽的 60% 以上且**可直接点选部位**（现小图 + 文本按钮代选的绕路取消）；点选后以填充高亮确认，下方文字回显部位名；系统术语不得出现在患者可见文案中（现错误横幅的技术黑话随本轮文案清理一并处理）。

### 4.5 急症屏（emergency）

- 版式冻结原则：本屏只许按 P6 增强，不许挪动语义。行动区（立即急救/拨打 120）置内容列顶部、首屏内；信号清单为纯展示（与可点击元素在样式上明确区分，现"瓷砖像按钮"的误认问题以去除悬停态与圆角按钮感解决）；作答按钮（有任一项/都没有）固定于信号清单下、首屏内，两者等权。

### 4.6 摘要与结论单

- 沿用已上线结构（结论单 D1–D7、记录模式去重、聚焦呈现），本轮只做令牌对齐：字阶、间距、圆角、语义色按 §2 刷新；结论单去向横幅为全页最强层级（display 下一档 + 语义底色），其余区块依次弱化。

### 4.7 事实抽屉

- 事实行：标签 caption 级、值 secondary 级；更正按钮为文字链样式，不做描边小按钮；未知项以"尚未记录"占位，不留空行。

### 4.8 开发者视图

- 密度豁免：研发界面保留高密度小字（工作台性质），但与患者界面在令牌层分开（developer 作用域单独的字阶下限 11px）；"测试视图"切换从患者侧栏移除，改由入口参数/研发界面内切换（开放决策 DV5 关联）。

## 5. 状态唯一出处

| 信息 | 唯一出处 | 移除的重复 |
|---|---|---|
| 本机服务连接状态 | 顶栏右 | 侧栏底部状态块、右面板状态芯片 |
| 会谈阶段（进行中/待确认/已结束） | 内容区标题行 | 右面板"本次问诊"状态芯片 |
| 已记录信息数 | 抽屉入口芯片 | 顶栏右计数、侧栏角标 |
| 当前步骤进度 | 问题标题上方细进度（第 N 步/共约 M 步，可选） | 无（新增时只许一处） |

## 6. 动效

- 步骤切换：新内容 180ms 淡入 + 上移 4px；抽屉/弹层 220ms 平移；其余状态变化只过渡颜色（120ms）。
- 结论生成完成不做庆祝动画；急症屏零动效。
- prefers-reduced-motion 时全部位移动画关闭，仅保留淡入。

---

## 7. 明确不改

- 问诊流程、问题顺序、分诊与红旗逻辑、临床文案语义（本轮只许清理患者可见的系统术语，不改临床含义，清理清单需逐条过目）。
- 内核契约 K1–K8 与任何后端数据结构；本轮改动应全部落在 web 静态资源内（styles/themes/appearance/structured-ui/app 的呈现代码），不新增接口。
- 6 个配色主题的色相身份（只调令牌数值，不删主题）。

## 8. 分期实施

**V1 令牌与排版（纯 CSS/主题层，风险最低）**
字阶落地与 ≤12px 清零（例外清单登记）、根字号与行高、边框收敛（一般卡片去描边）、纸面降饱和、焦点环统一、字号档位设置。
验收：字号审计脚本（统计口径同 §0.1）达标；11 屏走查无布局崩坏；全量测试绿。

**V2 布局与信息架构**
单列居中、事实抽屉、状态去重（§5）、首页高度约束、侧栏瘦身与测试视图移出。
验收：走查断言（抽屉开合、计数唯一出处、首屏露出输入框）；关闭态三形态复验（含结论单聚焦呈现不回归）。

**V3 组件细化**
选项行、量表色带、人体图可点选、急症屏版式增强、动效落地。
验收：急症屏首屏断言（行动区与作答按钮均在首屏内）；量表与人体图的交互走查；reduced-motion 检查。

每期独立分支、独立走查截图集（沿用 viz-review 的 11 屏编号），期与期之间可单独叫停或回滚（纯静态资源，回滚即还原文件）。

---

## 9. 验收标准（汇总）

- 量化：styles.css 中 ≤12px 的 font-size 声明从 225 处降至 ≤ 60 处，且每处登记归属（患者界面例外清单目标 ≤ 15 处，其余须属研发作用域）；`border: 1px solid` 从 79 处降至 ≤ 30 处（输入控件与警示容器为主）。
- 走查：11 屏基线（01–30 编号集）逐屏对比，无内容丢失、无安全语义降级；急症屏与关闭态单独断言（脚本化，同既有 verify 流程）。
- 回归：全量 pytest 绿（基线 458）；结论单评测门与发布门 PASS 不变。
- 人工：产品负责人逐屏过目 V1 与 V2 的对比截图后才进入下一期。

## 10. 开放决策

- DV1：标题衬线（品牌特征）保留在 display/title 两级，还是全量换无衬线（更"Muse"）？
- DV2：默认主题纸面是否降饱和到近白（品牌绿转为点缀），还是保留现绿雾底色？
- DV3：事实面板默认形态——抽屉（本文建议）还是保留窄常驻列？
- DV4：字号档位默认值与档位命名（小/标准/大 vs 关怀模式）？
- DV5：改版范围是否含桌面端（Electron）与开发者视图，还是只患者 web 界面？
