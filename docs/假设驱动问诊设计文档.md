# 假设驱动问诊设计文档

> 基线：`main ff5cb8b`（修缮批 A `1157581` + 批 B `ab5d9c2` + 批 C `ff5cb8b`）。
> 状态：待签核。签核方：用户 + 临床评审。落地 sequencing：第二轮复测跑完后实施，
> 实施前不得以本设计为由改动基线（见 §6）。
> 本文档只定“问诊旅程怎么走”，不改结论单结构、不改分诊阈值、不新增诊断措辞。

## 判断（先说结论）

诚信现在的问诊是**覆盖驱动**：按通路把问题集走完，结论在最后一次性给出。
医生式问诊是**假设驱动**：主诉一出先在脑中分类排序，每轮回答都刷新排序，
下一问永远是当前最能区分的问题，患者在 1 分钟内就能感到“医生在往一个方向想”。

本设计主张：把诚信的旅程从覆盖驱动改成假设驱动，**只改提问顺序与问题间的
意图表达，不改目的地**——结论单结构、分诊逻辑、红旗扫描、可见性门控全部不动。
时间模拟与两轮疾病测试的证据表明，旅程问题不是“时间太长”，而是“方向感来得太晚、
无效轮次太多”（§1）。这是一个旅程设计问题，不是再加一轮修复能解决的。

## 1. 背景与证据：为什么现在改

### 1.1 第一轮疾病测试：最大短板在旅程，不在单点功能

第一轮 76 病全量测试（基线 `3b13622`）共 168 条问题，总权重 450
（`~/workspace/scratch/disease-round1-aggregation.md`）：

- 结论/收尾未回应点名担忧（WORRY）：50 条，权重 150，见于全部 15 批。
  患者问“是不是××”而结论不接，是最频繁的失败类。
- 通路外：70 条，占 42%，是最大的结构短板。通路外主诉没有自有内容与自有分诊信号，
  只能借用最近似通路的模板（内分泌多饮多尿被写成“泌尿不适”、牙龈出血被写成“皮肤不适”、
  眼睑红肿被皮肤通路接管），导致漏报与单线索关闭并存。
- 其余高频类（证据引文与断言脱节、已记录未知被写成“还没有确认”、
  轨迹“加重”单线索提前关闭、收尾纯指令式）大多也是“问与答之间没有承接与意图”的表现，
  而非某个字段缺失。

修缮批 A/B/C 修掉了其中可修的单点问题，但旅程本身的结构没有变：
问题仍按固定顺序出现，患者仍不知道“为什么问这一句”。

### 1.2 第二轮复测：修复有效，但残留指向旅程

第二轮复测（基线 `ff5cb8b`）前 6 批累计：31/76 病，满意 18（第一轮同批满意 0–1/批），
新条目 8（P0 1、P1 5、P2 2），复现 11，涉及第一轮条目 50 条中未复现 39 条。
方向是对的，但未收敛——仍有新 P0/P1 出现。

最系统的残留共性与旅程直接相关：**urgent 关闭模板不渲染担忧节，累计已 6 例**
（N-06、E-05、E-08、S-03、S-08、S-10）。常规收尾的担忧槽位（批 B）已生效，
urgent 路径仍缺渲染。这是关闭层的独立缺口，本设计不顺带解决它（见 §7），
但它印证了同一个判断：患者在关键时刻得不到“我的担心被接住了”的信号。

### 1.3 时间模拟：总时长合理，时间结构不合理

患者视角时间模拟（`~/workspace/scratch/patient-time-simulation.md`，
双臂同一时间模型、结论文本逐字相同、处置结局不变，差异只来自提问方式；
全部时长为模型估算、非实测）：

| 病例 | 诚信现行 | 医生式重排 | 节省 |
|---|---|---|---|
| S1 阑尾炎样（15 轮 → 11 轮） | 8.86 分钟 | 7.01 分钟 | −111 秒（−20.9%） |
| G1 急性胃肠炎（13 轮 → 10 轮） | 7.18 分钟 | 6.06 分钟 | −67 秒（−15.6%） |
| E3 肥胖代谢（14 轮 → 9 轮） | 6.29 分钟 | 5.44 分钟 | −51 秒（−13.5%） |

6–9 分钟本身落在普通门诊问诊的提问时长区间内，不算离谱。真正的问题有四点：

1. **方向感缺失**：诚信臂全程无意图桥，患者到 5.8–8.2 分钟后的结论轮才知道问诊指向；
   医生臂 43–48 秒就给了方向感。
2. **重复/无关轮次**：S1 复述轮 36.5 秒零新信息；G1 向成年人问宝宝问题 52.2 秒，
   伤的不只是时间，更是“有没有被听进去”的信任；E3 两轮 41.5 秒换来两次“不清楚”。
3. **承接锚过长**：每例 21–43 秒花在重读重复认领上，应截短而非全量重复。
4. **时间短 ≠ 体验好**：三例中最短的恰是唯一不满意的 E3（单线索 urgent 提前关闭且不回应担忧）；
   最长的 S1 反而满意。比总分钟数更重要的，是“时间花在哪、有没有方向感”。

### 1.4 现状核查：零件大半已有，缺的是排序与先验

撰写前实读基线代码，现状如下（文件依据逐条注明）：

- **提问顺序是固定目录顺序，不是鉴别力顺序。**
  确定性引擎 `src/medagent/consultation.py` `_plan_next`（约 L1869）：
  候选 = 未记录 + `question_applies_in_state` + 事实门通过，取最早阶段（`planning_rank`），
  同阶段内由 `src/medagent/reasoner.py` `OrderedQuestionRanker.choose` 取 `candidates[0]`，
  即目录顺序。自适应引擎 `src/medagent/agent.py` `_candidate_questions`（约 L1251）用同一过滤口径，
  模型以 `ask_question` / `ask_patient` 提问、每轮最多 6 步自纠。
  两引擎都没有“按当前假设排序选最能区分的问题”这一层。
- **问题目录顺序是开场 → 筛查 → 历史 → 通路细节。**
  `src/medagent/content/questions.json` v2026-10-25.v1，共 27 题，目录顺序为：
  consult_for → sex → age → chief_complaint → emergency_screen →
  onset → trajectory → severity → associated_symptoms → 通路细节
  （gi_details、head_details、dizzy_details、back_details、urinary_details 等）。
  主诉深挖类问题排在历史块之后，不是主诉之后的第一位。
- **假设有鉴别问题，但没有可用于提问的先验。**
  `src/medagent/content/differentials.json` v1.2.1：8 通路、25 假设；每假设含
  `discriminating_questions`（每假设 2–4 个）、`support`、`refute`、`red_flags`、
  以及粗粒度 `prior_band`（high / medium / low）与 `category`
  （common_condition / serious_condition / red_flag_condition）。
  分布：常见高 6、常见中 7、严重中 4、严重低 7、红旗中 1。
  关键事实：`prior_band` **只用于结论方向排序**
  （`src/medagent/conclusion.py` 约 L405、L470–475 的 `PRIOR_RANK`），
  从不驱动提问；且无数值权重、无季节条件、无年龄组条件，
  全文件无 `season` / `prevalence` / `base_rate` / `epidemic` 字段。
- **承接层只有单题认领，没有一组问题的意图桥。**
  `src/medagent/bridging.py`：桥接句 = “你说/你提到 + 已记录事实值”认领 +
  “为了…/想确认…/好判断…”为什么问半句；B 路校验要求模型题以承接词开头且含 why 标记
  （无可锚事实的开场轮次豁免）；lint 命中整句丢弃。
  缺口：没有“接下来几个问题是想把几种可能区分开”这种**组级意图桥**，
  患者始终不知道一串问题共同指向什么。
- **安全层与结论层是本设计不动的底座。**
  `src/medagent/red_flags.py` `scan()`：不确定/受抑制表述不计为已确认红旗（批 A 门控），
  组合规则命中须经鉴别澄清（`FlagHit.requires_clarification`）。
  结论单由 `src/medagent/conclusion.py` 在 `_record_reply`  choke 点确定性组装，
  含 `worry` 与 `goal_response` 节（批 B；担忧回应绝不点名假设）；
  `directions_visible()` 与 `department_visible()` 默认均为 off，
  分别由 `MEDAGENT_CONCLUSION_DIRECTIONS` / `MEDAGENT_CONCLUSION_DEPARTMENT` 控制。

结论：要改的不是零件，而是**排序逻辑 + 先验层 + 组级意图表达**三处。
现有鉴别问题、红旗扫描、结论单全部复用。

## 2. 四步模型（用户亲述骨架，本文定稿）

用户 2026-10-25 晚亲述并批准的医生心智模型，本文将其定为设计骨架。
四步缺一不可；每步都写清“内部算什么、患者看到什么”，这是 Tier 边界的依据（§3.3）。

### 第一步：先验层——两张表 + 两个权重（内部计算，患者不可见）

主诉一出，引擎在内部做分类，不向患者披露分类结果：

1. **急性表**：该主诉对应的急性/危险病种（红旗条件假设优先）。
   排序原则是安全优先：先排除危险，再谈常见。急性表与红旗扫描同源，
   不新增任何红旗信号或阈值（§5）。
2. **非急性表**：该主诉对应的常见/慢性病种。
3. **季节权重**：当季高发病上调。权重表是临床认定的静态内容（见 §7 待签核），
   按季节键（春/夏/秋/冬）给出，不读任何实时数据源。
4. **年龄组权重**：儿童、成人、老年对同一主诉的先验不同，权重表同样由临床认定。

初始排序 = 急性优先 ×（先验带 × 季节权重 × 年龄组权重）。
这一步的输出只是一个**内部排序**，不是结论、不是诊断、不向患者展示。

**明确不在 v1 的事：本地实时疫情 feed。**
我们没有可用的本地流行病数据源，也不在本设计里新建一个。
“当地流行病”在 v1 只落实为两点：季节权重（静态、临床认定）与
“患者自述近期接触/聚集发病”作为普通事实记录（已有事实键可承载，不新增语义）。
任何实时疫情数据源的接入都是独立的数据决策，不属于本设计。

### 第二步：深挖层——主诉属性清单（先问，问全关键属性）

主诉之后的第一组问题必须是主诉本身的性质，而不是人口学与背景。
属性清单按主诉域组织，示例（清单本身由临床评审定稿，不由工程编造）：

- 发热：热程、最高体温、退烧药用否与效果、寒战/出汗。
- 腹痛：部位（脐上/脐下/右下等）、性质（绞痛/胀痛/隐痛）、位置变化（转移性）、
  按压加重与否、与进食/排便/体位的关系。
- 头痛：部位、性质、起病方式（骤发/渐进）、呕吐、视物变化。
- 咳嗽/呼吸：咳嗽性质与时间、痰、气促、喘鸣。
- 通用属性：起病时间与方式（突然/逐渐）、轨迹（加重/减轻/不变）、
  程度（0–10 分或功能影响）、诱因与缓解因素。

排序原则：**按鉴别力排序**。一个属性问题排在前面，当且仅当它的答案
能最大程度改变当前内部排序（区分急性表与非急性表、或区分排序前两名）。
已记录的属性不再重问（批 C 的去重修复是本层的前提，不得回退）。

### 第三步：主动探问层——没想过的症状 + 证伪问题（本设计的核心步骤）

除主诉外，引擎必须**主动**问患者没想过的症状，分两类，缺一不可：

1. **关联症状**：与当前排序靠前的假设相关的伴随症状（包括红旗关联项）。
   这一步是医生“替患者想”的能力，不是等患者补充。
2. **证伪问题**：指向**别的可能**的症状，即“如果这个症状存在/不存在，
   最初预判就要下调甚至排除”。每轮主动探问中，至少要有一道证伪问题。
   只问能证实预判的问题叫锚定；连能推翻预判的问题一起问，才叫鉴别。
   证伪问题的答案同样进入事实集，同样参与排序刷新。

每轮回答进来，内部排序刷新一次；下一问重新按鉴别力选。
排序的刷新是单调记录的：事实一旦记录不得因排序变化而改写，
只有患者本人更正才能改写（现有写回语义不变）。

### 第四步：收敛层——排序稳定准则与结论单不变

满足以下任一条件即收敛，进入摘要与结论：

1. **排序稳定**：连续两轮回答未改变排序前两名，且关键区分项已问完
   （区分项 = 能改变前两名相对顺序的问题）；或
2. **安全触发**：红旗扫描命中已确认信号或组合规则经鉴别确认，走现有急诊/紧急路径，
   不再为“问完”而拖延；或
3. **事实集完备**：结论所需的最低事实集（主诉属性 + 程度 + 轨迹 + 目标 +
   安全关键项）已齐，且患者无新的未回应担忧。

收敛后输出的结论单结构、处置分级、叙事口径、担忧与目标回应节**全部不变**；
收敛只决定“什么时候停”，不决定“说什么”。

## 3. 提问排序引擎改动面

### 3.1 改动面（只改排序层，不动事实与结论层）

1. **新增内部排序器**（引擎内，不向患者输出）：
   输入 = 当前事实集 + 主诉 + 季节 + 年龄组；
   输出 = 假设排序（急性优先 × 先验带 × 季节权重 × 年龄组权重 × 已记录证据的支持/反驳）。
   复用 `differentials.json` 现有 `support` / `refute` / `discriminating_questions` /
   `prior_band`，新增的只有季节与年龄组权重表（内容待临床签核，见 §7）。
2. **每轮动态重排**：确定性引擎 `_plan_next` 的同阶段 `candidates[0]` 目录顺序，
   改为“排序器给出的下一最优问题”；自适应引擎的模型提问同样受排序器约束——
   模型仍可措辞，但问什么由排序器决定（与现有 6 步自纠校验同层，不新增校验层）。
   阶段顺序本身不变（开场 → 急诊筛查 → 深挖 → 主动探问 → 背景 → 摘要），
   变的是**阶段内的问题顺序**与**深挖层提前到主诉之后第一位**。
3. **人口学与背景后移，不删除**：sex / age 仍在开场收集（年龄组权重需要年龄），
   但除年龄外的背景字段（病史、用药、过敏、生活方式）统一后移到主动探问之后、
   摘要之前，作为“背景合并轮”一次性补齐。背景字段一个不删，只是换位置——
   这与 2026-10-23 用户选定的问题负担选项 A（维持现状）不冲突：
   不剪问题，只重排。
4. **深挖层提前**：主诉记录后、急诊筛查完成后，立即进入主诉属性深挖，
   再进入主动探问。急诊筛查仍在深挖之前（§5 不变项）。

### 3.2 意图桥 Tier 1：只讲意图，不点名假设（本设计包含）

每组问题之前，加一句组级意图桥，模板限定为过程透明、不含方向信息：

- 深挖组：“先把你这个症状本身问清楚，部位、性质、时间这些细节会决定接下来问什么。”
- 鉴别组：“接下来几个问题，是想把几种可能区分开。”
- 主动探问组：“除了你说的这些，我再问几个你可能没留意的表现，有没有都请直接说。”
- 背景组：“最后补几个背景情况，问完我就把结论整理给你。”

Tier 1 的红线（lint 级，命中则整句丢弃、只出原问题，与现有桥接 lint 同制）：

- 不得出现任何假设名、疾病名、科室名、处置指向词；
- 不得出现“初步考虑”“很像”“倾向于”等预判措辞；
- 不得出现“排除××”“不是××”等结论性措辞（结论单的 banned 词表同标准）。

Tier 1 是过程透明，不是方向披露。它的验收标准是：给一组问题加桥前后，
患者无法从桥中推断出引擎的内部排序（抽查验收，见 §6）。

### 3.3 Tier 边界：点名假设仍属 Tier 2、C3 签核门控

**任何在问诊中段点名具体假设的行为，仍属 Tier 2，不属于本设计。**
包括但不限于：“我初步考虑是阑尾炎”“你这个很像胃肠炎”“先排除一下心梗”。
Tier 2 的放开条件与现有 C3 门完全一致：临床评审签核结论方向可见性之后，
才可讨论中段点名；本设计不预设、不绕过、不降低该门。
批 B 的担忧回应槽位（结论轮回应，不点名假设）不受影响，继续生效。

## 4. 通路外一等公民流程

通路外不是“ fallback”，是与通路内平行的正式流程。第一轮 70 条（42%）的教训是：
通路外一旦借用最近似通路的模板，就会同时出现误导性 framing 与分诊信号缺失。
本流程三条规则：

1. **中性措辞**：通路外结论与收尾不得借用任何通路的器官特异性 framing、
   自护、安全网条目。无对应器官条目时宁可缺省通用表述（观察、记录变化、何时就诊），
   不得臆测。这是批 A 已落地的中性 fallback 原则，本设计将其升为通路外流程的硬性规则。
2. **症状域警示问题**：通路外没有通路专属红旗时，问一組症状域通用警示问题
   （意识/呼吸/出血/剧痛/持续加重/功能骤降等域），模式复用批 C 的
   `eye_warning_signs` 经验：不针对器官，只针对危险信号域。
   警示问题的答案进入事实集，同样参与排序与安全触发。
3. **坦言可交付范围**：通路外收尾必须 plainly 说明本次问诊能交付什么、
   不能交付什么（例如“这次问诊没有覆盖到你这个问题的专属分诊路径，
   结论只给到观察与就诊指征”），不得用通路内模板的肯定口吻掩盖覆盖缺口。
   坦言本身是结论单叙事层的措辞要求，不新增结论字段。

通路外流程的内部排序同样适用 §2：先验表为空通路时，排序退化为
“症状域警示优先 + 通用属性深挖”，不回落到最近似通路。

**实施记录（2026-10-27）**：规则 2 的警示问题已接线到问诊主流程
（此前只有内容与契约，id-less 导致恒不提问）。落点与域范围收窄的裁定见
《问诊结论单设计文档》§13.10；本次未改排序层，警示问题当前排在通用属性深挖之后，
“警示优先”仍属 §3 排序层待做项。

## 5. 不变项（本设计一律不动，违反即否决）

1. **咨询内核 K1–K8**：硬约束，不削弱、不绕过。
2. **红旗扫描**：`red_flags.py` 的扫描语义、批 A 的不确定表述门控、
   组合规则的鉴别澄清要求，全部不变；先验层不新增红旗信号或阈值。
3. **急诊筛查顺序**：`emergency_screen` 仍在深挖之前；安全触发仍可随时打断问诊，
   不为“问完深挖”而延迟。
4. **结论单结构**：处置分级、方向（仍 shadow）、叙事、担忧与目标回应节、
   自护、安全网、展望、随访，结构与口径全部不变。
5. **可见性门控**：`MEDAGENT_CONCLUSION_DIRECTIONS` 与
   `MEDAGENT_CONCLUSION_DEPARTMENT` 默认 off 不变；Tier 2 仍待 C3 签核，
   科室提示仍待 C12 签核。
6. **不新增临床阈值与诊断措辞**：季节/年组权重是排序权重，不是诊断阈值；
   权重内容本身须经临床认定（§7），工程不得自拟数值含义。
7. **事实写回语义**：已记录事实不因排序变化而改写；去重与否认语义（批 B/C）不回退。
8. **担忧与目标的中段认领**：中段只认领（“你提到的担心，结论里会回应”），
   回应仍在结论轮；urgent 路径的担忧渲染缺口是独立项（§7），不由本设计顺带宣称解决。

## 6. 落地 sequencing 与验收

### 6.1 顺序（硬性）

1. **第二轮复测跑完（76/76）再实施。** 本设计获批不等于立即开工；
   第二轮进行中改动基线会污染复测可比性，复测的收敛判断（连续两轮无新 P0/P1）
   必须建立在同一基线之上。
2. 实施时按监督并行模式：排序器、权重表、意图桥、通路外流程分工，
   独立监督员复核接缝与门禁后方可提交。
3. 实施后先做 **focused live-eval 对照**：用时间模拟的三例（S1、G1、E3）为必测例，
   以同一时间模型复测，验收方向感时间与无效轮次是否改善、处置结局是否不变；
   再进入第三轮全量复测（同清单、同顺序）。

### 6.2 验收方式（每项须有证据，不得只凭实现自述）

| 验收项 | 方式 | 通过标准 |
|---|---|---|
| 深挖提前 | 抽查 transcript：主诉后第一组问题为主诉属性 | 3 例必测例全部满足 |
| 每轮动态重排 | 构造两例“同一主诉、不同第二轮答案”的对照，检查第三轮问题不同 | 排序随答案变化，且变化方向与鉴别力一致 |
| 意图桥 Tier 1 | 抽查桥文本 + lint；另做“桥是否泄漏排序”盲查 | 零疾病名/科室名/预判措辞；盲查无法从桥推断排序 |
| 证伪问题覆盖 | 抽查主动探问组 | 每例主动探问组至少 1 道证伪问题 |
| 结局不变 | focused 对照：处置级别与结论单结构与基线一致 | 3 例必测例处置不变；发布门 PASS |
| 时间结构 | 同一时间模型复测 S1/G1/E3 | 方向感 < 1 分钟；无效轮次（零新信息/无关）为 0 |
| 通路外流程 | 通路外必测例抽查 | 零器官特异性借用；收尾含可交付范围坦言 |
| 门禁 | pytest + 发布门 + 针对性 Playwright | 全绿；K1–K8 不退化 |

## 8. 风险与反模式

1. **锚定**：初始排序一旦形成，后续问题只找支持证据。反制：每轮主动探问组
   强制至少 1 道证伪问题；排序刷新必须同时计入支持与反驳证据
   （现有 `support` / `refute` 结构已支持，排序器不得只读 support）。
2. **过早收窄**：排序稳定准则过松，导致关键区分项未问就收敛。
   反制：收敛条件要求“关键区分项已问完”，区分项的定义须可审计
   （能改变前两名相对顺序的问题清单，逐例可查）。
3. **先验过期**：季节权重表写死后无人更新，变成错误先验。
   反制：权重表带版本号与季节键；过期季节键命中时退化为等权（不静默沿用旧季权重）；
   权重表变更走内容评审流程，不随代码发布悄悄改。
4. **意图桥变相泄漏方向**：桥的措辞越具体，越容易泄漏内部排序
   （例如“接下来问几个关于心脏的问题”等于点名方向）。
   反制：Tier 1 模板白名单制（§3.2 四类模板），lint 命中整句丢弃；
   任何超出白名单的桥措辞须经评审新增模板，不得由模型自由发挥。
5. **重排破坏可复现性**：动态排序使同一病例两次问诊路径不同，
   影响回归对比。反制：排序器必须是确定性函数（事实集 + 主诉 + 季节 + 年龄组），
   相同输入必得相同下一问；focused 对照与第三轮复测以此为准。
6. **通路外退化回最近似通路**：排序器在先验表为空时图方便借用通路。
   反制：§4 规则 1 为硬性规则，通路外流程单测须覆盖“零器官特异性借用”。
7. **体验回归**：重排后轮次减少，但患者感到“被审问”而非“被倾听”。
   反制：承接锚保留但截短（时间模拟 §四的 21–43 秒成本须压缩，不删除承接本身）；
   focused 对照须同时看体感分（被倾听/焦虑/共情），不只看分钟数。
