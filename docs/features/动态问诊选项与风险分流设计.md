# 动态问诊选项与风险分流设计

## 目标

模型可以根据当前病例生成问题、按钮文字和按钮数量。患者点击后，按钮对应的患者陈述进入下一轮问诊。宿主程序负责协议校验、页面渲染、旧操作拦截和风险分流，模型不能生成可执行代码，也不能直接决定急救结论。

## 数据流

```text
病例事实与本轮输入
  → 模型调用 ask_patient
  → 宿主校验问题、选项和风险标签
  → medical-ui/v1 问题块
  → 前端按 single / multiple / text 渲染
  → 患者点击或补充文字
  → 宿主核对当前 action_id 与选项原文
  → 本地风险规则优先处理
  → 普通回答交给模型记录事实并生成下一问
```

## `ask_patient` 协议

- `topic`：必须对应当前尚未处理的注册问诊字段。
- `question`：一次只问一个清楚的问题。
- `selection_mode`：`single`、`multiple` 或 `text`。
- `options`：选择题包含 1 到 8 项；文字题为空。
- `label`：按钮上显示的简短文字。
- `response_text`：患者点击后作为患者回答提交的文字，必须逐字包含按钮 `label`，不能偷偷增加患者未选择的事实。
- `exclusive`：多选题中的互斥项，例如“以上都没有”。
- `requires_detail`：单选后展开文字补充框。
- `allow_other`：为选择题提供“其他情况”文字入口。
- `risk_tags`：只能使用宿主登记的风险表现标签，而且必须能从该选项的可见文字中直接找到依据。

风险标签不代表诊断。它只表示患者明确选中了哪类可见表现。风险表现必须同时以肯定语义出现在按钮和提交文字中；否定这些表现的选项不能携带对应标签。

## 交互规则

- 普通单选点击后立即提交，减少多一步确认。
- 需要细节的单选先展开输入框，填写后提交。
- 多选允许组合，点击确认后一次提交；互斥项会清除其他选择。
- “其他情况”展开输入框，患者填写的原文直接提交。
- 输入草稿按当前问题标识保存。问题变化后，旧按钮和旧草稿不能提交到新问题。
- 图示任务进行中不并排创建动态问诊卡，先完成澄清或接续原任务。

## 风险处理

风险处理先于下一次模型调用：

1. 意识异常、抽搐、发紫、严重呼吸困难、胸部不适和大量出血等受控标签进入本地急症规则。
2. 对口腔、牙齿或下颌主诉，患者选择“活动相关”或“伴冷汗”时，当前原型升级为当天线下评估。
3. 风险标签必须通过文字依据、否定语义和协议白名单校验。
4. 没有触发本地规则的回答才继续交给模型理解、记录和追问。

这些阈值属于当前开发原型的安全策略，上线前仍需由临床人员审查并通过病例集评测。

## 示例

患者输入“牙疼”后，模型可以生成一个多选问题：

- “走路或爬楼时牙痛更明显” → `exertional`
- “同时有胸口发紧或胸痛” → `chest_discomfort`
- “同时有冷汗” → `cold_sweat`
- “以上情况都没有” → 无风险标签，且 `exclusive=true`

选择胸部不适会在模型继续回答前进入急症分流；选择活动相关或冷汗会结合牙齿主诉进入尽快就医分流；选择“以上情况都没有”则继续后续问诊。

## 验证范围

- 协议字段、长度、选项数量、唯一 ID 和风险标签白名单。
- 否定风险选项不能伪装成阳性风险标签。
- 旧问题按钮、篡改后的回答文字和不匹配的单选/多选提交会被拒绝。
- 普通回答、当天就医和急救三条控制器路径。
- 浏览器中的动态数量、多选、互斥项、“其他情况”和响应式宽度。
