# 执行工作区恢复与存储

实现版本：0.9.3，2026 年 10 月 16 日。此功能用于研发执行工作台；患者问诊的病例与会谈仍只在原服务进程内，不因本次改动变成持久病例库。

## 使用方式

在独立桌面进入“研发视图 → 执行工作台”，通过右上角选择器打开已保存工作区。“×”关闭当前工作区并释放进程与占用锁，文件和记录保留；“↻”刷新列表。正在执行或有后台任务时，需先停止再关闭。新建、选择、关闭、仅查看历史均不请求模型。

应用重新启动后，可以不填密钥，先查看已保存任务和文件。继续执行前，通过“模型与运行配置”填写原模型服务与模型 ID，密钥可更换；匹配后再提交新指令。更换为别的模型或服务不会自动把旧记录发送过去。工作区已绑定有效配置后，原配置在本进程内保持固定；要采用轮换后的凭据，可关闭工作区后重新打开。

界面把恢复的内容标为“历史任务”“历史执行结果”，不伪装为刚执行的工具事件。模型标签区分“仅查看已保存记录”和“真实执行”。未发送的输入草稿只在当前窗口内切换工作区时保留，不自动写入索引。

## 真正恢复模型上下文

官方固定版 SDK 的普通 `createSession` 入口只创建新会话。本项目没有将旧文件重新展示后声称恢复了智能体；`execution-sdk.mjs` 复用官方 `HarnessSdkJsonRpcServer`，在创建入口查询官方持久化服务。存在原会话时，检查目录归属和根会话身份，再通过官方 `agents.resume` 恢复。

原有初始化、请求校验、事件通知、子智能体通知和关闭生命周期仍由官方 SDK 类执行。上游包统一固定为 `0.2.0-rc.2`，没有修改依赖源码。需要恢复的历史缺失、损坏或不属于该工作区时，明确失败，不用空白会话冒充接续。原始模型上下文按 DSH 自身持久化与压缩机制管理，并不承诺无限上下文。

```mermaid
flowchart LR
    UI[选择已保存工作区] --> I[宿主索引与目录身份核对]
    I --> R[离线展示任务和文件]
    R --> C[匹配原服务与当前内存凭据]
    C --> U[用户提交新指令]
    U --> S[官方持久化服务恢复原会话]
    S --> L[原工具循环继续工作]
```

## 存储和凭据

默认执行根目录为桌面的“知微工作区”，可用 `MEDAGENT_EXECUTION_ROOT` 指定。若旧版“澄心工作区”已经存在且尚未创建“知微工作区”，桌面应用会继续使用旧目录，避免改名后丢失已有任务入口。文件分别保存在：

| 位置 | 内容 | 模型运行时是否可见 |
| --- | --- | --- |
| `<工作区ID>/` | 用户文件、生成代码与产物 | 当前工作区可见 |
| `.state/<工作区ID>/` | 当前工作区的 DSH 会话日志及运行资料 | 当前工作区可见 |
| `.index/<工作区ID>.json` | 宿主恢复索引、近期任务及结果 | 不挂载给模型运行时 |
| `.index/<工作区ID>.lock` | 宿主跨进程占用锁 | 不挂载给模型运行时 |
| `.index/changes/<工作区ID>/<回合ID>.json` | 0.9.9 起的内容哈希、权限与有限原始文本基线 | 不挂载给模型运行时 |

索引不保存配置密钥；存储模型与服务的路由摘要，用于核对当前配置。标题、任务和结果在截断前替换已知配置密钥，避免长密钥被截成前缀后落盘。当前仍是本机明文研究资料，不是加密病例数据库；只应输入合成研究任务。

索引目录为 `0700`，索引及锁文件为 `0600`。写入采用临时文件、同步和原子替换；读取拒绝路径越界、链接、特殊文件、超限或不兼容记录。根目录和 DSH 状态目录记录 inode 身份，不能通过同名目录替换接管原工作区。跨进程文件锁使一个工作区只由一个宿主打开；关闭时等待输出读取结束，再释放所有权，防止旧进程晚写覆盖新状态。这不是对同一操作系统用户下恶意进程的完整隔离。

界面恢复最多最近 32 轮任务/结果，长记录还受总大小上限约束，省略时会显示提示；旧工具详情不会凭空重建为实时事件。0.9.7 起另外保留最多 128 条结构化工具运行观察，可离线展示实际退出状态与主/子会话归属；旧记录缺失观察时保持未知，不从回复文字推断。原始工具文字仍不会全部恢复为实时卡片。完整原始 DSH 日志另行保留。列表最多展示 200 条索引，本进程最多打开 20 个工作区，可关闭闲置工作区再打开其他记录。

## 中断与错误

保存新任务失败时，撤回“正在执行”状态，不启动模型。执行期间记录无法保存时显示持久化错误，不能假装记录已安全保存。

重启时，原来仍处于启动、执行或取消中的记录转为“上次执行已中断”。仅打开历史不会重放旧命令或重启旧后台进程；提交新指令后，仍需核对实际文件，不能假设旧任务没有产生副作用，也不保证外部操作恰好发生一次。

0.9.3 以前创建的工作区没有本版宿主索引，文件与 DSH 原始日志仍保留在原目录，不自动猜测旧服务配置或冒充完成迁移。跨设备复制、旧目录导入、第三方存储、自动重放后台进程及患者病例恢复均不在本次实现范围。

## 已验证的证据

本地测试覆盖真正关闭旧 SDK 进程、保留原消息和文件、轮换凭据、缺失历史拒绝、离线查看、错误/不同服务配置拒绝执行、窗口占用、损坏记录、目录替换、索引链接、密钥脱敏、中断状态，以及磁盘保存失败时不启动任务。

原生桌面检查还实际完成：第一次执行 → 关闭应用 → 不继承模型凭据启动 → 选择历史 → 查看文件 → 通过图形界面配置新密钥 → 继续同一会话 → 关闭工作区并重新打开。全流程检查模型调用数，离线阶段及打开/关闭操作不产生请求。

真实提供商验收共 **6 次请求**。不仅检查生成文件，还在新进程第一次请求送往提供商之前，检查请求消息中确实含有原会话的随机项目代号；续跑指令未重新提供该代号。最终连续任务保存了正确代号和计算结果，关闭候选运行时后独立重跑代码也通过。该实验只证明所测试的冷恢复路径，不是临床验证或整体 DSH 能力证明。

```bash
# 本地确定模型与官方 SDK，不调用外部模型
RUN_DSH_EXECUTION=1 PYTHONPATH=src python3 -m unittest discover \
  -s tests -p test_execution_persistence.py -v

# 原生桌面恢复流程
DISPLAY=:1 XAUTHORITY=/run/user/1000/gdm/Xauthority \
  npm run test:desktop -- --grep 'desktop restores'

# 真实模型，使用新报告路径；父目录累计额度48次
PYTHONPATH=src python3 scripts/evaluation/execution/evaluate_persistence.py \
  --max-calls 20 --output .runtime/evaluations/new-persistence/report.json
```

0.9.9 的文件基线与回合一同建立，保存近期最多 32 轮、每份最多 4 MB。它允许在无模型凭据时查看最近一轮代码差异，但不是完整文件备份或自动回滚；被忽略目录、链接目标、空目录、超限文件与文本留存限制见 [文件变更设计](通用执行底座与能力评测设计.md#12-v099-文件变更与长任务预算)。旧版本任务缺少基线时保持不可用；下一次新执行才从当前文件建立新的基线。每轮所选执行时限也保存到回合，不自动改变下一次界面选择。

0.10.0 支持通过原生目录选择器绑定已有项目。索引增加可选原项目路径，模型状态和基线仍保存在执行根目录，项目文件直接留在用户选择的位置；相同规范路径复用可读的原记录，无凭据可离线打开。老管理工作区无需迁移。目录保护、inode 占用锁及跨应用恢复见 [本地项目目录与原位执行](本地项目目录与原位执行.md)。

0.10.1 的澄清问题及真实回答也进入近期宿主索引。未完成请求重启后失效，仅查看历史，不自动重放回答；已确认接收的近期回答可作为后续注册计算的用户原文来源。最近最多 32 个问题，范围和状态见 [执行澄清与用户回答](执行澄清与用户回答.md)。
