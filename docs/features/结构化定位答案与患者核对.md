# 结构化定位答案与患者核对

源码目标：0.11.15。定位内容包：`observe.location 0.4.0`，仍待临床审核。

上一版实际模型问“头部哪个区域、哪一侧、范围如何”，界面却只有头／胸／腹等大部位。几何可见不代表答案组件足以回答问题。本版使用声明式的定位输入组件修复这个具体缺口。

## 问题与输入

模型通过 `clarify.answer_fields` 声明需要的维度，宿主从注册内容包生成 `location-answer/v1` 输入，不从问题文本猜控件，也不执行模型生成的页面。只问大部位时保留原图；要求细节时逐项显示需要的字段，始终保留大部位作为锚点。

| 维度 | 患者看到的输入 | 记录的含义 |
| --- | --- | --- |
| region | 人体图与大部位选项 | 患者选择的大范围部位 |
| area | 头部区域示意、预设或自己描述 | 附近区域或原话；当前仅头部有区域预设 |
| side | 左侧、右侧、两侧、正中、说不清 | 按患者自己的左右，不能从图片默认推断 |
| extent | 一个点、一片范围、说不清 | 主观范围描述，不是面积或距离测量 |

每次只呈现一个问题维度，最后用可编辑的答案卡核对。未填写不能自动成为“说不清”。不符合预设的位置可以直接描述；可跳过整个任务。区域示意并非解剖标定、动作识别或经过验证的测量工具。

## 对话、草稿与确认

患者也可以自然表达“右太阳穴附近疼”。模型用 `propose_self_check_result` 提议已报告的维度，宿主按需建立或扩展细化输入卡。没说范围就保留空白，模型草稿不直接写入病史。

`input_evidence` 可逐项引用完整定位原话中的连续文字。宿主补回所在分句及紧邻位置限定，进行有界词语校验：不允许把“可能右侧”截成确定右侧，预设与左右、范围需有对应原话。不确定的自述可原样保留；词语校验不是完整语义或临床验证。

患者确认通过独立的 `observation` 请求提交，包含协议、表单ID、答案与可选补充。宿主校验当前动作、当前表单、字段范围及预设所属部位，缺项／过期／重复提交在写入前拒绝。紧急原话仍优先进入既有求助路径。

确认后的 `Fact.structured_input` 保存逐项断言、标签、值和输入方式。即使大部位已知，范围仍可为未知。患者修改草稿后，以本次核对选项和确认轮次为记录来源；原模型草稿、原话、原轮次和各维度引文另存 `proposal_source`，不把旧引文冒充修改后的证据。患者／照护者来源沿用宿主规则，质量保持 `not_assessed`。

## 接续与呈现

同一表单的选择、步骤及可选补充在当前页面内恢复，另写的对话草稿独立保留。新模型草稿使用新身份，避免复用旧选择。局部操作不调用模型，最后确认后继续原问诊；后续服务失败可重试，已确认事实不重复写入。

核对卡和病史摘要使用同一份结构化字段渲染标签，未知项有单独样式。来源按需展开。头部预设仅是收集位置描述，不能据此作诊断、计算面积、推断左右或建议自行按压检查。

## 验证与剩余范围

定向检查覆盖：未确认不写入、缺项和跨部位拒绝、患者修改模型草稿、未知子字段、过期动作、紧急补充优先，以及服务失败后的原事实接续。界面检查覆盖宽屏、390像素窄屏、900×648小窗口、自然语言草稿修改、页面切换恢复、自述位置和明确未知。关键输入与操作目标至少44像素，问题、当前字段、下一步／确认、输入框与求助入口按实际几何检查。

真实模型评估脚本 `scripts/evaluation/medical/evaluate_location_answers.py` 使用脚本准备初始状态，随后由实际DSH和提供商决定工具调用；最终确认由合成患者显式提交。每轮最多14次、同目录累计最多28次模型请求，保留失败轨迹。这些是定向工程案例，不是全新完整问诊、临床准确率或患者理解测试。

当前不增加部位确认后的专用重选流程、摄像头动作检查或任意第三方界面组件。后续完整问诊和目标用户评审仍需单独验证。

本轮已完成两轮真实模型定向评估，各9次请求、四类案例最终均通过，共18次。最终运行的三个确认后接续均各1次模型请求。第一轮保留了分句引文末尾标点被过度拒绝的轨迹，随后修复并新增检查；第二轮保留了未知位置的两次无效提议，宿主拒绝后模型改为图示澄清。不能将最终通过解释为所有提议首次正确。默认后端383项中329通过、54项跳过；另单独运行注册计算SDK1项与问诊桥接集成1项通过。界面全量70组通过，原生及打包结果在本轮归档中另列。
