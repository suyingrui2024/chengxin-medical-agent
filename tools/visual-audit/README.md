# 界面树自动走查（visual audit）

把「打开每一个界面、截图、逐张审阅」固化成一条命令。走查按一棵声明式的
**界面树**执行：从落地页顺着问诊状态机一路走下去（问诊对象 → 年龄 →
紧急筛查 → 发病 → 严重程度 → 部位观察 → 体温自检 → 定向追问 → 摘要 →
结论单），再覆盖抽屉、弹窗、会谈记录、健康档案、设置（含每个主题）、
研发模式四个视图。每个节点用**真实交互**到达并截图，同时做基础几何
自检（横向溢出、问诊面板是否被内容收缩——面板宽度 < 栏宽即标红）。

## 运行

```bash
node tools/visual-audit/audit.mjs \
  --python <项目虚拟环境的 python 路径> \
  --chrome <Chromium/Chrome/Edge 可执行文件路径>
```

可选参数：`--width 1440 --height 900`（视口）、`--port 18767`、
`--out <输出目录>`、`--only <节点 id 或标题子串>`（只跑部分节点）。

当前的产品重心是桌面端，默认视口即桌面尺寸；移动端走查未纳入本工具
的节点验收（同一条命令换小视口可作参考）。

## 产出

默认写到 `tools/visual-audit/runs/<时间戳>/`：

- `index.html` — 树形图库：按分支分组、缩略图点开看原图，失败节点与
  几何异常（面板收缩/横向溢出）带红色徽章；
- `manifest.json` — 每节点的路径、截图文件、几何数据与错误信息；
- `shots/*.png` — 全部截图（文件名含序号与节点 id）。

退出码：有非可选节点失败时为 1 —— 可以接进发布前检查。

## 扩展

界面树就是 `audit.mjs` 里的 `TREE` 数组：新增界面/状态时加一个节点
（`branch` 决定它在图库树里的位置，`run(page)` 用真实交互到达该状态，
截图与自检由运行器统一做）。`optional: true` 的节点失败只记录不断流。
